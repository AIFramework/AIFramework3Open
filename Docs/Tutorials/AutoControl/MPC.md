# Линейный квадратичный MPC

**Пространство имён:** `AI.ControlSystems.Optimal`  
**Класс:** `LinearQuadraticMpc`

---

## Теория

### Принцип управления с прогнозирующей моделью

**Model Predictive Control (MPC)** — метод управления с прогнозирующей моделью. На каждом такте решается задача оптимизации на горизонте $N$ шагов вперёд, и применяется только **первое** управление из оптимальной последовательности. Затем горизонт сдвигается на один шаг вперёд («скользящий горизонт»).

### Линейный квадратичный MPC без ограничений

Для системы $x[k+1] = Ax[k] + Bu[k]$ минимизируется:

$$J_N(x, \mathbf{u}) = x_N^\top Q_f x_N + \sum_{t=0}^{N-1}\bigl(x_t^\top Q x_t + u_t^\top R u_t\bigr)$$

где $Q_f$ — терминальный штраф (часто берут как решение DARE для LQR).

Без ограничений на $u$ и $x$ задача имеет аналитическое решение через **обратный проход Риккати**:

$$S_N = Q_f$$
$$K_t = (B^\top S_{t+1} B + R)^{-1} B^\top S_{t+1} A$$
$$S_t = A^\top S_{t+1} A - A^\top S_{t+1} B K_t + Q$$

Оптимальное управление на шаге $t$: $u_t^* = -K_t x_t$.

Применяется только $u_0^* = -K_0 x[k]$ (первое усиление горизонта).

### Связь с LQR

При $N \to \infty$ и $Q_f$ = решение DARE, $K_0$ сходится к матрице LQR. MPC с конечным горизонтом — это «конечный LQR» с терминальным штрафом.

### Преимущества MPC перед LQR

- Явный учёт горизонта планирования.
- Легко расширить на ограничения (требует QP-решателя, не реализован в данной версии).
- Терминальный штраф $Q_f$ позволяет гарантировать устойчивость.

## API

### `LinearQuadraticMpc`

| Метод | Описание |
|-------|----------|
| `ComputeFirstGain(A, B, Q, R, Qf, horizon)` | Возвращает матрицу $K_0$ (m×n) для первого шага горизонта. |

**Параметры:**

| Параметр | Описание |
|----------|----------|
| `A`, `B` | Матрицы дискретной модели. |
| `Q` | Стадийный штраф за состояние (n×n, $Q \ge 0$). |
| `R` | Штраф за управление (m×m, $R > 0$). |
| `Qf` | Терминальный штраф (n×n, $Q_f \ge 0$). |
| `horizon` | Горизонт $N \ge 1$. |

## Примеры

### MPC для двойного интегратора

```csharp
using AI.ControlSystems.Linear;
using AI.ControlSystems.Optimal;
using AI.DataStructs.Algebraic;

double dt = 0.05;
var A = new Matrix(new double[,] { { 1, dt }, { 0, 1 } });
var B = new Matrix(new double[,] { { 0.5 * dt * dt }, { dt } });
var C = new Matrix(new double[,] { { 1, 0 } });

var Q  = new Matrix(new double[,] { { 10, 0 }, { 0, 1 } });
var R  = new Matrix(new double[,] { { 0.1 } });

// Терминальный штраф = решение LQR (гарантирует устойчивость)
Matrix Qf = DiscreteLqr.Solve(A, B, Q, R);  // P из DARE как Qf

int horizon = 10;
Matrix K0 = LinearQuadraticMpc.ComputeFirstGain(A, B, Q, R, Qf, horizon);

Console.WriteLine($"K0 = [{K0[0, 0]:F4}, {K0[0, 1]:F4}]");

// Симуляция (K0 пересчитывается каждый такт для текущего x)
var model = new DiscreteLtiModel(A, B, C);
model.Step(new Vector(new[] { 0.0 }));  // инициализация
// Установим начальное состояние вручную через Reset + Step
model.Reset();

// Начальное состояние x = [5, 0]
// (DiscreteLtiModel не позволяет задать State напрямую — используем Step с нулевым u)
// Для демонстрации просто симулируем с начальным отклонением:
var x = new Vector(new[] { 5.0, 0.0 });

for (int k = 0; k < 100; k++)
{
    // В реальном MPC K0 пересчитывается для текущего x (здесь он постоянный без ограничений)
    double u = -(K0[0, 0] * x[0] + K0[0, 1] * x[1]);
    double x1n = A[0, 0] * x[0] + A[0, 1] * x[1] + B[0, 0] * u;
    double x2n = A[1, 0] * x[0] + A[1, 1] * x[1] + B[1, 0] * u;
    x[0] = x1n;
    x[1] = x2n;

    if (k % 10 == 0)
        Console.WriteLine($"k={k:D3}  x1={x[0]:F4}  x2={x[1]:F4}  u={u:F4}");
}
```

### Сравнение горизонтов

```csharp
foreach (int N in new[] { 1, 5, 10, 20 })
{
    Matrix K = LinearQuadraticMpc.ComputeFirstGain(A, B, Q, R, Qf, N);
    Console.WriteLine($"N={N:D2}  K=[{K[0,0]:F4}, {K[0,1]:F4}]");
}
// При N→∞ K сходится к LQR
```

## Замечания

- Без ограничений на $u$ и $x$ MPC с $Q_f$ = DARE-решение эквивалентен LQR по первому шагу.
- Для учёта ограничений (насыщение привода, ограничения состояния) необходим QP-решатель — данная реализация его не включает.
- `ComputeFirstGain` вычисляет $K_0$ заново при каждом вызове; для экономии вычислений кэшируйте результат, если модель не меняется.
- Терминальный штраф $Q_f = 0$ допустим, но может привести к нестабильности при малых горизонтах.
