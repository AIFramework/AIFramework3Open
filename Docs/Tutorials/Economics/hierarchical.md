# Иерархическое согласование прогнозов

Сумма прогнозов по товарам обязана сходиться с прогнозом по категории, а сумма
по категориям — с прогнозом по компании. Построенные независимо, они никогда
не сходятся.

## Постановка задачи

Дано: прогнозы, построенные независимо на каждом уровне иерархии —
SKU, категория, регион, компания.

Требуется: согласованный набор прогнозов, в котором агрегаты равны суммам
своих частей.

Где встречается: планирование закупок против финансового плана, бюджет продаж
по регионам, любая организация, где разные подразделения прогнозируют разные
уровни одной и той же выручки.

## Теория

Задача возникает всегда, когда прогнозы нужны на нескольких уровнях сразу.
Закупка планирует по товарам, коммерческий директор — по категориям,
финансовый план — по компании. Построенные независимо, эти прогнозы
не сходятся, и организация начинает жить по трём разным цифрам.

Формально: пусть $S$ — матрица суммирования, отображающая нижний уровень
во все узлы иерархии. Согласованный прогноз имеет вид $\tilde y = S G \hat y$,
где $G$ зависит от метода:

| Метод | Матрица $G$ | Свойство |
|-------|-------------|----------|
| Снизу вверх | выбирает строки листьев | прогнозы листьев не меняются |
| Сверху вниз | разносит вершину по долям | структура внутри категории фиксирована |
| МНК | $(S'S)^{-1}S'$ | все уровни равноправны |
| MinT | $(S'W^{-1}S)^{-1}S'W^{-1}$ | уровни взвешены обратно дисперсии ошибок |

MinT с диагональной оценкой ковариации обычно точнее и «снизу вверх», и
«сверху вниз»: он меньше сдвигает те уровни, которые прогнозируются надёжнее.
Это важно, потому что агрегаты обычно прогнозируются точнее — на них меньше
шума, — но при этом именно они хуже всего отражают изменение структуры внутри.

Согласование само по себе не улучшает прогноз, если исходные прогнозы
систематически смещены: оно распределяет смещение, а не убирает его. Ценность
в другом — организация получает один непротиворечивый набор чисел.

## Сложность

| Ресурс | Оценка | Комментарий |
|--------|--------|-------------|
| Построение $G$ | $O(m^3 + n m^2)$ | $m$ — листьев, $n$ — всех узлов |
| Согласование | $O(h \cdot n m)$ | $h$ — горизонт |
| Память | $O(n m)$ | Матрица суммирования |

## API

| Метод | Описание |
|-------|----------|
| `HierarchicalReconciliation.Reconcile(nodes, summing, baseForecasts, method, variances)` | Согласование |
| `HierarchicalReconciliation.BuildTwoLevel(groupSizes)` | Матрица для иерархии «итого — группы — листья» |
| `ReconciliationMethod` | BottomUp, TopDown, OrdinaryLeastSquares, MinTraceDiagonal |
| `ReconciliationResult.MaxIncoherenceBefore` | Насколько не сходились исходные прогнозы |
| `ReconciliationResult.LargestAdjustment` | Наибольший относительный сдвиг и его узел |

Исходник: `src/AI.Economics/Forecasting/HierarchicalReconciliation.cs`.

## Код

```csharp
using AI.DataStructs.Algebraic;
using AI.Economics.Forecasting;

// Иерархия: итого, три группы, по три позиции в каждой
(Matrix summing, IReadOnlyList<HierarchyNode> nodes) =
    HierarchicalReconciliation.BuildTwoLevel([3, 3, 3]);

var random = new Random(5);
var baseForecasts = new Matrix(nodes.Count, 3);

for (int i = 0; i < nodes.Count; i++)
{
    // Уровни прогнозировались независимо и потому не сходятся
    double scale = nodes[i].Level switch { 0 => 900, 1 => 300, _ => 100 };
    for (int h = 0; h < 3; h++)
        baseForecasts[i, h] = scale * (0.9 + (random.NextDouble() * 0.2));
}

// Агрегаты прогнозируются точнее — им и меньший вес в MinT
var variances = new Vector(nodes.Count);
for (int i = 0; i < nodes.Count; i++)
    variances[i] = nodes[i].IsBottom ? 1.0 : nodes[i].Level == 0 ? 4.0 : 2.0;

ReconciliationResult result = HierarchicalReconciliation.Reconcile(
    nodes, summing, baseForecasts, ReconciliationMethod.MinTraceDiagonal, variances);

Console.WriteLine($"Расхождение до: {result.MaxIncoherenceBefore:F2}");
Console.WriteLine($"Расхождение после: {result.MaxIncoherenceAfter:E2}");
Console.WriteLine($"Средний сдвиг: {result.AverageAdjustment:P1}");
Console.WriteLine($"Наибольший сдвиг у «{result.LargestAdjustmentNode}»: " +
                  $"{result.LargestAdjustment:P1}");

Console.WriteLine(result.Interpret().ToLlmText());
```

## Ограничения

- Согласование не улучшает точность само по себе. Если базовые прогнозы
  систематически смещены, оно распределит смещение между уровнями.
- MinT требует оценки дисперсий ошибок по узлам. Их надо брать из бэктеста,
  а не назначать: неверные веса делают метод хуже простого «снизу вверх».
- Реализована диагональная оценка ковариации. Полная матрица учитывала бы
  корреляции между узлами, но на типичных объёмах данных оценивается
  неустойчиво.
- Согласование сверху вниз разносит агрегат по историческим долям и потому
  не реагирует на изменение структуры спроса внутри категории.
- Метод работает с точечными прогнозами. Согласование интервалов —
  отдельная задача, здесь не решаемая.
