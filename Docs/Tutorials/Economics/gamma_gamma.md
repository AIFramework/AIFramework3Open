# Gamma-Gamma: оценка среднего чека

Денежная половина CLV: сколько в среднем тратит клиент за покупку, если
наблюдённое среднее по двум заказам ничего не доказывает.

## Постановка задачи

Дано: по каждому клиенту число покупок $x$ и наблюдённый средний чек
$\bar m$.

Требуется: оценка ожидаемого среднего чека этого клиента, устойчивая к малому
числу наблюдений.

Где встречается: расчёт CLV, сегментация по ценности, приоритизация клиентов
для программы удержания.

## Теория

Проблема наблюдённого среднего очевидна на крайнем случае: клиент с единственной
покупкой на 50 000 рублей имеет средний чек ровно 50 000, но это почти наверняка
везение выборки, а не свойство клиента.

Модель предполагает, что чек клиента — гамма-величина с индивидуальным
масштабом, а сам масштаб распределён по популяции тоже гамма-законом. Плотность
наблюдённого среднего:

$$
f(\bar m \mid p, q, \gamma, x) \;=\;
\frac{\Gamma(px+q)}{\Gamma(px)\,\Gamma(q)}\;
\frac{\gamma^{q}\, \bar m^{\,px-1}\, x^{px}}{(\gamma + x\bar m)^{px+q}}.
$$

Апостериорное ожидание оказывается взвешенной суммой индивидуального и
популяционного средних:

$$
E[M \mid x, \bar m] \;=\;
\underbrace{\frac{q-1}{px+q-1}}_{\text{вес популяции}} \cdot \frac{\gamma p}{q-1}
\;+\;
\underbrace{\frac{px}{px+q-1}}_{\text{вес клиента}} \cdot \bar m
\;=\;
\frac{p\,(\gamma + x \bar m)}{px + q - 1}.
$$

Вес индивидуального среднего растёт с числом покупок: чем длиннее история, тем
больше модель доверяет самому клиенту. Это и есть регрессия к среднему,
выведенная из модели, а не введённая руками.

Популяционное среднее равно $\gamma p / (q-1)$ и существует только при $q > 1$.

## Сложность

| Ресурс | Оценка | Комментарий |
|--------|--------|-------------|
| Время  | $O(I \cdot n)$ | $I$ — итераций симплекса, $n$ — клиентов с покупками |
| Память | $O(n)$ | Сводки клиентов |

## API

| Метод | Описание |
|-------|----------|
| `GammaGammaModel.Fit(customers)` | Оценка $p, q, \gamma$; берутся клиенты с `Frequency > 0` |
| `ConditionalExpectedValue(customer)` | Ожидаемый чек с поправкой на регрессию к среднему |
| `PopulationMean` | Средний чек популяции $\gamma p/(q-1)$ |
| `LogLikelihood` | Логарифм правдоподобия в оптимуме |
| `SampleSize` | Сколько клиентов реально участвовало в подгонке |

Исходник: `src/AI.Economics/Clv/GammaGammaModel.cs`.

## Код

```csharp
using AI.Economics.Clv;

var random = new Random(7);
var customers = new List<CustomerSummary>();

for (int i = 0; i < 400; i++)
{
    int purchases = 1 + random.Next(12);
    double personal = 3_000 + (random.NextDouble() * 6_000);
    double observedMean = personal * (0.6 + (random.NextDouble() * 0.8));

    customers.Add(new CustomerSummary
    {
        Id = $"c{i}",
        Frequency = purchases,
        Recency = 10,
        Age = 18,
        MonetaryValue = observedMean,
    });
}

var model = new GammaGammaModel();
model.Fit(customers);

Console.WriteLine($"p={model.P:F3} q={model.Q:F3} gamma={model.Gamma:F1}");
Console.WriteLine($"Средний чек популяции: {model.PopulationMean:N0}");

var rare = new CustomerSummary { Frequency = 1, MonetaryValue = 50_000, Age = 18 };
var loyal = new CustomerSummary { Frequency = 30, MonetaryValue = 50_000, Age = 18 };

Console.WriteLine($"Одна покупка на 50 000  -> ожидание {model.ConditionalExpectedValue(rare):N0}");
Console.WriteLine($"Тридцать покупок по 50 000 -> ожидание {model.ConditionalExpectedValue(loyal):N0}");
```

## Ограничения

- Модель предполагает независимость среднего чека и частоты покупок. Перед
  применением проверьте корреляцию между `Frequency` и `MonetaryValue`:
  допустимой обычно считают величину до 0,1.
- Клиенты без повторных покупок в подгонке не участвуют — для них модель
  вернёт значение, целиком определяемое популяционным средним.
- Отрицательные и нулевые чеки (возвраты, промо) должны быть отфильтрованы до
  подгонки: плотность определена только на положительной полуоси.
- Оценка $q \le 1$ означает, что популяционное среднее не существует; на
  практике это признак слишком короткой или загрязнённой истории.
