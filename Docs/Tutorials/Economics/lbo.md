# Модель выкупа за счёт долга

Долговой график по траншам с водопадом погашения, ковенанты, доходность фонда
и разложение прироста капитала на рост бизнеса, снижение долга и изменение
мультипликатора.

## Постановка задачи

Дано: прибыль до амортизации на входе, мультипликатор покупки и ожидаемый
мультипликатор продажи, структура долгового финансирования по траншам, темп
роста и срок владения.

Требуется: доходность вложенного капитала (IRR), кратность возврата,
динамика долговой нагрузки по годам и предельный мультипликатор входа, при
котором сделка ещё даёт целевую доходность.

Где встречается: инвестиционные комитеты фондов прямых инвестиций, банковский
андеррайтинг сделок с высоким рычагом, оценка «сколько за нас может заплатить
финансовый инвестор» со стороны продавца.

## Теория

**Экономика сделки.** Фонд покупает бизнес за $\mathrm{EV}_0 = m_0 \cdot
\mathrm{EBITDA}_0$, финансируя часть цены долгом $D_0$. Собственные средства
составляют $E_0 = \mathrm{EV}_0 - D_0$. При продаже через $T$ лет:

$$
E_T \;=\; m_T\,\mathrm{EBITDA}_T \;-\; D_T,
\qquad
\mathrm{MoM} = \frac{E_T}{E_0},
\qquad
\mathrm{IRR} = \mathrm{MoM}^{1/T} - 1 .
$$

**Водопад погашения.** Свободный поток после процентов и планового погашения
направляется на досрочное гашение траншей в порядке старшинства: сначала
самый старший, затем следующий. Именно поэтому структура долга влияет на
доходность даже при неизменной общей сумме — дорогие младшие транши гасятся
последними и успевают накопить проценты.

Поток на погашение в году $t$:

$$
\mathrm{FCF}_t \;=\; \mathrm{EBITDA}_t\,(1 - c) \;-\; I_t \;-\; \tau\,(\mathrm{EBITDA}_t - I_t)^{+},
$$

где $c$ — доля прибыли, уходящая на капитальные затраты и оборотный капитал,
$I_t$ — начисленные проценты. Налоговый щит возникает автоматически: проценты
уменьшают базу.

**Ковенанты** проверяются на каждый отчётный год: долговая нагрузка
$D_t/\mathrm{EBITDA}_t$ не выше предела и покрытие процентов
$\mathrm{EBITDA}_t/I_t$ не ниже минимума. Нарушение не останавливает расчёт,
но фиксируется — на практике оно означает пересмотр условий или потерю
контроля.

**Разложение доходности** отвечает на вопрос, откуда взялся прирост:

$$
\underbrace{(\mathrm{EBITDA}_T - \mathrm{EBITDA}_0)\,m_0}_{\text{рост}}
\;+\;
\underbrace{D_0 - D_T}_{\text{снижение долга}}
\;+\;
\underbrace{(m_T - m_0)\,\mathrm{EBITDA}_T}_{\text{мультипликатор}} .
$$

Сделка, где основной вклад даёт третье слагаемое, — это ставка на рынок, а не
на управление активом. Инвестиционные комитеты относятся к таким сделкам
осторожно именно поэтому.

## Сложность

| Ресурс | Оценка | Комментарий |
|--------|--------|-------------|
| Время  | $O(T\,K)$ | $T$ лет, $K$ траншей; подбор мультипликатора — $O(T K \log(1/\varepsilon))$ |
| Память | $O(T + K)$ | график по годам и состояние траншей |

## API

| Метод | Описание |
|-------|----------|
| `LeveragedBuyout.Run(input)` | Полный расчёт сделки с графиком и ковенантами |
| `LeveragedBuyout.MaximumEntryMultiple(input, targetIrr, maxMultiple)` | Предельная цена входа |
| `LeveragedBuyout.Sensitivity(input, entry, exit)` | Матрица IRR по мультипликаторам |
| `LboResult.Irr` / `MoneyMultiple` | Доходность и кратность возврата |
| `LboResult.Schedule` | Долг, проценты и покрытие по годам |
| `LboResult.GrowthContribution` и соседние | Разложение прироста капитала |

Исходники: `src/AI.Economics/Corporate/LeveragedBuyout.cs`.

## Код

```csharp
using AI.Economics.Corporate;

var deal = new LboInput
{
    Name = "Дистрибьютор",
    EntryEbitda = 1_000_000_000,
    EntryMultiple = 6.5,
    ExitMultiple = 7.0,
    HoldingPeriod = 5,
    EbitdaGrowth = 0.08,
    CashConversionDrag = 0.35,
    TaxRate = 0.2,
    MaxLeverage = 4.5,
    MinInterestCoverage = 2.0,
    Tranches =
    [
        new DebtTranche("Старший кредит", 2_600_000_000, 0.14, 0.10, Seniority: 1),
        new DebtTranche("Мезонин", 900_000_000, 0.19, 0.00, Seniority: 2),
    ],
};

LboResult lbo = LeveragedBuyout.Run(deal);

Console.WriteLine($"Вход {lbo.EntryValue:N0}, собственные средства {lbo.EquityInvested:N0}");
Console.WriteLine($"Выход {lbo.ExitValue:N0}, к акционерам {lbo.EquityProceeds:N0}");
Console.WriteLine($"IRR {lbo.Irr:P1}, кратность {lbo.MoneyMultiple:F2}x");
Console.WriteLine($"Долговая нагрузка на входе {lbo.EntryLeverage:F2}x");

foreach (LboYear year in lbo.Schedule)
{
    Console.WriteLine($"Год {year.Year}: долг {year.ClosingDebt:N0}, " +
                      $"нагрузка {year.Leverage:F2}x, покрытие {year.InterestCoverage:F2}x");
}
```

Разложение доходности и проверка ковенантов — то, о чём спрашивает комитет:

```csharp
Console.WriteLine($"Рост бизнеса: {lbo.GrowthContribution:N0}");
Console.WriteLine($"Снижение долга: {lbo.DeleveragingContribution:N0}");
Console.WriteLine($"Мультипликатор: {lbo.MultipleContribution:N0}");

foreach (CovenantBreach breach in lbo.Breaches)
{
    Console.WriteLine($"Год {breach.Year}: нарушен «{breach.Covenant}» — " +
                      $"{breach.Value:F2} при пределе {breach.Limit:F2}");
}
```

Предельная цена входа задаёт потолок в переговорах:

```csharp
double ceiling = LeveragedBuyout.MaximumEntryMultiple(deal, targetIrr: 0.22);
Console.WriteLine($"При целевой IRR 22% платить можно не выше {ceiling:F2}x EBITDA");

Console.WriteLine(lbo.Interpret().ToLlmText());
```

## Ограничения

- Модель предполагает, что ставки по траншам фиксированы на весь срок. При
  плавающей ставке доходность сделки становится ставкой на денежно-кредитную
  политику, и её надо моделировать отдельным сценарием.
- Рост EBITDA задан константой. Реальные сделки чувствительны к тому, в каком
  году произойдёт спад: провал на второй год бьёт по ковенантам сильнее, чем
  такой же провал на четвёртый.
- Предположение о полном направлении свободного потока на погашение
  оптимистично: на практике часть уходит на дивиденды и приобретения.
  Увеличивайте `CashConversionDrag`, если у актива есть программа развития.
- Стоимость выхода задаётся мультипликатором, а не оценкой. Сверяйте с
  [DCF](dcf.md) и [аналогами](comparables.md), иначе IRR превращается в
  функцию собственного оптимизма.
- Нарушение ковенанта в модели фиксируется, но не влечёт последствий. В жизни
  оно означает штрафную ставку, запрет на выплаты или требование досрочного
  погашения — сценарий надо просчитывать вручную.
