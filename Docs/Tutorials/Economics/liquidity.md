# Риск ликвидности: кассовые разрывы и запас денег

Платёжный календарь с выявлением разрывов, вероятность нехватки денег при
случайных поступлениях и оптимальный остаток на счёте по моделям Баумоля и
Миллера — Орра.

## Постановка задачи

Дано: начальный остаток денежных средств, план поступлений и выплат по
периодам, разброс поступлений, стоимость одной операции пополнения и ставка
доходности свободных денег.

Требуется: где и на сколько возникает кассовый разрыв, какой лимит кредитной
линии его закроет, какова вероятность нехватки денег и какой остаток
поддерживать, чтобы не терять доходность и не разоряться на комиссиях.

Где встречается: казначейство, планирование оборотного капитала, переговоры о
кредитной линии, управление остатками группы компаний, обоснование
овердрафта.

## Теория

**Платёжный календарь** строится тривиально, но именно он показывает
проблему: прибыльная компания может обанкротиться, если поступления приходят
позже выплат.

$$
B_t \;=\; B_{t-1} + \mathrm{In}_t - \mathrm{Out}_t,
\qquad
\mathrm{Shortfall}_t = \max(B_{\min} - B_t,\,0).
$$

Требуемый лимит кредитной линии — максимум нехватки по всем периодам, а не
её сумма: линия возобновляемая.

**Вероятность разрыва** оценивается симуляцией: поступления разыгрываются
с заданным разбросом, и считается доля траекторий, в которых остаток хотя бы
раз опустился ниже минимума. Детерминированный календарь с нулевым запасом
даёт вероятность разрыва около половины — это ключевой аргумент в пользу
буфера.

**Модель Баумоля** решает задачу, аналогичную оптимальному размеру заказа:
деньги расходуются равномерно, пополнение стоит фиксированную сумму $F$, а
хранение обходится в упущенную доходность $r$:

$$
C^{*} \;=\; \sqrt{\frac{2\,T\,F}{r}},
$$

где $T$ — потребность в деньгах за период. Средний остаток равен $C^{*}/2$.

**Модель Миллера — Орра** снимает нереалистичное допущение о равномерном
расходовании: остаток блуждает случайно с дисперсией $\sigma^2$ в день.
Задаются нижняя граница $L$ и точка возврата $Z$:

$$
Z \;=\; L + \left(\frac{3F\sigma^2}{4r}\right)^{1/3},
\qquad
H \;=\; 3Z - 2L,
\qquad
\bar C = \frac{4Z - L}{3}.
$$

При падении до $L$ счёт пополняется до $Z$, при росте до $H$ излишек
размещается. Асимметрия ($Z$ ближе к $L$, чем к $H$) не случайна: пополнение
и размещение стоят одинаково, но риск разрыва односторонний.

## Сложность

| Ресурс | Оценка | Комментарий |
|--------|--------|-------------|
| Время  | $O(T + S\,T)$ | $T$ периодов, $S$ симуляций |
| Память | $O(T)$ | календарь |

## API

| Метод | Описание |
|-------|----------|
| `LiquidityRisk.Analyze(opening, inflows, outflows, volatility, cost, rate, minimum, company, sims, seed)` | Полный анализ |
| `LiquidityRisk.Baumol(demand, transactionCost, rate)` | Оптимальный размер пополнения |
| `LiquidityRisk.MillerOrr(minimum, dailyVariance, cost, dailyRate)` | Границы и точка возврата |
| `LiquidityResult.Positions` | Платёжный календарь с нехватками |
| `LiquidityResult.RequiredCreditLine` | Требуемый лимит линии |
| `LiquidityResult.ShortfallProbability` | Вероятность разрыва по симуляции |

Исходники: `src/AI.Economics/Risk/LiquidityRisk.cs`.

## Код

```csharp
using AI.DataStructs.Algebraic;
using AI.Economics.Risk;

var inflows = new Vector(
    120_000_000, 95_000_000, 80_000_000, 130_000_000,
    110_000_000, 70_000_000, 140_000_000, 125_000_000);

var outflows = new Vector(
    100_000_000, 105_000_000, 115_000_000, 98_000_000,
    120_000_000, 135_000_000, 90_000_000, 105_000_000);

LiquidityResult liquidity = LiquidityRisk.Analyze(
    openingBalance: 40_000_000,
    inflows: inflows,
    outflows: outflows,
    inflowVolatility: 0.18,
    transactionCost: 25_000,
    interestRate: 0.12,
    minimumBalance: 15_000_000,
    company: "Торговый дом");

foreach (CashPosition position in liquidity.Positions)
{
    Console.WriteLine($"Период {position.Period}: остаток {position.Closing:N0}" +
                      (position.Shortfall > 0 ? $" (разрыв {position.Shortfall:N0})" : ""));
}

Console.WriteLine($"Минимум {liquidity.MinimumBalance:N0} в периоде {liquidity.MinimumPeriod}");
Console.WriteLine($"Разрывов {liquidity.ShortfallPeriods}, максимальный {liquidity.MaximumShortfall:N0}");
Console.WriteLine($"Требуемая кредитная линия {liquidity.RequiredCreditLine:N0}");
Console.WriteLine($"Вероятность разрыва {liquidity.ShortfallProbability:P1}");
```

Оптимальный запас денег отвечает на вопрос, сколько держать на счёте:

```csharp
Console.WriteLine($"Баумоль: пополнять по {liquidity.BaumolCash:N0}");
Console.WriteLine($"Миллер — Орр: нижняя {liquidity.MillerOrrLower:N0}, " +
                  $"точка возврата {liquidity.MillerOrrReturn:N0}, " +
                  $"верхняя {liquidity.MillerOrrUpper:N0}");
Console.WriteLine($"Средний остаток {liquidity.MillerOrrAverage:N0}");
```

Формулы доступны и напрямую — например, для разных подразделений:

```csharp
double lot = LiquidityRisk.Baumol(periodDemand: 900_000_000, transactionCost: 25_000, interestRate: 0.12);
Console.WriteLine($"Оптимальный размер пополнения {lot:N0}");

(double lower, double target, double upper) = LiquidityRisk.MillerOrr(
    minimumBalance: 15_000_000,
    dailyVariance: 8_000_000d * 8_000_000d,
    transactionCost: 25_000,
    dailyRate: 0.12 / 365);

Console.WriteLine($"Коридор {lower:N0} — {upper:N0}, возврат к {target:N0}");
Console.WriteLine(liquidity.Interpret().ToLlmText());
```

## Ограничения

- Модель Баумоля предполагает равномерный расход денег и потому годится для
  предсказуемых выплат — зарплаты, аренды. Для торговой компании с
  неравномерными закупками она занижает нужный остаток.
- Миллер — Орр предполагает нулевой снос: остаток блуждает вокруг среднего.
  У растущей или убыточной компании есть тренд, и коридор надо
  пересчитывать регулярно.
- Дневная дисперсия остатка оценивается по истории, которая уже отражает
  прежнюю политику управления деньгами. Это делает оценку самоподтверждающейся.
- Симуляция разыгрывает только поступления. Реальные кризисы ликвидности
  начинаются с одновременного роста выплат — срабатывания гарантий, требования
  досрочного погашения; такие сценарии задавайте вручную.
- Наличие кредитной линии не равно доступности денег: ковенанты и право банка
  на односторонний отказ превращают линию в иллюзию именно в момент стресса.
