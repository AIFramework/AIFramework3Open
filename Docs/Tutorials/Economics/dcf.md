# Оценка методом дисконтированных потоков

Свободный денежный поток фирмы, терминальная стоимость по Гордону и по
выходному мультипликатору, поправка на середину года, анализ чувствительности
торнадо.

## Постановка задачи

Дано: прогноз выручки, рентабельности, амортизации, капитальных затрат и
прироста оборотного капитала на несколько лет вперёд; ставка дисконтирования;
чистый долг.

Требуется: стоимость бизнеса (enterprise value) и стоимость собственного
капитала, а также понимание, какие допущения влияют на результат сильнее всего.

Где встречается: сделки слияния и поглощения, обоснование цены выкупа доли,
тест на обесценение по МСФО, внутренняя оценка стратегических инициатив.

## Теория

**Свободный денежный поток фирмы** — то, что остаётся всем поставщикам
капитала после уплаты налогов и финансирования роста:

$$
\mathrm{FCFF}_t \;=\; \mathrm{EBIT}_t\,(1 - \tau) \;+\; D_t \;-\; \mathrm{Capex}_t \;-\; \Delta \mathrm{NWC}_t .
$$

Проценты в поток не входят: их влияние учтено в ставке через WACC. Если
дисконтировать поток к акционерам (FCFE) по стоимости собственного капитала,
результат должен совпасть — расхождение обычно означает ошибку в структуре
капитала.

**Стоимость бизнеса** — приведённая сумма прогнозного периода и терминальной
стоимости:

$$
\mathrm{EV} \;=\; \sum_{t=1}^{N} \frac{\mathrm{FCFF}_t}{(1+r)^t} \;+\; \frac{\mathrm{TV}}{(1+r)^N}.
$$

**Терминальная стоимость** считается двумя способами. Формула Гордона
предполагает бесконечный рост с постоянным темпом:

$$
\mathrm{TV} \;=\; \frac{\mathrm{FCFF}_N\,(1+g)}{r - g},\qquad g < r .
$$

Выходной мультипликатор задаёт её через сопоставимую сделку:
$\mathrm{TV} = m \cdot \mathrm{EBITDA}_N$. Профессиональная практика —
считать обоими способами и сверять: из мультипликатора выводится подразумеваемый
темп роста, из Гордона — подразумеваемый мультипликатор. Если они расходятся
вдвое, одно из допущений неверно.

**Поправка на середину года.** Формула выше неявно предполагает, что весь
годовой поток приходит 31 декабря. На практике он поступает равномерно, поэтому
средний срок поступления — середина года:

$$
\mathrm{EV}_{\text{mid}} \;=\; \mathrm{EV}\cdot\sqrt{1+r}.
$$

Поправка увеличивает оценку примерно на половину ставки — при $r = 15\%$ это
около 7%, что для сделки существенно.

**Стоимость собственного капитала** получается вычитанием чистого долга и
прибавлением непрофильных активов:
$\mathrm{Equity} = \mathrm{EV} - \mathrm{NetDebt} + \mathrm{NonOperating}$.

**Торнадо** — ранжирование допущений по вкладу в разброс оценки: каждый фактор
поочерёдно сдвигается вверх и вниз при неизменных остальных, и факторы
сортируются по размаху результата.

## Сложность

| Ресурс | Оценка | Комментарий |
|--------|--------|-------------|
| Время  | $O(N)$ | $N$ — горизонт прогноза; торнадо добавляет $O(FN)$ |
| Память | $O(N)$ | потоки и их приведённые значения |

## API

| Метод | Описание |
|-------|----------|
| `DiscountedCashFlow.Value(input)` | Оценка вместе с анализом чувствительности |
| `DiscountedCashFlow.Tornado(input, baseValue)` | Только вклад факторов в разброс |
| `DcfResult.EnterpriseValue` / `EquityValue` | Стоимость бизнеса и собственного капитала |
| `DcfResult.TerminalShare` | Доля терминальной стоимости в результате |
| `DcfResult.ImpliedExitMultiple` / `ImpliedGrowth` | Перекрёстная проверка допущений |
| `ForecastYear.FreeCashFlow` / `Ebitda` | Производные показатели года прогноза |

Исходники: `src/AI.Economics/Corporate/DiscountedCashFlow.cs`.

## Код

```csharp
using AI.Economics.Corporate;

var forecast = new List<ForecastYear>();
double planRevenue = 4_000_000_000;

for (int year = 1; year <= 5; year++)
{
    planRevenue *= 1.12;
    forecast.Add(new ForecastYear(
        Revenue: planRevenue,
        EbitMargin: 0.18,
        TaxRate: 0.2,
        Depreciation: planRevenue * 0.06,
        CapitalExpenditures: planRevenue * 0.08,
        WorkingCapitalChange: planRevenue * 0.02));
}

var plan = new DcfInput
{
    Name = "Розничная сеть",
    Forecast = forecast,
    DiscountRate = 0.15,
    TerminalMethod = TerminalValueMethod.GordonGrowth,
    TerminalGrowth = 0.04,
    ExitMultiple = 7,
    NetDebt = 1_500_000_000,
    MidYearConvention = true,
};

DcfResult dcf = DiscountedCashFlow.Value(plan);

Console.WriteLine($"Стоимость бизнеса {dcf.EnterpriseValue:N0}");
Console.WriteLine($"Стоимость капитала {dcf.EquityValue:N0}");
Console.WriteLine($"Доля терминальной стоимости {dcf.TerminalShare:P1}");
Console.WriteLine($"Подразумеваемый мультипликатор выхода {dcf.ImpliedExitMultiple:F2}");
```

Перекрёстная проверка: тот же прогноз, но терминальная стоимость задана
мультипликатором сопоставимой сделки:

```csharp
DcfResult byMultiple = DiscountedCashFlow.Value(plan with
{
    TerminalMethod = TerminalValueMethod.ExitMultiple,
});

Console.WriteLine($"По Гордону {dcf.EnterpriseValue:N0}, " +
                  $"по мультипликатору {byMultiple.EnterpriseValue:N0}");
Console.WriteLine($"Подразумеваемый рост в мультипликаторе {byMultiple.ImpliedGrowth:P2}");
```

Торнадо показывает, о чём стоит спорить на инвестиционном комитете:

```csharp
foreach (SensitivityBar bar in dcf.Tornado)
{
    Console.WriteLine($"{bar.Factor}: от {bar.LowValue:N0} до {bar.HighValue:N0} " +
                      $"(размах {bar.Swing:N0})");
}

Console.WriteLine(dcf.Interpret().ToLlmText());
```

## Ограничения

- Терминальная стоимость обычно даёт 60–80% результата. Это значит, что DCF в
  первую очередь оценивает не прогноз, а допущение о вечности — и точность
  первых пяти лет намного менее важна, чем кажется.
- Условие $g < r$ обязательно. Темп роста выше ставки даёт отрицательный
  знаменатель и бессмысленную стоимость; на длинном горизонте $g$ не может
  превышать номинальный рост экономики.
- Прогноз должен быть внутренне согласован: рост выручки без роста оборотного
  капитала и капитальных затрат завышает поток. Проверяйте, что отношение
  капитальных затрат к амортизации на терминальном году соответствует темпу
  роста.
- Поправка на середину года применима, когда поток действительно равномерен.
  Для сезонного бизнеса с выручкой в четвёртом квартале она завышает оценку.
- Метод не учитывает управленческую гибкость — возможность отложить, свернуть
  или расширить проект. Для этого нужны [реальные опционы](real_options_lsm.md).
