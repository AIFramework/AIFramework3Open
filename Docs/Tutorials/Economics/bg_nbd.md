# BG/NBD: прогноз покупок без контракта

Модель Fader — Hardie — Lee (2005) отвечает на два вопроса о клиенте
интернет-магазина или маркетплейса: жив ли он ещё и сколько раз купит дальше.

## Постановка задачи

Дано: по каждому клиенту три числа — сколько повторных покупок он сделал $x$,
когда была последняя покупка $t_x$ и сколько времени прошло с первой $T$.

Требуется: вероятность того, что клиент ещё активен, и ожидаемое число покупок
за ближайшие месяцы.

Где встречается: e-commerce, маркетплейсы, мобильные приложения с покупками —
везде, где клиент уходит молча, не расторгая договор.

## Теория

Модель описывает поведение клиента двумя процессами.

Пока клиент активен, он покупает пуассоновским потоком с индивидуальной
интенсивностью $\lambda$; по популяции $\lambda \sim \Gamma(r, \alpha)$.

После каждой покупки клиент с вероятностью $p$ уходит навсегда; по популяции
$p \sim \mathrm{Beta}(a, b)$.

Логарифм правдоподобия одного клиента:

$$
\ln L \;=\; \ln\frac{\Gamma(r+x)}{\Gamma(r)} + r\ln\alpha
+ \ln\frac{B(a, b+x)}{B(a,b)}
+ \ln\!\left[ \frac{1}{(\alpha+T)^{r+x}} + \delta_{x>0}\,\frac{a}{b+x-1}\,\frac{1}{(\alpha+t_x)^{r+x}} \right].
$$

Второе слагаемое под логарифмом отвечает сценарию «клиент ушёл сразу после
последней покупки» и существует только при $x > 0$: единственная покупка ещё
не давала повода уйти.

Отсюда вероятность активности:

$$
P(\text{жив}) \;=\; \left[ 1 + \delta_{x>0}\,\frac{a}{b+x-1}\left(\frac{\alpha+T}{\alpha+t_x}\right)^{r+x} \right]^{-1}.
$$

Практический смысл этой формулы виден на паре клиентов. У покупателя с двадцатью
покупками и молчанием в два месяца показатель степени $r+x$ велик, отношение
$(\alpha+T)/(\alpha+t_x)$ возводится в большую степень — вероятность ухода
близка к единице. У покупателя с двумя покупками то же молчание почти ничего
не меняет: он просто редко покупает. Средний отток такого различия не видит.

Условное ожидание числа покупок за время $t$ требует гипергеометрической
функции Гаусса $_2F_1$; она вычисляется степенным рядом, аргумент
$t/(\alpha+T+t)$ всегда внутри круга сходимости.

## Сложность

| Ресурс | Оценка | Комментарий |
|--------|--------|-------------|
| Время  | $O(I \cdot n)$ | $I$ — итераций симплекса, $n$ — клиентов |
| Память | $O(n)$ | Хранение сводок RFM |

## API

| Метод | Описание |
|-------|----------|
| `BgNbdModel.Fit(customers)` | Оценка $r, \alpha, a, b$ методом максимального правдоподобия |
| `ProbabilityAlive(customer)` | Вероятность того, что клиент ещё активен |
| `ExpectedTransactions(customer, horizon)` | Условный прогноз числа покупок |
| `ExpectedTransactionsPopulation(t)` | Безусловное ожидание для среднего клиента |
| `CustomerSummary` | Сводка RFM: `Frequency`, `Recency`, `Age`, `MonetaryValue` |

Исходники: `src/AI.Economics/Clv/`.

## Код

```csharp
using AI.Economics.Clv;

var customers = new List<CustomerSummary>
{
    new() { Id = "A", Frequency = 20, Recency = 17.0, Age = 18 },
    new() { Id = "B", Frequency = 20, Recency = 6.0,  Age = 18 },
    new() { Id = "C", Frequency = 2,  Recency = 6.0,  Age = 18 },
    new() { Id = "D", Frequency = 0,  Recency = 0.0,  Age = 18 },
};

var model = new BgNbdModel();
model.Fit(customers);

Console.WriteLine($"r={model.R:F3} alpha={model.Alpha:F3} a={model.A:F3} b={model.B:F3}");

foreach (CustomerSummary customer in customers)
{
    Console.WriteLine($"{customer.Id}: P(жив)={model.ProbabilityAlive(customer):P1}  " +
                      $"покупок за 12 мес.={model.ExpectedTransactions(customer, 12):F2}");
}
```

## Ограничения

- Для устойчивой оценки нужны сотни клиентов с повторными покупками; на
  выборке из десятка правдоподобие почти плоское.
- Время отсчитывается от **первой** покупки клиента, а не от начала выборки,
  и `Frequency` не включает первую покупку. Ошибка в этом соглашении смещает
  все прогнозы.
- Модель предполагает, что уход возможен только сразу после покупки. Если
  клиенты «отваливаются» в непрерывном времени, ближе к реальности
  `ParetoNbdModel` — см. раздел ниже.
- Формула условного ожидания требует $a > 1$; при подгонке на коротких историях
  оценка может уйти ниже, и результат приходится ограничивать нулём снизу.
- Модель не знает о деньгах: размер чека оценивается отдельно моделью
  [Gamma-Gamma](gamma_gamma.md).

## Альтернатива: Pareto/NBD

`ParetoNbdModel` описывает ту же задачу, но с другим механизмом ухода: клиент
живёт экспоненциальное время с индивидуальной интенсивностью $\mu$, а по
популяции $\mu \sim \Gamma(s, \beta)$. Уход возможен в любой момент, а не только
сразу после покупки.

Практическая разница: Pareto/NBD аккуратнее описывает клиентов, которые
замолчали надолго, и обычно даёт более консервативную оценку вероятности их
возвращения. Цена — правдоподобие с гипергеометрической функцией и более
капризная оптимизация.

Интерфейс совпадает, поэтому одна модель заменяется другой без правки денежной
части расчёта:

```csharp
var pareto = new ParetoNbdModel();
pareto.Fit(customers);

bool paretoWins = pareto.LogLikelihood > model.LogLikelihood;
ITransactionModel chosen = paretoWins ? pareto : model;

Console.WriteLine($"Выбрана модель: {(paretoWins ? "Pareto/NBD" : "BG/NBD")}");

foreach (CustomerSummary customer in customers)
    Console.WriteLine($"{customer.Id}: P(жив)={chosen.ProbabilityAlive(customer):P1}");
```
