# Разрывный дизайн

Оценка эффекта на пороге формального правила: локальная линейная регрессия с
треугольным ядром, автоматический выбор полосы пропускания, плацебо-пороги и
проверка манипуляции плотностью.

## Постановка задачи

Дано: переменная назначения (балл, доход, размер компании) и правило, по
которому объекты выше порога получают воздействие, а ниже — нет.

Требуется: причинный эффект воздействия в окрестности порога и доказательство,
что скачок вызван правилом, а не чем-то ещё.

Где встречается: пороги субсидий и льгот по размеру бизнеса, проходной балл
для программы, лимит по скоринговому баллу для одобрения кредита,
регуляторные требования, вступающие в силу с определённого размера.

## Теория

**Идея.** Объекты чуть ниже и чуть выше порога практически одинаковы по всем
характеристикам — но одни получили воздействие, а другие нет. Порог создаёт
локальный эксперимент.

**Оценка эффекта** — разрыв условного среднего в точке порога:

$$
\tau \;=\; \lim_{x\downarrow c}\mathbb E[y\mid x] - \lim_{x\uparrow c}\mathbb E[y\mid x].
$$

**Локальная линейная регрессия.** С каждой стороны порога строится взвешенная
регрессия отклика на расстояние до порога с треугольным ядром:

$$
w_i = \left(1 - \frac{|x_i - c|}{h}\right)^{+}.
$$

Линейный, а не постоянный, локальный полином принципиален: постоянная
аппроксимация смещена, если функция имеет наклон, а квадратичная неустойчива
на границе.

**Полоса пропускания $h$** — центральный выбор. Узкая полоса даёт малое
смещение и большую дисперсию, широкая — наоборот. Правило Имбенса —
Калянарамана выбирает $h$, минимизируя среднеквадратичную ошибку;
приближение вида $h \approx C\,\sigma\,n^{-1/5}$ достаточно для практики.

**Проверки достоверности.** Дизайн держится на трёх опорах:

1. **Плацебо-пороги.** Тот же расчёт на ложных порогах вдали от истинного не
   должен давать значимых скачков.
2. **Устойчивость к полосе.** Оценка не должна резко меняться при удвоении
   или уполовинивании $h$.
3. **Непрерывность плотности** (тест Макрари). Если объекты могут точно
   контролировать переменную назначения, они скопятся с выгодной стороны
   порога, и локального эксперимента не будет. Скачок плотности — приговор
   дизайну.

**Что оценивается.** Разрывный дизайн даёт локальный эффект — только для
объектов у порога. Экстраполировать его на далёкие от порога наблюдения
нельзя, и это его фундаментальное ограничение по сравнению с
[разностью разностей](causal_did.md).

## Сложность

| Ресурс | Оценка | Комментарий |
|--------|--------|-------------|
| Время  | $O(n)$ на оценку, $\times(P+S)$ на плацебо и полосы |
| Память | $O(n)$ | наблюдения |

## API

| Метод | Описание |
|-------|----------|
| `RegressionDiscontinuity.Estimate(observations, cutoff, bandwidth)` | Эффект и все проверки |
| `RddObservation(running, outcome)` | Переменная назначения и отклик |
| `RddResult.Effect` / `StandardError` / `PValue` | Оценка разрыва |
| `RddResult.LeftLimit` / `RightLimit` | Пределы с двух сторон |
| `RddResult.Sensitivity` / `Placebo` | Устойчивость и ложные пороги |
| `RddResult.DensityStatistic` / `DensityPValue` | Проверка на манипуляцию |

Исходники: `src/AI.Economics/Econometrics/RegressionDiscontinuity.cs`.

## Код

```csharp
using AI.Economics.Econometrics;
using AI.Statistics;

Random rng = RandomEngine.Create(139);
int n = 3000;
const double trueJump = 2.0;

var observations = new List<RddObservation>(n);

for (int i = 0; i < n; i++)
{
    double score = (rng.NextDouble() * 4) - 2;  // балл, порог — ноль

    double outcome = 1 + (0.5 * score)
        + (score >= 0 ? trueJump : 0)
        + RandomEngine.NextGaussian(rng, 0, 0.3);

    observations.Add(new RddObservation(score, outcome));
}

RddResult rdd = RegressionDiscontinuity.Estimate(observations, cutoff: 0);

Console.WriteLine($"Истинный скачок {trueJump:F2}");
Console.WriteLine($"Оценка {rdd.Effect:F4} ± {rdd.StandardError:F4} (p = {rdd.PValue:F5})");
Console.WriteLine($"Интервал [{rdd.ConfidenceLow:F3}; {rdd.ConfidenceHigh:F3}]");
Console.WriteLine($"Пределы: слева {rdd.LeftLimit:F3}, справа {rdd.RightLimit:F3}");
Console.WriteLine($"Полоса {rdd.Bandwidth:F3}, наблюдений {rdd.LeftObservations} + " +
                  $"{rdd.RightObservations}");
```

Без трёх проверок результат не принимается ни в одном приличном издании:

```csharp
Console.WriteLine("Устойчивость к полосе:");
foreach ((double width, double effect, double error) in rdd.Sensitivity)
    Console.WriteLine($"  h = {width:F3}: {effect:F3} ± {error:F3}");

Console.WriteLine("Плацебо-пороги:");
foreach ((double cutoff, double effect, double error) in rdd.Placebo)
{
    bool significant = error > 0 && Math.Abs(effect / error) > 1.96;
    Console.WriteLine($"  порог {cutoff:F2}: {effect:F3} ± {error:F3}" +
                      (significant ? " — тревожный сигнал" : ""));
}

Console.WriteLine($"Плотность на пороге: статистика {rdd.DensityStatistic:F3}, " +
                  $"p = {rdd.DensityPValue:F4}");
Console.WriteLine(rdd.DensityPValue > 0.05
    ? "Признаков манипуляции нет"
    : "Плотность разрывна — возможна подгонка под порог");
```

Манипуляция переменной назначения обнаруживается тем же тестом:

```csharp
var manipulated = new List<RddObservation>(n);
foreach (RddObservation point in observations)
{
    double score = point.Running;

    // Часть объектов чуть ниже порога «дотягивается» до него
    if (score is > -0.3 and < 0 && rng.NextDouble() < 0.5) score = -score * 0.5;

    manipulated.Add(new RddObservation(score, point.Outcome));
}

RddResult suspicious = RegressionDiscontinuity.Estimate(manipulated, 0);
Console.WriteLine($"При манипуляции: p плотности {suspicious.DensityPValue:F4}, " +
                  $"оценка {suspicious.Effect:F3}");

Console.WriteLine(rdd.Interpret().ToLlmText());
```

## Ограничения

- Эффект локален. Он справедлив для объектов у порога и не переносится на
  далёких от него — а именно они обычно интересуют политику.
- Выбор полосы пропускания влияет на результат сильнее любой другой детали.
  Всегда показывайте оценку при нескольких полосах.
- Требуется достаточная плотность наблюдений у порога. При редких данных
  локальная регрессия опирается на десятки точек, и интервалы огромны.
- Правило должно применяться строго. При «размытом» дизайне (порог влияет на
  вероятность воздействия, а не определяет его) нужна инструментальная
  версия — [двухшаговый МНК](iv_2sls.md) с индикатором порога как
  инструментом.
- Несколько порогов на одной переменной (ступенчатая шкала) требуют
  раздельной оценки: их нельзя объединять в одну регрессию без дополнительных
  допущений.
