# Ребалансировка с издержками и налогами

Четыре правила возврата к целевым весам — календарное, пороговое, частичное и
отсутствие ребалансировки — с учётом комиссий, налога на реализованную
прибыль и накопленного отклонения от цели.

## Постановка задачи

Дано: история доходностей активов, целевые веса, ставка комиссии, ставка
налога на прибыль от продажи и параметры правила (интервал или порог
отклонения).

Требуется: итоговая стоимость портфеля, суммарные издержки и налоги, оборот,
максимальное отклонение от целевых весов — и ответ, какое правило лучше на
этих данных.

Где встречается: инвестиционная политика фонда, регламент управления
портфелем клиента, спор о частоте ребалансировки, налоговая оптимизация
портфеля физического лица.

## Теория

Портфель без вмешательства **дрейфует**: выросшие активы занимают всё большую
долю, и профиль риска меняется сам собой. Ребалансировка возвращает веса к
цели, но каждая сделка стоит денег и реализует налоговую прибыль.

**Календарное правило** ребалансирует раз в $k$ периодов независимо от
состояния портфеля. Просто и предсказуемо, но торгует и тогда, когда
отклонение ничтожно.

**Пороговое правило** срабатывает, только когда максимальное отклонение веса
превысило порог $\delta$:

$$
\max_i |w_i^{\text{тек}} - w_i^{*}| > \delta .
$$

При типичных параметрах оно даёт тот же контроль риска при вдвое меньшем
обороте.

**Частичная ребалансировка** сдвигает веса не до цели, а на долю $\gamma$
расстояния до неё:

$$
w_i^{\text{нов}} \;=\; w_i^{\text{тек}} + \gamma\,(w_i^{*} - w_i^{\text{тек}}).
$$

Это компромисс между контролем отклонения и издержками; при $\gamma = 0{,}5$
оборот сокращается примерно вдвое, а отклонение растёт незначительно.

**Налоговый учёт.** Ключевая тонкость: при частичной продаже позиции
реализуется прибыль пропорционально проданной доле, и налоговая база
уменьшается в той же пропорции:

$$
\mathrm{Gain} \;=\; (V_i - B_i)\,\frac{|\Delta_i|}{V_i},
\qquad
B_i \;\leftarrow\; B_i\left(1 - \frac{|\Delta_i|}{V_i}\right).
$$

Поэтому корректный учёт ведётся в деньгах — в весах он невозможен в принципе.
Из-за налога оптимальная частота ребалансировки для налогооблагаемого счёта
существенно ниже, чем для пенсионного.

**Издержки как доля** (cost drag) — суммарные комиссии и налоги, отнесённые к
итоговой стоимости. Это прямое сравнение цены дисциплины и цены дрейфа.

## Сложность

| Ресурс | Оценка | Комментарий |
|--------|--------|-------------|
| Время  | $O(Tn)$ | $T$ периодов, $n$ активов |
| Память | $O(T + n)$ | сделки и позиции |

## API

| Метод | Описание |
|-------|----------|
| `Rebalancing.Simulate(returns, targets, rule, assets, cost, tax, interval, threshold, share, periodsPerYear)` | Прогон одного правила |
| `Rebalancing.CompareRules(returns, targets, assets, cost, tax)` | Все правила рядом |
| `RebalancingResult.Trades` | Сделки: оборот, издержки, налог |
| `RebalancingResult.TotalCost` / `TotalTax` / `CostDrag` | Цена дисциплины |
| `RebalancingResult.MaximumDrift` | Максимальное отклонение от цели |
| `RebalancingResult.FinalWeights` | Веса на конец периода |

Исходники: `src/AI.Economics/Portfolio/Rebalancing.cs`.

## Код

```csharp
using AI.DataStructs.Algebraic;
using AI.Economics.Portfolio;
using AI.Statistics;

Random walk = RandomEngine.Create(83);
var path = new Matrix(120, 3);
double[] mu = [0.004, 0.011, 0.006];
double[] sd = [0.009, 0.048, 0.028];

for (int t = 0; t < path.Height; t++)
{
    double common = RandomEngine.NextGaussian(walk);
    for (int j = 0; j < path.Width; j++)
        path[t, j] = mu[j] + (sd[j] * ((0.5 * common) + (0.87 * RandomEngine.NextGaussian(walk))));
}

var targets = new Vector(0.4, 0.4, 0.2);
string[] holdings = ["Облигации", "Акции", "Золото"];

RebalancingResult threshold = Rebalancing.Simulate(
    path, targets, RebalancingRule.Threshold, holdings,
    transactionCost: 0.0015, taxRate: 0.13, threshold: 0.05, periodsPerYear: 12);

Console.WriteLine($"Итоговая стоимость {threshold.FinalValue:F4} (без издержек {threshold.GrossValue:F4})");
Console.WriteLine($"Ребалансировок {threshold.RebalanceCount}, оборот {threshold.TotalTurnover:P1}");
Console.WriteLine($"Издержки {threshold.TotalCost:P2}, налоги {threshold.TotalTax:P2}, " +
                  $"итого {threshold.CostDrag:P2}");
Console.WriteLine($"Максимальный дрейф {threshold.MaximumDrift:P1}");
```

Сравнение правил — главный практический результат:

```csharp
IReadOnlyList<RebalancingResult> rules = Rebalancing.CompareRules(
    path, targets, holdings, transactionCost: 0.0015, taxRate: 0.13);

foreach (RebalancingResult rule in rules)
{
    Console.WriteLine($"{rule.Rule}: доходность {rule.AnnualReturn:P2}, " +
                      $"волатильность {rule.Volatility:P2}, " +
                      $"издержки {rule.CostDrag:P2}, дрейф {rule.MaximumDrift:P1}");
}
```

Налог меняет вывод сильнее комиссии — это стоит проверять отдельно:

```csharp
foreach (double tax in new[] { 0.0, 0.13, 0.20 })
{
    RebalancingResult scenario = Rebalancing.Simulate(
        path, targets, RebalancingRule.Calendar, holdings,
        transactionCost: 0.0015, taxRate: tax, interval: 3);

    Console.WriteLine($"Ставка налога {tax:P0}: издержки {scenario.CostDrag:P2}, " +
                      $"доходность {scenario.AnnualReturn:P2}");
}

Console.WriteLine(threshold.Interpret().ToLlmText());
```

## Ограничения

- Результат сравнения правил зависит от конкретной реализации доходностей.
  На трендовом рынке отсутствие ребалансировки выигрывает, на боковом —
  проигрывает; вывод по одной траектории ненадёжен, нужен прогон по многим.
- Модель предполагает, что налог платится в момент продажи по единой ставке.
  Льгота за долгое владение, сальдирование убытков и перенос убытков на
  будущее меняют картину принципиально.
- Издержки заданы линейной ставкой от оборота. Для крупных позиций
  существенна ещё и цена влияния на рынок, растущая быстрее линейной.
- Дивиденды и купоны не моделируются отдельно. Между тем реинвестирование
  поступлений — самый дешёвый способ ребалансировки, не порождающий продаж
  вовсе.
- Целевые веса считаются постоянными. Если они пересматриваются, к издержкам
  ребалансировки добавляются издержки смены стратегии — их надо учитывать
  отдельно.
