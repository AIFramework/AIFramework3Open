# Скоринг контрагента и лимит отгрузки

Балльная оценка коммерческого контрагента с явными весами факторов, вероятность
дефолта, рекомендованный лимит и ставка финансирования в факторинге.

## Постановка задачи

Дано: финансовые показатели контрагента (выручка, прибыль, капитал, долг,
ликвидность), его поведение в расчётах (просрочки оплат, споры по поставкам,
концентрация покупателей) и запрошенный лимит.

Требуется: решение по заявке, размер лимита отгрузки без предоплаты, ставка
финансирования для факторинга и ожидаемые потери на этом лимите.

Где встречается: коммерческий кредит поставщика, факторинг, дистрибуция с
отсрочкой платежа, лизинг оборудования малому бизнесу.

## Теория

Задача отличается от банковского скоринга: решается не «выдать или нет», а
«на какую сумму отгружать без предоплаты». Обучающей выборки обычно нет —
поставщик работает с сотнями контрагентов, а не с сотнями тысяч, — поэтому
модель строится как взвешенная оценка факторов с явными весами, а не
оценивается регрессией.

Факторы делятся на три группы:

| Группа | Факторы | Суммарный вес |
|--------|---------|---------------|
| Финансовая устойчивость | капитал, ликвидность, долговая нагрузка, рентабельность | 0,60 |
| Масштаб и история | выручка, срок работы, динамика | 0,20 |
| Поведение | просрочки оплат, споры, концентрация покупателей | 0,20 |

Каждый фактор нормируется в отрезок $[0,1]$ кусочно-линейным отображением и
складывается с весом:

$$
\text{Score} \;=\; 100\sum_j w_j\, s_j(x_j),
\qquad
\mathrm{PD} \;=\; \mathrm{clamp}\bigl(0{,}5\,e^{-0{,}055\,\text{Score}}\bigr).
$$

Стоп-факторы — налоговая задолженность, существенные иски, отрицательный
капитал, систематическая просрочка — не обнуляют балл, а снижают его и
переводят решение на кредитный комитет. Полное обнуление скрыло бы информацию
о том, насколько контрагент хорош по остальным факторам.

**Лимит** ограничивается сверху двумя независимыми правилами — долей капитала
контрагента и месяцами его выручки — и масштабируется баллом:

$$
\text{Limit} \;=\; \min\Bigl(\kappa\,\mathrm{Equity},\; \tau\,\frac{\mathrm{Revenue}}{12}\Bigr)
\cdot \Bigl(\frac{\text{Score}}{100}\Bigr)^{3/2}.
$$

Смысл двойного ограничения в том, что ни один поставщик не должен становиться
основным кредитором покупателя: даже отличный балл не оправдывает лимит,
сопоставимый с собственным капиталом контрагента.

Решение принимается не по вероятности дефолта, а по соотношению маржи сделки и
ожидаемых потерь $\text{Limit}\cdot \mathrm{PD}\cdot \mathrm{LGD}$. Лимит здесь —
инструмент управления риском, а не следствие балла.

## Сложность

| Ресурс | Оценка | Комментарий |
|--------|--------|-------------|
| Время  | $O(k)$ | $k$ факторов, всё считается в один проход |
| Память | $O(k)$ | вклады факторов |

## API

| Метод | Описание |
|-------|----------|
| `CounterpartyScoring.Score(profile, options)` | Балл, класс, лимит и решение |
| `CounterpartyScoring.ScoreAll(profiles, options)` | Пул контрагентов по убыванию балла |
| `CounterpartyScore.Factors` | Вклад каждого фактора с пояснением |
| `CounterpartyScore.StopFactors` | Сработавшие стоп-факторы |
| `CounterpartyScore.RecommendedLimit` / `AdvanceRate` | Лимит отгрузки и ставка факторинга |
| `CounterpartyOptions` | Предельная доля капитала, месяцы выручки, порог одобрения |

Исходники: `src/AI.Economics/Credit/CounterpartyScoring.cs`.

## Код

```csharp
using AI.Economics.Credit;

var distributor = new CounterpartyProfile
{
    Name = "Надёжный дистрибьютор",
    Revenue = 1_200_000_000,
    Ebitda = 150_000_000,
    Equity = 400_000_000,
    TotalDebt = 250_000_000,
    CurrentAssets = 500_000_000,
    CurrentLiabilities = 250_000_000,
    RevenueGrowth = 0.14,
    YearsInBusiness = 12,
    AveragePaymentDelayDays = 3,
    DisputeRate = 0.01,
    BuyerConcentration = 0.25,
    RequestedLimit = 40_000_000,
};

CounterpartyScore decision = CounterpartyScoring.Score(distributor);

Console.WriteLine($"Балл {decision.Score:F1} из 100, класс {decision.Grade}");
Console.WriteLine($"Вероятность дефолта {decision.ProbabilityOfDefault:P2}");
Console.WriteLine($"Лимит {decision.RecommendedLimit:N0} из запрошенных {decision.RequestedLimit:N0}");
Console.WriteLine($"Ставка финансирования {decision.AdvanceRate:P0}, решение: {decision.Decision}");

foreach (CounterpartyFactor factor in decision.Factors)
    Console.WriteLine($"{factor.Name}: {factor.Contribution:F1} балла — {factor.Comment}");
```

Слабый контрагент и стоп-факторы:

```csharp
var risky = distributor with
{
    Name = "Проблемный поставщик",
    Revenue = 180_000_000,
    Ebitda = 4_000_000,
    Equity = 12_000_000,
    TotalDebt = 90_000_000,
    CurrentAssets = 70_000_000,
    CurrentLiabilities = 85_000_000,
    RevenueGrowth = -0.20,
    YearsInBusiness = 1.5,
    AveragePaymentDelayDays = 38,
    HasTaxArrears = true,
    RequestedLimit = 25_000_000,
};

CounterpartyScore refused = CounterpartyScoring.Score(risky);

Console.WriteLine($"{refused.Name}: балл {refused.Score:F1}, {refused.Decision}");
Console.WriteLine($"Стоп-факторы: {string.Join(", ", refused.StopFactors)}");
Console.WriteLine(refused.Interpret().ToLlmText());
```

Настройки кредитной политики задаются явно и одинаковы для всего пула:

```csharp
var policy = new CounterpartyOptions
{
    LossGivenDefault = 0.7,
    EquityShareCap = 0.10,
    RevenueMonthsCap = 1.0,
    ApprovalScore = 55,
};

IReadOnlyList<CounterpartyScore> ranked =
    CounterpartyScoring.ScoreAll([distributor, risky], policy);

foreach (CounterpartyScore item in ranked)
    Console.WriteLine($"{item.Name}: {item.Grade}, лимит {item.RecommendedLimit:N0}");
```

## Ограничения

- Веса факторов заданы экспертно и не оценивались на данных. Если накопилась
  история дефолтов контрагентов, точнее построить [скоркарту](scorecard.md) на
  тех же признаках.
- Отчётность контрагента обычно отстаёт на квартал и более. Платёжная
  дисциплина по вашим собственным отгрузкам предсказывает дефолт лучше любого
  коэффициента из баланса, поэтому лимит нужно пересматривать по факту оплат.
- Вероятность дефолта получается из балла экспоненциальным преобразованием с
  фиксированными константами. Её уровень — ориентир, а не калиброванная оценка.
- Модель не учитывает обеспечение, страхование дебиторской задолженности и
  групповую структуру: связанные компании должны оцениваться одним лимитом.
- Ставка финансирования в факторинге зависит ещё и от качества дебиторов
  контрагента, которое здесь не оценивается.
