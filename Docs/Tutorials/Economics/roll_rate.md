# Анализ перетекания просрочки

Ставки перехода между корзинами просрочки и ожидаемые потери, выведенные прямо
из оборотной ведомости — без моделей вероятности дефолта.

## Постановка задачи

Дано: история остатков задолженности по корзинам просрочки — текущая,
1–30 дней, 31–60, 61–90, 91–120, списание — за несколько периодов.

Требуется: доля остатка, перетекающая на каждом шаге, доля текущей
задолженности, которая в итоге станет убытком, и ожидаемые потери из
сложившихся остатков.

Где встречается: резервы по коротким розничным портфелям, независимая проверка
модельных резервов, оценка эффективности взыскания, экспресс-анализ портфеля
при покупке.

## Теория

Портфель разбивается на корзины по числу дней просрочки. Ставка перетекания
показывает, какая доля остатка корзины за период переходит в следующую:

$$
r_i \;=\; \frac{\text{balance}(t+1,\, i+1)}{\text{balance}(t,\, i)} .
$$

Произведение ставок вдоль всей цепочки даёт долю остатка, которая дойдёт до
списания:

$$
\mathrm{RollToLoss}_i \;=\; \prod_{k=i}^{K-1} r_k ,
\qquad
\mathrm{Loss} \;=\; \sum_i \text{balance}_i \cdot \mathrm{RollToLoss}_i .
$$

Ценность метода — в прозрачности: каждая цифра проверяется по оборотной
ведомости, никакие параметры не оцениваются. Поэтому его используют и как
самостоятельный расчёт резерва для коротких розничных портфелей, и как
независимую проверку моделей: расхождение с резервом по МСФО 9 больше четверти
почти всегда указывает на ошибку в стадировании, а не на разницу методик.

Практически важны три вещи. Во-первых, ставка первого шага — вход в просрочку —
отражает качество выдач, а последующие ставки отражают качество взыскания:
это разные подразделения и разные решения. Во-вторых, разброс ставки по
периодам не менее информативен, чем среднее: нестабильный шаг означает, что
прогноз по нему ненадёжен. В-третьих, сравнение последнего периода со средним
даёт ранний сигнал ухудшения сбора.

## Сложность

| Ресурс | Оценка | Комментарий |
|--------|--------|-------------|
| Время  | $O(T\,K)$ | $T$ периодов, $K$ корзин |
| Память | $O(T\,K)$ | матрица остатков |

## API

| Метод | Описание |
|-------|----------|
| `RollRate.DefaultBuckets()` | Стандартные корзины розничной просрочки |
| `RollRate.Analyze(buckets, balances)` | Ставки перетекания и ожидаемые потери |
| `RollRateResult.Steps` | Средняя ставка, разброс и последний период по шагам |
| `RollRateResult.RollToLoss` | Доля остатка корзины, доходящая до списания |
| `RollRateResult.ImpliedLoss` / `ImpliedLossRate` | Ожидаемые потери в деньгах и в долях |

Исходники: `src/AI.Economics/Credit/RollRate.cs`.

## Код

```csharp
using AI.DataStructs.Algebraic;
using AI.Economics.Credit;

IReadOnlyList<string> buckets = RollRate.DefaultBuckets();

const int months = 12;
var balances = new Matrix(months, buckets.Count);
double[] level = [1_000_000_000, 40_000_000, 22_000_000, 12_000_000, 7_000_000, 4_000_000];

for (int t = 0; t < months; t++)
{
    for (int b = 0; b < buckets.Count; b++)
    {
        // Лёгкая сезонность: остатки колеблются вокруг уровня
        balances[t, b] = level[b] * (1 + (0.02 * ((t % 3) - 1)));
    }
}

RollRateResult roll = RollRate.Analyze(buckets, balances);

foreach (RollRateStep step in roll.Steps)
{
    Console.WriteLine($"{step.FromBucket} -> {step.ToBucket}: " +
                      $"{step.AverageRollRate:P1} (разброс {step.StandardDeviation:P2})");
}

Console.WriteLine($"Из текущей задолженности до списания доходит {roll.RollToLoss[0]:P3}");
Console.WriteLine($"Ожидаемые потери: {roll.ImpliedLoss:N0} ({roll.ImpliedLossRate:P2} портфеля)");
```

Результат читается вместе с разбором — он же годится для отчёта:

```csharp
Console.WriteLine(roll.Interpret().ToLlmText());
```

Сверка с резервом по МСФО 9 на том же портфеле — типовая проверка валидации:

```csharp
var quickPortfolio = new List<CreditExposure>
{
    new()
    {
        Id = "Портфель", ExposureAtDefault = roll.LatestBalances[0],
        ProbabilityOfDefault = roll.RollToLoss[0], LossGivenDefault = 1.0,
        RemainingMonths = 12, EffectiveInterestRate = 0.18,
    },
};

EclResult reserve = Ifrs9.Compute(quickPortfolio);

Console.WriteLine($"Метод перетекания: {roll.ImpliedLoss:N0}");
Console.WriteLine($"МСФО 9 на тех же входных данных: {reserve.TotalEcl:N0}");
```

## Ограничения

- Метод предполагает, что остаток корзины движется только вперёд по шкале.
  Реструктуризации, частичные платежи и выход из просрочки нарушают
  предпосылку и занижают расчётные потери.
- Продажа портфеля коллекторам обнуляет старшие корзины и делает ставки
  перетекания несопоставимыми между периодами. Такие месяцы надо исключать.
- Ставки сезонны. Оценка по трём-четырём периодам почти наверняка примет
  сезонное колебание за тренд.
- Усреднение по всему портфелю скрывает проблемные сегменты: считать нужно
  отдельно по продуктам и каналам выдачи.
- Метод даёт ожидаемые потери, но не даёт вероятность дефолта отдельного
  заёмщика — для решений по конкретной заявке нужна [скоркарта](scorecard.md).
