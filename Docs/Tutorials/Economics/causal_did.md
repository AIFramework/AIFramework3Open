# Разность разностей и современные робастные оценки

Оценка эффекта политики по данным «до и после» с контрольной группой:
классическая двусторонняя регрессия, её смещение при ступенчатом внедрении и
робастная оценка по когортам с исследованием динамики эффекта.

## Постановка задачи

Дано: панель наблюдений, часть объектов в некоторый момент попадает под
воздействие (программа, закон, тариф), часть — нет или попадает позже.

Требуется: средний эффект воздействия на подвергшихся ему, динамика эффекта
по периодам и проверка ключевого допущения о параллельных трендах.

Где встречается: оценка эффекта закона по регионам, запуск функции в части
магазинов, изменение тарифа для группы клиентов, вход конкурента на часть
рынков.

## Теория

**Базовая идея.** Простое сравнение «до и после» смешивает эффект с общим
трендом. Простое сравнение групп смешивает эффект с их различиями. Разность
разностей вычитает и то, и другое:

$$
\widehat{\mathrm{ATT}} \;=\;
\left(\bar y^{\text{возд}}_{\text{после}} - \bar y^{\text{возд}}_{\text{до}}\right)
-
\left(\bar y^{\text{контр}}_{\text{после}} - \bar y^{\text{контр}}_{\text{до}}\right).
$$

**Допущение параллельных трендов** — в отсутствие воздействия обе группы
изменились бы одинаково. Оно непроверяемо напрямую, но косвенно оценивается по
периодам **до** воздействия: если эффекты там значимо отличаются от нуля,
допущение под сомнением.

**Двусторонняя регрессия** — стандартная реализация:

$$
y_{it} = \alpha_i + \gamma_t + \delta\,D_{it} + \varepsilon_{it}.
$$

При одновременном воздействии на всех она даёт корректную оценку. Но при
**ступенчатом внедрении** (объекты подключаются в разное время) она смещена,
что было показано в работах 2020-х годов: коэффициент $\delta$ оказывается
взвешенной суммой сравнений между когортами, причём часть весов
**отрицательна** — уже подвергшиеся воздействию используются как контроль для
подключающихся позже. При гетерогенном во времени эффекте оценка может даже
поменять знак.

**Робастная оценка** (в духе Каллауэй — Сант'Анна) строит эффекты по группам
и периодам $\mathrm{ATT}(g,t)$, используя в качестве контроля только
**никогда** или **ещё не** подвергшихся воздействию, и агрегирует их с
неотрицательными весами.

**Событийное исследование** показывает эффект по относительным периодам
$t - g$: до нуля должно быть плоско (проверка допущения), после — динамика
эффекта. Именно этот график, а не одно число, убеждает рецензента.

**Стандартные ошибки** считаются кластерным бутстрапом по объектам: внутри
объекта наблюдения зависимы, и игнорирование этого занижает ошибки в разы.

## Сложность

| Ресурс | Оценка | Комментарий |
|--------|--------|-------------|
| Время  | $O(B\,N T)$ | $B$ бутстрап-повторов |
| Память | $O(NT)$ | панель наблюдений |

## API

| Метод | Описание |
|-------|----------|
| `DifferenceInDifferences.Estimate(observations, bootstrap, seed)` | Обе оценки и событийное исследование |
| `DidObservation(unit, period, outcome, firstTreatedPeriod)` | Наблюдение; 0 — никогда не под воздействием |
| `DidResult.RobustAtt` / `TwoWayFixedEffects` | Робастная и классическая оценки |
| `DidResult.EstimatorGap` | Расхождение — индикатор смещения |
| `DidResult.EventStudy` | Эффект по относительным периодам |
| `DidResult.PreTrendPValue` | Проверка параллельности трендов |

Исходники: `src/AI.Economics/Econometrics/DifferenceInDifferences.cs`.

## Код

```csharp
using AI.Economics.Econometrics;
using AI.Statistics;

Random rng = RandomEngine.Create(137);
int units = 90, periods = 10;
const double trueEffect = 3.0;

var observations = new List<DidObservation>();

for (int u = 0; u < units; u++)
{
    // Ступенчатое внедрение: треть не участвует, треть с пятого, треть с восьмого периода
    int firstTreated = u % 3 == 0 ? 0 : u % 3 == 1 ? 5 : 8;
    double level = RandomEngine.NextGaussian(rng, 10, 2);

    for (int t = 1; t <= periods; t++)
    {
        double outcome = level + (0.5 * t) + RandomEngine.NextGaussian(rng, 0, 0.5);
        if (firstTreated > 0 && t >= firstTreated) outcome += trueEffect;

        observations.Add(new DidObservation(u, t, outcome, firstTreated));
    }
}

DidResult did = DifferenceInDifferences.Estimate(observations, bootstrapSamples: 200, seed: 5);

Console.WriteLine($"Истинный эффект {trueEffect:F2}");
Console.WriteLine($"Робастная оценка {did.RobustAtt:F4} ± {did.RobustStandardError:F4}");
Console.WriteLine($"Двусторонние эффекты {did.TwoWayFixedEffects:F4} ± {did.TwoWayStandardError:F4}");
Console.WriteLine($"Расхождение оценок {did.EstimatorGap:F4}");
Console.WriteLine($"Когорт {did.Cohorts}, под воздействием {did.Treated}, " +
                  $"контрольных {did.NeverTreated}");
```

Событийное исследование — обязательная часть отчёта, а не иллюстрация:

```csharp
foreach (EventStudyPoint point in did.EventStudy)
{
    string marker = point.RelativePeriod < 0 ? "до" : "после";
    Console.WriteLine($"{point.RelativePeriod:+0;-0;0} ({marker}): {point.Estimate:F3} " +
                      $"[{point.ConfidenceLow:F2}; {point.ConfidenceHigh:F2}]" +
                      (point.IsSignificant ? " — значим" : ""));
}

Console.WriteLine($"Параллельность трендов: p = {did.PreTrendPValue:F4}");
Console.WriteLine(did.PreTrendPValue > 0.05
    ? "Допущение о параллельных трендах не отвергается"
    : "Тренды до воздействия расходятся — оценке доверять нельзя");
```

Смещение классической оценки проявляется тем сильнее, чем разнообразнее
моменты подключения:

```csharp
var simultaneous = observations
    .Select(o => o with { FirstTreatedPeriod = o.FirstTreatedPeriod > 0 ? 5 : 0 })
    .ToList();

DidResult uniform = DifferenceInDifferences.Estimate(simultaneous, 200, 5);
Console.WriteLine($"При одновременном внедрении расхождение {uniform.EstimatorGap:F4} " +
                  $"против {did.EstimatorGap:F4} при ступенчатом");

Console.WriteLine(did.Interpret().ToLlmText());
```

## Ограничения

- Допущение о параллельных трендах невозможно доказать. Плоские
  предварительные тренды — необходимое, но не достаточное свидетельство:
  тренды могли разойтись именно в момент воздействия.
- Метод не работает, если воздействие само вызвано изменением отклика.
  Программу поддержки вводят там, где дела идут плохо, — это классическая
  обратная причинность.
- Эффекты перелива (объекты под воздействием влияют на контрольные) нарушают
  ключевое условие. Соседние регионы почти всегда взаимодействуют.
- Кластерный бутстрап требует достаточного числа объектов. При $N < 30$
  доверительные интервалы занижены, и нужен wild bootstrap.
- Робастная оценка требует наличия достаточной контрольной группы. Если
  воздействию подверглись все объекты, метод неприменим — используйте
  [синтетический контроль](synthetic_control.md) или
  [разрывный дизайн](causal_rdd.md).
