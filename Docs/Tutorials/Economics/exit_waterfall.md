# Каскад выплат при выходе

Кто и сколько получит при продаже компании за заданную сумму: ликвидационные
преференции, участие в остатке, потолки и решение о конвертации.

## Постановка задачи

Дано: таблица капитализации с классами акций и их условиями, цена продажи
компании.

Требуется: выплата каждому держателю, решение по каждому классу
(взять преференцию или конвертироваться) и цена обыкновенной акции.

Где встречается: обсуждение term sheet, оценка опционов сотрудника, решение
о принятии предложения о покупке, спор акционеров о распределении.

## Теория

Главный вопрос, на который таблица долей не отвечает: 20 % — это сколько денег?
При наличии преференций ответ нелинеен и на умеренных суммах сделки может быть
равен нулю.

Порядок распределения:

1. **Преференции по старшинству.** Классы с большим старшинством получают
   $k_i \cdot I_i$ раньше остальных; классы одного старшинства делят
   доступную сумму пропорционально своим требованиям.
2. **Остаток** делится между обыкновенными акциями, конвертированными классами
   и участвующими привилегированными — пропорционально числу акций.
3. **Потолки участия.** Если суммарная выплата участвующего класса превышает
   $c_i \cdot I_i$, она фиксируется на потолке, а высвободившееся
   перераспределяется между остальными.

Решение о конвертации ищется итеративно. Неучаствующий класс сравнивает
преференцию с тем, что дала бы конвертация в обыкновенные акции:

$$
\text{payout}_i \;=\; \max\left( k_i I_i,\; \frac{n_i}{N_{common}} \cdot \bigl(V - \textstyle\sum_{j \ne i} \text{pref}_j\bigr) \right).
$$

Выбор одного класса меняет расклад для остальных, поэтому процесс повторяется
до стабилизации. Точка, где конвертация становится выгоднее преференции, — та
самая «ступенька» на графике выплат основателям: до неё почти весь прирост цены
сделки достаётся инвесторам.

## Сложность

| Ресурс | Оценка | Комментарий |
|--------|--------|-------------|
| Время  | $O(K^2 \cdot (K + n))$ | $K$ — классов акций, $n$ — держателей |
| Память | $O(K + n)$ | Выплаты по классам и держателям |

Число классов в реальных таблицах невелико, поэтому квадратичный поиск решения
о конвертации не имеет практического значения.

## API

| Метод | Описание |
|-------|----------|
| `ExitWaterfall.Distribute(table, exitValue)` | Распределение суммы сделки |
| `ExitWaterfall.PayoutCurve(table, maxExit, points)` | Выплаты как функция цены продажи |
| `ExitWaterfallResult.Payouts` | Выплаты держателям, по убыванию |
| `ExitWaterfallResult.Classes` | Решение по каждому классу и его составляющие |
| `ExitWaterfallResult.CommonPerShare` | Цена обыкновенной акции в этой сделке |
| `ShareClass.ParticipationCap` | Потолок участия в кратностях вложения |

Исходник: `src/AI.Economics/Equity/ExitWaterfall.cs`.

## Код

```csharp
using AI.Economics.Equity;

var seed = new CapTable()
    .AddHolding("Основатель 1", 6_000_000)
    .AddHolding("Основатель 2", 4_000_000);

CapTable afterA = FundingRound.Execute(seed, new RoundInput
{
    RoundName = "Series A",
    InvestorName = "Фонд A",
    PreMoneyValuation = 400_000_000,
    Investment = 100_000_000,
    TargetOptionPoolPost = 0.10,
}).CapTable;

CapTable afterB = FundingRound.Execute(afterA, new RoundInput
{
    RoundName = "Series B",
    InvestorName = "Фонд B",
    PreMoneyValuation = 1_500_000_000,
    Investment = 300_000_000,
    Preference = PreferenceType.Participating,
    ParticipationCap = 2.0,
}).CapTable;

foreach (double exitValue in new[] { 400_000_000d, 1_200_000_000d, 4_000_000_000d })
{
    ExitWaterfallResult outcome = ExitWaterfall.Distribute(afterB, exitValue);

    double founders = outcome.Payouts
        .Where(payout => payout.Holder.StartsWith("Основатель"))
        .Sum(payout => payout.Payout);

    Console.WriteLine($"Продажа за {exitValue:N0}: основателям {founders:N0} " +
                      $"({founders / exitValue:P1} при доле в капитале)");

    foreach (ClassOutcome outcomeClass in outcome.Classes)
        Console.WriteLine($"   {outcomeClass.ClassName,-20} {outcomeClass.Decision,-32} {outcomeClass.TotalPaid:N0}");
}
```

## Ограничения

- Нераспределённые опционы участвуют как обыкновенные акции: цена исполнения не
  учитывается. На суммах сделки, где она значима, опционы всё равно не
  исполняются, но для точного расчёта выплат сотрудникам это упрощение надо
  помнить.
- Не моделируются escrow, earn-out, отложенные платежи и налоги — распределяется
  сумма, фактически поступившая акционерам в момент сделки.
- Накопленные дивиденды по привилегированным акциям в преференцию не входят.
  Если они предусмотрены договором, увеличьте `Invested` на их сумму.
- Право на конвертацию считается безусловным; блокирующие условия и
  необходимость согласия отдельных классов не проверяются.
