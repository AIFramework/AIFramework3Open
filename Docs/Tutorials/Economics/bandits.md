# Многорукие бандиты

Стратегии распределения трафика между вариантами, когда важнее не измерить
эффект, а получить максимум конверсий по ходу дела.

## Постановка задачи

Дано: несколько вариантов с неизвестными конверсиями и поток показов.

Требуется: правило выбора варианта на каждом показе, минимизирующее суммарные
потери от того, что лучший вариант заранее неизвестен.

Где встречается: подбор баннера, тема письма в рассылке, порядок выдачи
рекомендаций, ротация креативов.

## Теория

A/B-тест и бандит решают разные задачи. Тест минимизирует ошибку оценки
эффекта: трафик делится поровну и не меняется до конца. Бандит минимизирует
**потери** — суммарную разницу между полученным результатом и тем, что дал бы
всезнающий выбор лучшего варианта с самого начала:

$$
R_T = T \max_i \mu_i - \sum_{t=1}^{T} \mu_{a_t}.
$$

Реализованы четыре стратегии.

**Равномерное деление** — обычный A/B-тест. Оценивает каждый вариант с
максимальной точностью и платит за это линейно растущими потерями: половина
трафика уходит заведомо худшему варианту до самого конца.

**Эпсилон-жадная** — с вероятностью $\varepsilon$ случайный вариант, иначе
лучший по текущей оценке. Проста, но продолжает тратить фиксированную долю
трафика на исследование даже тогда, когда ответ давно ясен.

**Верхняя доверительная граница (UCB)** — оптимизм при неопределённости:

$$
a_t = \arg\max_i \left( \hat\mu_i + \sqrt{\frac{2\ln t}{n_i}} \right).
$$

Вариант с малым числом показов получает большую надбавку и потому не будет
отброшен по случайной неудаче.

**Сэмплирование Томпсона** — из апостериорного бета-распределения каждого
варианта берётся выборка, выбирается вариант с наибольшей. Доля трафика
оказывается пропорциональна вероятности быть лучшим. На практике обычно
даёт наименьшие потери.

Плата за адаптивность — смещённые оценки. У проигрывающих вариантов мало
наблюдений, и сказать, насколько именно они хуже, бандит не может. Поэтому
для решения «менять ли продукт» нужен тест, а для решения «какой баннер
показать сейчас» — бандит.

## Сложность

| Ресурс | Оценка | Комментарий |
|--------|--------|-------------|
| Время  | $O(T k)$ | $T$ — показов, $k$ — вариантов |
| Память | $O(T + k)$ | Траектория потерь и счётчики |

## API

| Метод | Описание |
|-------|----------|
| `Bandits.Simulate(names, rates, policy, rounds, epsilon, seed)` | Симуляция одной стратегии |
| `Bandits.CompareAll(names, rates, rounds, epsilon, seed)` | Все стратегии, по возрастанию потерь |
| `BanditSimulationResult.Regret` | Недополученные конверсии |
| `BanditSimulationResult.BestArmShare` | Доля трафика, доставшаяся лучшему варианту |
| `BanditSimulationResult.RegretPath` | Накопленные потери по шагам |
| `BanditArmResult.TrafficShare` | Как распределился трафик между вариантами |

Исходник: `src/AI.Economics/Experiments/Bandits.cs`.

## Код

```csharp
using AI.DataStructs.Algebraic;
using AI.Economics.Experiments;

var trueRates = new Vector(0.05, 0.08, 0.12);
string[] variants = ["Баннер A", "Баннер B", "Баннер C"];

foreach (BanditSimulationResult run in Bandits.CompareAll(variants, trueRates, rounds: 20_000))
{
    Console.WriteLine($"{run.Policy,-24} потери {run.Regret,8:N0}  " +
                      $"лучшему досталось {run.BestArmShare:P0}  " +
                      $"конверсий {run.TotalReward:N0}");
}

BanditSimulationResult thompson = Bandits.Simulate(
    variants, trueRates, BanditPolicy.ThompsonSampling, rounds: 20_000, seed: 9);

foreach (BanditArmResult arm in thompson.Arms)
{
    Console.WriteLine($"{arm.Name,-12} истинная {arm.TrueRate:P1}, " +
                      $"наблюдённая {arm.ObservedRate:P1}, трафика {arm.TrafficShare:P0}");
}

Console.WriteLine(thompson.Interpret().ToLlmText());
```

## Ограничения

- Симуляция предполагает стационарность: истинные конверсии не меняются
  во времени. При сезонности и дрейфе адаптивные стратегии закрепляют вариант,
  который был лучшим только в начале.
- Оценки вариантов смещены. Доверительные интервалы у проигравших широки,
  и измерять по ним размер эффекта нельзя.
- Отложенная конверсия ломает обратную связь: если результат показа становится
  известен через сутки, бандит принимает решения на устаревших данных.
- Сэмплирование Томпсона предполагает бинарный отклик с бета-априорным
  распределением. Для непрерывных метрик (выручка на показ) нужна другая
  параметризация.
- Результат симуляции зависит от зерна генератора. Сравнивайте стратегии
  на одном зерне, иначе разница будет частично шумом.
