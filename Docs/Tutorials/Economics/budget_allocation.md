# Оптимальное распределение маркетингового бюджета

Как разложить фиксированный бюджет между каналами так, чтобы суммарный отклик
был максимальным — и почему распределение по среднему ROI даёт неверный ответ.

## Постановка задачи

Дано: оценённая маркетинг-микс модель с кривыми насыщения по каналам и общий
бюджет на период.

Требуется: рекомендованные затраты по каналам и оценка прироста продаж без
увеличения бюджета.

Где встречается: квартальное планирование, срочное сокращение расходов,
обоснование переноса бюджета между каналами.

## Теория

Отклик канала в установившемся режиме при постоянных затратах $s$ равен

$$
r_i(s) = \beta_i\, h_i\!\left(\frac{s}{1-\lambda_i}\right),
$$

где деление на $1-\lambda_i$ — сумма геометрической прогрессии накопленного
эффекта, а $h_i$ — кривая Хилла.

Задача: максимизировать $\sum_i r_i(s_i)$ при $\sum_i s_i = B$, $s_i \ge 0$.

**Классическое решение через множитель Лагранжа здесь непригодно.** Оно
опирается на вогнутость отклика, а кривая Хилла при показателе больше единицы
S-образна: на начальном участке отдача **растёт** с бюджетом. Уравнение
«предельная отдача равна заданному уровню» имеет на такой кривой два корня,
и водоналивной алгоритм находит не тот. Результат внешне выглядит правдоподобно
и при этом хуже исходного распределения.

Используется последовательный перенос малых долей бюджета из канала с
наименьшей предельной отдачей в канал с наибольшей, с проверкой суммарного
отклика на каждом шаге. Алгоритм монотонно улучшает решение независимо от
формы кривой и сходится к выравниванию предельных отдач там, где отклик
вогнут. Отправная точка — текущее распределение, поэтому результат заведомо
не хуже того, что компания делает сейчас.

Главная практическая мысль: перераспределять надо по **предельному**, а не
по среднему ROI. Средний включает уже сделанные вложения — в том числе те,
что пришлись на крутой участок кривой, — и потому завышает привлекательность
крупных каналов, давно вышедших на плато.

## Сложность

| Ресурс | Оценка | Комментарий |
|--------|--------|-------------|
| Время  | $O(S \cdot k)$ | $S$ — шагов переноса (до 4000), $k$ — каналов |
| Память | $O(k)$ | Вектор бюджетов |

## API

| Метод | Описание |
|-------|----------|
| `BudgetOptimizer.Allocate(model, totalBudget, periods)` | Распределение бюджета |
| `BudgetOptimizer.Response(effect, spendPerPeriod)` | Отклик канала в установившемся режиме |
| `BudgetAllocationResult.ResponseGain` | Прирост продаж без увеличения бюджета |
| `ChannelBudget.MarginalReturnAtOptimum` | Предельная отдача; в оптимуме выравнивается |
| `ChannelBudget.Change` | Относительное изменение бюджета канала |

Исходник: `src/AI.Economics/Marketing/BudgetOptimizer.cs`.

## Код

```csharp
using AI.DataStructs.Algebraic;
using AI.Economics.Marketing;

var random = new Random(3);
const int weeks = 156;

var tvSpend = new Vector(weeks);
var digitalSpend = new Vector(weeks);
var revenue = new Vector(weeks);
double tvStock = 0, digitalStock = 0;

for (int t = 0; t < weeks; t++)
{
    tvSpend[t] = t % 8 < 3 ? 800_000 * (0.7 + (random.NextDouble() * 0.6)) : 0;
    digitalSpend[t] = 300_000 * (0.6 + (random.NextDouble() * 0.8));

    tvStock = tvSpend[t] + (0.6 * tvStock);
    digitalStock = digitalSpend[t] + (0.2 * digitalStock);

    revenue[t] = 8_000_000 + (12_000 * t)
               + (4_000_000 * MarketingMixModel.Hill(tvStock, 1_500_000, 1.5))
               + (2_000_000 * MarketingMixModel.Hill(digitalStock, 400_000, 1.2));
}

MmmResult model = MarketingMixModel.Fit(new MmmInput
{
    Sales = revenue,
    Channels =
    [
        new MediaChannel { Name = "ТВ", Spend = tvSpend },
        new MediaChannel { Name = "Digital", Spend = digitalSpend },
    ],
    SeasonalPeriod = 52,
    MarginRate = 0.4,
});

BudgetAllocationResult allocation = BudgetOptimizer.Allocate(model);

Console.WriteLine($"Бюджет {allocation.TotalBudget:N0} даёт " +
                  $"{allocation.ResponseGain:N0} дополнительных продаж " +
                  $"({allocation.ResponseGainRate:P1}) без роста затрат");

foreach (ChannelBudget row in allocation.Channels)
{
    Console.WriteLine($"{row.Name,-10} {row.CurrentSpend,12:N0} -> {row.OptimalSpend,12:N0} " +
                      $"({row.Change,7:P1}), предельная отдача {row.MarginalReturnAtOptimum:F3}");
}

Console.WriteLine(allocation.Interpret().ToLlmText());
```

## Ограничения

- Оптимизация опирается на кривые насыщения из маркетинг-микс модели. Их форма
  за пределами исторического диапазона затрат не проверена, и рекомендация
  удвоить канал экстраполирует модель туда, где данных не было.
- Предложение почти обнулить канал выходит за диапазон наблюдений особенно
  далеко. Сокращайте бюджет постепенно и следите за фактическим откликом.
- Не учитываются минимальные бюджеты входа в канал, контрактные обязательства
  и время на перестройку закупки.
- Расчёт даёт установившийся режим. Переход к новому распределению занимает
  несколько периодов, в течение которых отклик отличается от расчётного.
- Взаимодействие каналов не моделируется: телевидение может усиливать отдачу
  контекстной рекламы, и такой эффект в аддитивной модели теряется.
