# Качество прибыли

Начисления по Слоуну, подтверждение прибыли денежным потоком и расхождение
динамики оборотных статей с выручкой — оценка того, насколько прибыль в отчёте
воспроизводится в следующем году.

## Постановка задачи

Дано: отчётность компании за период и, желательно, за предыдущий.

Требуется: оценить, какая часть прибыли подтверждена деньгами, и не растут ли
оборотные статьи быстрее, чем должны при данном росте бизнеса.

Где встречается: отбор акций, кредитный анализ, проверка прогноза прибыли,
подготовка к сделке, аудиторская оценка рисков искажения.

## Теория

Прибыль состоит из денежной части и начислений — бухгалтерской оценки будущих
поступлений и расходов:

$$
\mathrm{Accruals} \;=\; \frac{\mathrm{NI} - \mathrm{OCF}}{\overline{\mathrm{Assets}}} .
$$

Эффект начислений, описанный Слоуном, устойчив: компании с высокой их долей в
прибыли систематически показывают худшие результаты в следующем году.
Начисления держатся хуже денежной части, поэтому качество прибыли —
самостоятельный фактор, а не техническая деталь учёта.

Отдельно проверяется, подтверждена ли прибыль деньгами:

$$
\frac{\mathrm{OCF}}{\mathrm{NI}},
\qquad
\frac{\mathrm{FCF}}{\mathrm{NI}},
\qquad
\frac{\mathrm{OCF}}{\mathrm{Capex} + \mathrm{Dividends}} .
$$

Последнее отношение отвечает на практический вопрос: хватает ли операционного
потока на поддержание бизнеса и выплаты собственникам, или разрыв финансируется
долгом и сокращением остатков.

При наличии предыдущего периода сравнивается динамика оборотных статей с
динамикой соответствующей базы: дебиторская задолженность — с выручкой,
запасы — с себестоимостью. Устойчивое опережение означает, что рост
показателей отчётности не подкреплён движением денег. Компания продаёт, но не
получает деньги — либо смягчила условия оплаты, либо признаёт выручку раньше
отгрузки.

Показатели сворачиваются в сводную оценку от 0 до 100: каждый нормируется
кусочно-линейно и усредняется. Это удобно для скрининга, но решение всегда
принимается по разбору отдельных показателей, а не по одному числу.

## Сложность

| Ресурс | Оценка | Комментарий |
|--------|--------|-------------|
| Время  | $O(1)$ | шесть показателей |
| Память | $O(1)$ | шесть записей |

## API

| Метод | Описание |
|-------|----------|
| `EarningsQuality.Evaluate(current, previous)` | Показатели качества и сводная оценка |
| `EarningsQualityResult.AccrualRatio` | Доля начислений относительно активов |
| `EarningsQualityResult.CashFlowToNetIncome` | Подтверждение прибыли деньгами |
| `EarningsQualityResult.ReceivablesDivergence` / `InventoryDivergence` | Опережение оборотных статей |
| `EarningsQualityResult.QualityScore` / `Verdict` | Сводная оценка и словесный вывод |

Исходники: `src/AI.Economics/Statements/EarningsQuality.cs`.

## Код

```csharp
using AI.Economics.Statements;

var reported = new FinancialStatement
{
    Company = "Компания", Period = "2024",
    TotalAssets = 1_150_000_000, CurrentAssets = 520_000_000,
    Cash = 80_000_000, AccountsReceivable = 230_000_000, Inventory = 170_000_000,
    PropertyPlantEquipment = 550_000_000, IntangibleAssets = 80_000_000,
    TotalLiabilities = 560_000_000, CurrentLiabilities = 280_000_000,
    AccountsPayable = 160_000_000, ShortTermDebt = 120_000_000, LongTermDebt = 280_000_000,
    Revenue = 1_150_000_000, CostOfGoodsSold = 700_000_000,
    OperatingExpenses = 200_000_000, Depreciation = 52_000_000,
    InterestExpense = 52_000_000, IncomeTax = 29_200_000, NetIncome = 116_800_000,
    OperatingCashFlow = 70_000_000, CapitalExpenditures = 70_000_000,
    DividendsPaid = 23_000_000,
};

FinancialStatement prior = reported with
{
    Period = "2023",
    TotalAssets = 1_000_000_000, AccountsReceivable = 150_000_000, Inventory = 150_000_000,
    Revenue = 1_000_000_000, CostOfGoodsSold = 600_000_000,
    NetIncome = 101_700_000, OperatingCashFlow = 150_000_000,
};

EarningsQualityResult quality = EarningsQuality.Evaluate(reported, prior);

Console.WriteLine($"Сводная оценка {quality.QualityScore:F0} из 100 — {quality.Verdict}");
Console.WriteLine($"Доля начислений {quality.AccrualRatio:P2}");
Console.WriteLine($"Поток к прибыли {quality.CashFlowToNetIncome:F2}, " +
                  $"свободный поток к прибыли {quality.FreeCashFlowConversion:F2}");
Console.WriteLine($"Дебиторка опережает выручку на {quality.ReceivablesDivergence:P1}, " +
                  $"запасы опережают себестоимость на {quality.InventoryDivergence:P1}");
```

Разбор по показателям показывает, какой именно сигнал сработал:

```csharp
foreach (EarningsQualityMetric metric in quality.Metrics)
{
    string verdict = metric.IsFavourable ? "в норме" : "хуже порога";
    Console.WriteLine($"{metric.Name}: {metric.Value:F3} при пороге {metric.Threshold:F2} — {verdict}");
}

Console.WriteLine(quality.Interpret().ToLlmText());
```

Сигнал полезно сверять с [M-score Бениша](beneish.md) на тех же данных:

```csharp
BeneishResult manipulation = BeneishModel.Compute(reported, prior);

Console.WriteLine($"Качество прибыли: {quality.QualityScore:F0}/100");
Console.WriteLine($"M-балл Бениша: {manipulation.MScore:F3} " +
                  $"({(manipulation.IsLikelyManipulator ? "зона риска" : "вне зоны")})");
```

## Ограничения

- Метод оценивает агрегаты отчётности и не отличает агрессивный учёт от
  нормального финансирования роста. Растущая компания законно наращивает
  дебиторскую задолженность и запасы, и модель это увидит как ухудшение.
- Одного периода мало. Начисления нужно смотреть в динамике за три-пять лет:
  устойчиво высокая доля информативнее одного всплеска.
- Без предыдущего периода два из шести показателей не считаются, и сводная
  оценка строится на неполном наборе.
- Отношение потока к прибыли неустойчиво при прибыли, близкой к нулю: знаменатель
  мал, и показатель улетает. В таких случаях смотреть надо на долю начислений
  относительно активов.
- Оценка не заменяет анализ раскрытий. Причина разрыва между прибылью и деньгами
  может быть совершенно законной — например, разовая сделка с длинной отсрочкой.
