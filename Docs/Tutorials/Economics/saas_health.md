# Здоровье SaaS-бизнеса

Четыре метрики, которые невозможно нарисовать одновременно: Rule of 40,
magic number, burn multiple и срок окупаемости привлечения.

## Постановка задачи

Дано: ARR на начало и конец периода, затраты на продажи и маркетинг, чистое
сжигание денег, маржа свободного денежного потока, CAC и ARPA.

Требуется: набор метрик с оценкой каждой относительно принятых в отрасли
порогов.

Где встречается: инвесторский апдейт, внутренний борд, подготовка к раунду,
сравнение с сопоставимыми компаниями.

## Теория

Метрики отвечают на четыре разных вопроса, и в этом их ценность: рост можно
купить бюджетом, но тогда испортятся magic number и burn multiple.

**Rule of 40** — сумма темпа роста и маржи в процентах:

$$
R_{40} \;=\; g \cdot 100 \;+\; m_{FCF} \cdot 100.
$$

Правило разрешает быть убыточным, если растёшь быстро, и наоборот. Ориентир —
не ниже 40.

**Magic number** — сколько нового ARR приносит рубль коммерческих затрат:

$$
MN \;=\; \frac{ARR_{end} - ARR_{start}}{S\&M}.
$$

Ниже 0,5 масштабировать продажи рано: каждый дополнительный рубль в отдел
продаж возвращается медленнее, чем тратится.

**Burn multiple** — сколько денег сожжено на каждый рубль нового ARR:

$$
BM \;=\; \frac{\text{чистое сжигание}}{\Delta ARR}.
$$

Главная метрика эффективности сжигания: она не даёт спрятать плохую экономику
за быстрым ростом. Ниже 1,5 считается хорошим, выше 3 — тревожным.

**CAC payback** считается по валовой марже, а не по выручке:

$$
T \;=\; \frac{CAC}{ARPA \cdot g}.
$$

Расчёт по выручке систематически занижает срок окупаемости на величину
себестоимости обслуживания.

## Сложность

| Ресурс | Оценка | Комментарий |
|--------|--------|-------------|
| Время  | $O(1)$ | Замкнутые формулы |
| Память | $O(1)$ | Набор метрик фиксированного размера |

## API

| Метод | Описание |
|-------|----------|
| `SaasMetrics.Evaluate(input)` | Набор метрик с оценками относительно порогов |
| `SaasMetrics.RuleOf40(growth, margin)` | Сумма роста и маржи в процентах |
| `SaasMetrics.MagicNumber(arrStart, arrEnd, sm)` | Новый ARR на рубль коммерческих затрат |
| `SaasMetrics.BurnMultiple(netBurn, netNewArr)` | Сожжено денег на рубль нового ARR |
| `SaasMetrics.CacPaybackMonths(cac, arpa, margin)` | Окупаемость привлечения по марже |
| `MetricVerdict` | Оценка: `Good`, `Warning`, `Poor` |

Исходник: `src/AI.Economics/Saas/SaasMetrics.cs`.

## Код

```csharp
using AI.Economics.Saas;

var input = new SaasHealthInput
{
    ArrStart = 120_000_000,
    ArrEnd = 204_000_000,
    ArrYearAgo = 120_000_000,
    SalesAndMarketing = 48_000_000,
    NetBurn = 60_000_000,
    FreeCashFlowMargin = -0.35,
    GrossMarginRate = 0.8,
    ArpaMonthly = 60_000,
    Cac = 300_000,
    NetDollarRetention = 1.12,
};

IReadOnlyList<SaasMetric> metrics = SaasMetrics.Evaluate(input);

foreach (SaasMetric metric in metrics)
    Console.WriteLine($"{metric.Name,-22} {metric.Value,10:F2} {metric.Unit,-5} {metric.Verdict}");

int problems = metrics.Count(m => m.Verdict == MetricVerdict.Poor);
Console.WriteLine($"Метрик за пределами нормы: {problems}");
```

Отдельные показатели считаются и без сборки полного отчёта:

```csharp
double burn = SaasMetrics.BurnMultiple(60_000_000, 84_000_000);
double payback = SaasMetrics.CacPaybackMonths(300_000, 60_000, 0.8);
Console.WriteLine($"Burn multiple {burn:F2}, окупаемость {payback:F1} мес.");
```

## Ограничения

- Пороги взяты из практики венчурного рынка для SaaS-компаний и неприменимы
  напрямую к маркетплейсам, аппаратным продуктам и агентскому бизнесу.
- Magic number чувствителен к сезонности: считать его надо на годовом окне
  либо со сдвигом на цикл сделки, иначе квартальные колебания дадут шум.
- Burn multiple неопределён при нулевом или отрицательном приросте ARR — в этом
  случае метрика возвращает бесконечность, и никакая её интерпретация не
  спасает бизнес-модель.
- Rule of 40 складывает величины разной природы. Компания с ростом 100 % и
  маржой минус 60 % и компания с ростом 20 % и маржой плюс 20 % получают
  одинаковую оценку, хотя риски у них совершенно разные.
