# Бэктест со скользящим началом

Единственный честный способ сравнить прогнозные модели: обучить на прошлом,
проверить на будущем, повторить, сдвигая границу — и обязательно включить
в сравнение наивный прогноз.

## Постановка задачи

Дано: исторический ряд и несколько моделей-кандидатов.

Требуется: сравнение по ошибке на данных, которых модели не видели,
и ответ на вопрос, стоит ли вообще внедрять сложную модель.

Где встречается: выбор модели для промышленного прогноза, приёмка
прогнозного сервиса, регулярная переоценка качества.

## Теория

Ошибка на обучающей выборке для выбора модели не годится: модель
с достаточным числом параметров опишет любой ряд идеально и провалится
на первом же новом наблюдении. Скользящее начало воспроизводит рабочий
режим — обучение только на прошлом, проверка на будущем:

```
[----- обучение -----][прогноз]
[------- обучение -------][прогноз]
[--------- обучение ---------][прогноз]
```

**MASE** — основная метрика. В отличие от MAPE она определена при нулевых
значениях ряда, симметрична и сравнима между рядами разного масштаба:

$$
MASE = \frac{\frac{1}{h}\sum_{t}\left|y_t - \hat y_t\right|}
{\frac{1}{n-m}\sum_{t=m+1}^{n}\left|y_t - y_{t-m}\right|}.
$$

Единица имеет прямой смысл: значение 1 означает «точно как наивный прогноз»,
0,7 — «на 30 % точнее». Значение выше единицы — главный и самый неприятный
результат бэктеста: сложная модель не превзошла повтор прошлогоднего значения,
и внедрять её означает оплачивать сопровождение без выигрыша в точности.

**Пинболл-функция потерь** оценивает интервальный прогноз: она штрафует
занижение и завышение асимметрично, в соответствии с обещанным квантилем:

$$
L_\tau(y, q) = \begin{cases}
\tau\,(y - q), & y \ge q,\\
(\tau - 1)(y - q), & y < q.
\end{cases}
$$

Отдельно измеряется **покрытие**: доля фактов, попавших в заявленный интервал.
Расхождение с номинальным уровнем означает, что планирование запаса по таким
интервалам даст не тот уровень сервиса, на который рассчитывали.

Ошибка по шагам горизонта показывает, как быстро падает точность — это прямо
влияет на то, какие решения можно принимать на какой глубине.

## Сложность

| Ресурс | Оценка | Комментарий |
|--------|--------|-------------|
| Время  | $O(F \cdot M \cdot C)$ | $F$ — срезов, $M$ — моделей, $C$ — стоимость обучения |
| Память | $O(F + h)$ | Накопленные метрики |

## API

| Метод | Описание |
|-------|----------|
| `ForecastBacktest.Run(series, models, horizon, folds, minimumTrain, seasonalPeriod)` | Прогон по срезам |
| `BacktestResult.Models` | Итоги по моделям, по возрастанию MASE |
| `BacktestResult.Naive` | Итог наивного прогноза — обязательный ориентир |
| `BacktestSummary.MaeByHorizon` | Как падает точность с удалением горизонта |
| `BacktestSummary.Coverage` | Фактическое покрытие интервалов |
| `ForecastMetrics.Mase` / `SMape` / `PinballLoss` / `Coverage` | Метрики по отдельности |

Исходник: `src/AI.Economics/Forecasting/ForecastBacktest.cs`.

## Код

```csharp
using AI.DataStructs.Algebraic;
using AI.Economics.Forecasting;

var random = new Random(21);
const int months = 150;
var series = new Vector(months);

for (int t = 0; t < months; t++)
{
    series[t] = 1000 + (3.0 * t)
              + (150 * Math.Sin(2 * Math.PI * t / 12.0))
              + ((random.NextDouble() - 0.5) * 80);
}

BacktestResult result = ForecastBacktest.Run(
    series,
    [
        ("Сглаживание", (train, h) => ExponentialSmoothing.AutoFit(train, h, 12)),
        ("Theta", (train, h) => ThetaMethod.Fit(train, h, 12)),
        ("ARIMA", (train, h) => Arima.AutoFit(train, h, 12, maxOrder: 1)),
    ],
    horizon: 6,
    folds: 6,
    seasonalPeriod: 12);

foreach (BacktestSummary model in result.Models)
{
    Console.WriteLine($"{model.Model,-14} MASE {model.Mase:F3}  sMAPE {model.SMape:P1}  " +
                      $"покрытие {model.Coverage:P0}  срезов {model.Folds}");
}

Console.WriteLine($"{result.Naive.Model,-14} MASE {result.Naive.Mase:F3}");

BacktestSummary best = result.Models[0];
Console.WriteLine($"Ошибка на первом шаге {best.MaeByHorizon[0]:F1}, " +
                  $"на шестом {best.MaeByHorizon[5]:F1}");

Console.WriteLine(result.Interpret().ToLlmText());
```

## Ограничения

- Результат привязан к конкретному участку истории. Модель, победившая
  на данных прошлого года, необязательно победит в следующем — перепроверяйте
  выбор регулярно.
- Малое число срезов делает сравнение случайным: при трёх-четырёх срезах
  разница в MASE между моделями часто лежит внутри шума.
- Срезы пересекаются по обучающей выборке, поэтому их ошибки коррелированы.
  Формальные критерии значимости различия моделей к ним неприменимы напрямую.
- Модель, не сумевшая обучиться на срезе, этот срез пропускает. Сравнивайте
  число срезов у разных моделей: разное число делает MASE несопоставимыми.
- Бэктест не воспроизводит одну важную деталь рабочего режима: в проде часть
  внешних регрессоров на горизонте прогноза неизвестна, а здесь они известны
  точно.
