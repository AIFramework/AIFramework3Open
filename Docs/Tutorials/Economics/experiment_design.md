# Планирование эксперимента: размер выборки и MDE

Сколько наблюдений нужно, чтобы обнаружить заданный эффект, и — что важнее —
какой эффект вообще способен обнаружить эксперимент на доступном трафике.

## Постановка задачи

Дано: базовая конверсия, желаемый уровень значимости и мощность, число
вариантов и суточный трафик.

Требуется: размер выборки на вариант, длительность эксперимента и минимальный
обнаруживаемый эффект.

Где встречается: подготовка любого A/B-теста, спор о том, стоит ли его вообще
запускать, планирование очереди экспериментов.

## Теория

Для сравнения двух долей требуемый размер группы:

$$
n = \frac{\left(z_{1-\alpha/2} + z_{1-\beta}\right)^2 \left[p_1(1-p_1) + p_2(1-p_2)\right]}{(p_2 - p_1)^2},
$$

где $p_2 = p_1(1+\text{MDE})$. Для сравнения средних числитель заменяется
на $2\sigma^2$.

Квадрат в знаменателе — главное практическое следствие: чтобы обнаружить вдвое
меньший эффект, нужна вчетверо большая выборка. Отсюда типичная ситуация,
ради которой расчёт и делается: эксперимент на доступном трафике способен
обнаружить только эффект в 15 %, а обсуждаемое изменение даёт от силы 2 %.
Такой эксперимент бессмысленно запускать — его отрицательный результат
ничего не докажет.

Обратная задача — минимальный обнаруживаемый эффект при заданной выборке.
Абсолютный эффект входит и в числитель, и в дисперсию, поэтому решение ищется
простой итерацией; двух-трёх шагов достаточно.

При числе вариантов больше двух уровень значимости ужесточается поправкой
Бонферрони до $\alpha/(k-1)$, что увеличивает требуемую выборку.

Расчёт предполагает **фиксированный горизонт**. Подглядывание в промежуточные
результаты с остановкой при достижении значимости повышает ошибку первого рода
с 5 % до 20–30 %: половина «побед» в таких экспериментах — артефакт правила
остановки. Для законного подглядывания нужен
[последовательный критерий](sequential_testing.md).

## Сложность

| Ресурс | Оценка | Комментарий |
|--------|--------|-------------|
| Время  | $O(1)$ | Замкнутые формулы; MDE — восемь итераций |
| Память | $O(1)$ | Скалярный результат |

## API

| Метод | Описание |
|-------|----------|
| `ExperimentDesign.ForProportions(baseline, effect, alpha, power, variants, traffic)` | Выборка для долей |
| `ExperimentDesign.ForMeans(mean, sd, effect, alpha, power, variants, traffic)` | Выборка для средних |
| `ExperimentDesign.MinimumDetectableEffect(baseline, perVariant, alpha, power)` | Обратная задача |
| `SampleSizeResult.DaysRequired` | Длительность при заданном трафике |
| `SampleSizeResult.AdjustedAlpha` | Уровень значимости с поправкой на множественность |

Исходник: `src/AI.Economics/Experiments/ExperimentDesign.cs`.

## Код

```csharp
using AI.Economics.Experiments;

SampleSizeResult plan = ExperimentDesign.ForProportions(
    baselineRate: 0.05,
    relativeEffect: 0.10,
    alpha: 0.05,
    power: 0.8,
    variants: 2,
    dailyTraffic: 2000);

Console.WriteLine($"Нужно {plan.PerVariant:N0} наблюдений на вариант, " +
                  $"всего {plan.Total:N0}, это {plan.DaysRequired:F1} суток");

// Обратный вопрос: что вообще можно обнаружить за две недели
foreach (int weeks in new[] { 1, 2, 4, 8 })
{
    int perVariant = 2000 * weeks * 7 / 2;
    double mde = ExperimentDesign.MinimumDetectableEffect(0.05, perVariant);
    Console.WriteLine($"{weeks} нед.: {perVariant:N0} на вариант, обнаружим эффект от {mde:P1}");
}

Console.WriteLine(plan.Interpret().ToLlmText());
```

## Ограничения

- Формула предполагает независимость наблюдений. При рандомизации по
  пользователям и метрике на уровне сессий это нарушено, и фактическая
  дисперсия выше расчётной — нужна кластерная поправка.
- Расчёт справедлив только при фиксированном горизонте и заранее выбранной
  метрике. Смена метрики по ходу эксперимента обнуляет заявленные вероятности
  ошибок.
- Срок меньше недели не усредняет недельную сезонность: результат окажется
  смещён теми днями недели, которые попали в эксперимент.
- Срок свыше месяца создаёт другую проблему: меняется состав аудитории и
  внешние условия, и рандомизация перестаёт защищать от смещения.
- Нормальное приближение для долей работает плохо при очень малых конверсиях:
  при $np < 10$ используйте точные методы.
