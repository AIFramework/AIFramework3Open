# Закон Бенфорда для транзакций

Проверка массивов сумм на соответствие распределению первых значащих цифр —
фильтр для отбора транзакций на ручную проверку.

## Постановка задачи

Дано: массив числовых величин — суммы платежей, остатки по счетам, объёмы
поставок, начисления.

Требуется: проверить, соответствует ли распределение первых цифр закону
Бенфорда, и указать конкретные цифровые группы, по которым отклонение значимо.

Где встречается: внутренний контроль, аудиторские процедуры, выявление
дробления платежей под порог согласования, проверка первичных данных перед
построением моделей.

## Теория

В наборах чисел, охватывающих несколько порядков и возникающих как
произведение многих факторов, первая значащая цифра распределена неравномерно:

$$
P(d) = \log_{10}\Bigl(1 + \frac{1}{d}\Bigr),\; d = 1..9,
\qquad
P(dd) = \log_{10}\Bigl(1 + \frac{1}{dd}\Bigr),\; dd = 10..99 .
$$

Единица встречается в 30,1% случаев, девятка — в 4,6%. Человек, придумывающий
суммы, распределяет первые цифры почти равномерно, поэтому отклонение от закона
служит фильтром для отбора транзакций на проверку.

Соответствие оценивается тремя способами:

- **Хи-квадрат** — формальный критерий согласия. На больших выборках он
  отвергает согласие даже при экономически незначимых отклонениях.
- **Среднее абсолютное отклонение долей** не зависит от объёма выборки и потому
  используется в аудиторской практике. Пороги Нигрини для первой цифры: до
  0,006 — близкое соответствие, до 0,012 — приемлемое, до 0,015 — пограничное,
  выше — несоответствие.
- **Z-статистика по каждой цифровой группе** с поправкой на непрерывность:

$$
Z_d = \frac{|\hat p_d - p_d| - \frac{1}{2n}}{\sqrt{p_d(1-p_d)/n}} .
$$

Именно она и указывает, какие суммы проверять: группа с максимальной
Z-статистикой — точка входа в ручную проверку.

Анализ по первым двум цифрам чувствительнее и лучше ловит дробление платежей
под порог согласования, но требует заметно большей выборки: девяносто групп
против девяти.

## Сложность

| Ресурс | Оценка | Комментарий |
|--------|--------|-------------|
| Время  | $O(n + k)$ | один проход по значениям, $k$ цифровых групп |
| Память | $O(k)$ | частоты по группам |

## API

| Метод | Описание |
|-------|----------|
| `BenfordAnalysis.Analyze(values, scope, dataset)` | Частоты, критерии согласия и подозрительные группы |
| `BenfordAnalysis.LeadingDigits(value, scope)` | Первая цифра или первые две, независимо от масштаба |
| `BenfordResult.MeanAbsoluteDeviation` / `Conformity` | Отклонение долей и словесная оценка |
| `BenfordResult.ChiSquare` / `PValue` | Формальный критерий согласия |
| `BenfordResult.Suspicious` | Группы со значимым отклонением, по убыванию Z |

Исходники: `src/AI.Economics/Statements/BenfordAnalysis.cs`.

## Код

```csharp
using AI.Economics.Statements;

var natural = new List<double>();
var fabricated = new List<double>();
var benfordRng = new Random(31);

for (int i = 0; i < 4_000; i++)
{
    // Естественные платежи охватывают несколько порядков
    double normal = benfordRng.NextDouble() + 1e-9;
    double lognormal = Math.Exp(Math.Log(100_000) + (2.5 * (Math.Log(normal) + 0.5)));
    natural.Add(lognormal);

    // Придуманные суммы: первые цифры распределены почти равномерно
    fabricated.Add(Math.Round((benfordRng.NextDouble() * 900_000) + 100_000));
}

BenfordResult clean = BenfordAnalysis.Analyze(natural, BenfordScope.FirstDigit, "платежи поставщикам");
BenfordResult suspect = BenfordAnalysis.Analyze(fabricated, BenfordScope.FirstDigit, "подобранные суммы");

Console.WriteLine($"Естественные: MAD {clean.MeanAbsoluteDeviation:F5} — {clean.Conformity}");
Console.WriteLine($"Придуманные:  MAD {suspect.MeanAbsoluteDeviation:F5} — {suspect.Conformity}");
Console.WriteLine($"Хи-квадрат придуманных: {suspect.ChiSquare:F1}, p = {suspect.PValue:F5}");
```

Разбор по цифрам указывает, где искать:

```csharp
foreach (BenfordDigit digit in suspect.Digits)
{
    Console.WriteLine($"Цифра {digit.Digit}: наблюдалось {digit.ObservedShare:P2}, " +
                      $"ожидалось {digit.ExpectedShare:P2}, Z = {digit.ZScore:F2}");
}

foreach (BenfordDigit digit in suspect.Suspicious.Take(3))
    Console.WriteLine($"Проверить группу {digit.Digit}: отклонение {digit.AbsoluteDeviation:P2}");
```

Разрез по первым двум цифрам чувствительнее к дроблению под порог:

```csharp
BenfordResult twoDigits = BenfordAnalysis.Analyze(natural, BenfordScope.FirstTwoDigits);

Console.WriteLine($"Групп: {twoDigits.Digits.Count}, значений в анализе: {twoDigits.SampleSize}");
Console.WriteLine($"Первая цифра числа 0,00123: {BenfordAnalysis.LeadingDigits(0.00123, BenfordScope.FirstDigit)}");
Console.WriteLine(twoDigits.Interpret().ToLlmText());
```

## Ограничения

- Тест применим не ко всем данным. Номера счетов, суммы с жёстким верхним
  пределом, тарифы и цены из прайс-листа не подчиняются закону изначально, и
  отклонение по ним ничего не означает.
- Несоответствие закону не доказывает мошенничество. Типичные законные причины:
  округление сумм, лимиты согласования, тарифная сетка, договорные цены.
- Объём выборки критичен. Для первой цифры 300 значений — минимум, для первых
  двух цифр этого заведомо мало: тест теряет мощность.
- На больших выборках хи-квадрат отвергает согласие практически всегда.
  Опираться нужно на среднее абсолютное отклонение и на Z-статистики групп.
- На уровне всей компании локальное искажение растворяется в объёме. Прогонять
  тест нужно отдельно по подразделениям, подотчётным лицам и контрагентам.
