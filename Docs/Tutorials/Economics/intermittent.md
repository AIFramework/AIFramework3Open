# Прогнозирование прерывистого спроса

Запчасти, B2B-заказы и длинный хвост ассортимента: ряды, где продажи
случаются раз в несколько периодов и классические методы ломаются.

## Постановка задачи

Дано: ряд спроса с большинством нулевых периодов.

Требуется: оценка среднего спроса за период и точка перезаказа, обеспечивающая
заданный уровень сервиса.

Где встречается: управление запасами запчастей, дистрибуция редких позиций,
B2B-продажи с длинным циклом сделки.

## Теория

На таких рядах экспоненциальное сглаживание усредняет нули с продажами и
выдаёт дробный спрос каждый период, а процентные метрики ошибки не определены
на нулях.

**Кростон** разделяет задачу: отдельно сглаживается размер спроса в тех
периодах, когда он был, и отдельно интервал между такими периодами. Прогноз —
их отношение:

$$
\hat y_t = \frac{z_t}{x_t},
$$

где $z_t$ — сглаженный размер, $x_t$ — сглаженный интервал. Обновление
происходит только в периоды со спросом.

**Синтетос и Бойлан** заметили, что отношение сглаженных величин смещено
вверх — отношение средних не равно среднему отношений. Поправка:

$$
\hat y_t = \left(1 - \frac{\beta}{2}\right)\frac{z_t}{x_t}.
$$

**TSB** вместо интервала сглаживает вероятность спроса и обновляет её
**каждый** период, в том числе нулевой:

$$
p_t = \beta\,\mathbb{1}[y_t > 0] + (1-\beta)p_{t-1}, \qquad \hat y_t = p_t z_t.
$$

Отсюда единственное практически важное свойство: TSB реагирует на то, что
позиция перестала продаваться. Кростон в такой ситуации держит старый прогноз
бесконечно.

Классификация ряда по Синтетосу — Бойлану — Кроустону разделяет случаи по
среднему интервалу $p$ и вариации размера $CV^2$:

| | $CV^2 < 0{,}49$ | $CV^2 \ge 0{,}49$ |
|---|---|---|
| $p < 1{,}32$ | гладкий | неравномерный |
| $p \ge 1{,}32$ | прерывистый | комковатый |

Для управления запасом важнее прогноза точка перезаказа: спрос за срок
поставки плюс страховой запас. Дисперсия спроса за срок поставки складывается
из вариации размера заказа и случайности самого факта заказа:

$$
\sigma^2_{L} = L\left[p\,\sigma^2_z + p(1-p)\,\bar z^2\right].
$$

## Сложность

| Ресурс | Оценка | Комментарий |
|--------|--------|-------------|
| Время  | $O(n)$ | Один проход по ряду |
| Память | $O(n)$ | Модельные значения |

## API

| Метод | Описание |
|-------|----------|
| `IntermittentDemand.Fit(series, method, horizon, alpha, beta, leadTime, serviceLevel)` | Прогноз и параметры запаса |
| `IntermittentDemand.CompareAll(series, horizon, alpha, leadTime, serviceLevel)` | Три метода, по возрастанию ошибки |
| `IntermittentForecast.DemandPattern` | Классификация ряда |
| `IntermittentForecast.RecommendedMethod` | Уместный метод для этого типа ряда |
| `IntermittentForecast.ReorderPoint` | Спрос за срок поставки плюс страховой запас |
| `IntermittentForecast.SafetyStock` | Запас под заданный уровень сервиса |

Исходник: `src/AI.Economics/Forecasting/IntermittentDemand.cs`.

## Код

```csharp
using AI.DataStructs.Algebraic;
using AI.Economics.Forecasting;

var random = new Random(3);
const int periods = 120;
var demand = new Vector(periods);

for (int t = 0; t < periods; t++)
    demand[t] = random.NextDouble() < 0.25 ? Math.Round(12 * (0.5 + random.NextDouble())) : 0;

IntermittentForecast forecast = IntermittentDemand.Fit(
    demand,
    IntermittentMethod.SyntetosBoylan,
    horizon: 12,
    alpha: 0.1,
    leadTime: 4,
    serviceLevel: 0.95);

Console.WriteLine($"Тип ряда: {forecast.DemandPattern}");
Console.WriteLine($"Нулевых периодов: {forecast.ZeroShare:P0}");
Console.WriteLine($"Средний интервал: {forecast.AverageInterval:F1}, " +
                  $"средний заказ: {forecast.AverageDemandSize:F1}");
Console.WriteLine($"Спрос за период: {forecast.DemandPerPeriod:F2}");
Console.WriteLine($"Точка перезаказа: {forecast.ReorderPoint:F1} " +
                  $"(страховой запас {forecast.SafetyStock:F1})");

foreach (IntermittentForecast candidate in IntermittentDemand.CompareAll(demand))
{
    Console.WriteLine($"{candidate.Method,-24} прогноз {candidate.DemandPerPeriod:F3}, " +
                      $"MASE {candidate.InSampleMase:F3}");
}

Console.WriteLine(forecast.Interpret().ToLlmText());
```

## Ограничения

- Прогноз даёт средний спрос за период, а не момент следующего заказа.
  Планировать по нему производство отдельной позиции нельзя — только запас
  через точку перезаказа либо агрегированный спрос по группе позиций.
- Процентные метрики ошибки на таких рядах не определены. Оценивайте методы
  по уровню сервиса и издержкам хранения, а не по MAPE.
- Формула страхового запаса предполагает независимость размеров заказов
  и постоянную вероятность спроса. Крупный контрактный заказ нарушает оба
  допущения.
- Параметры сглаживания заданы вручную. Их автоподбор на прерывистых рядах
  неустойчив: правдоподобие почти плоское.
- Кростон и его поправка не реагируют на прекращение продаж. Если позиция
  выводится из ассортимента, нужен TSB или явное правило снятия с прогноза.
