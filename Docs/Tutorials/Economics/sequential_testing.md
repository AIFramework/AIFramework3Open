# Последовательные критерии и байесовское сравнение

Как останавливать эксперимент в любой момент, не раздувая вероятность ложного
срабатывания, и как отвечать на вопрос бизнеса «какова вероятность, что
вариант B лучше».

## Постановка задачи

Дано: два потока наблюдений — контрольная группа и группа воздействия,
поступающие в реальном времени.

Требуется: критерий, на который можно смотреть в любой момент, и правило
остановки, сохраняющее заявленную вероятность ошибки.

Где встречается: онлайн-эксперименты с непрерывным потоком трафика, любые
тесты, за которыми наблюдают ежедневно.

## Теория

Проблема, которую решают последовательные критерии: при фиксированном
горизонте подглядывание с остановкой при достижении значимости повышает
ошибку первого рода с 5 % до 20–30 %. Половина «побед» в таких экспериментах —
артефакт правила остановки, а не эффект.

**Смешанное отношение правдоподобий (mSPRT)** строит статистику, уровень
ошибки которой контролируется одновременно на всех моментах остановки.
Эффект под альтернативой не фиксируется, а интегрируется по нормальному
априорному распределению с параметром $\tau$:

$$
\Lambda_n = \sqrt{\frac{\sigma^2}{\sigma^2 + n\tau^2}}\,
\exp\!\left(\frac{n^2\tau^2\hat\Delta_n^2}{2\sigma^2(\sigma^2 + n\tau^2)}\right),
\qquad
p_n = \min\left(1,\ \min_{k \le n} \Lambda_k^{-1}\right).
$$

Величина $p_n$ называется всегда допустимым p-значением: она невозрастающая
по построению, и правило «остановиться, когда $p_n \le \alpha$» сохраняет
заявленный уровень ошибки при любой траектории наблюдений.

Параметр $\tau$ задаёт масштаб эффектов, на которые критерий настроен: чем он
больше, тем чувствительнее к крупным эффектам и слабее к мелким. Разумное
значение — эффект, который имеет смысл обнаруживать.

**Байесовский подход** отвечает на другой вопрос. При равномерном априорном
распределении апостериорное для конверсии — бета-распределение, и прямо
считаются вероятность превосходства и ожидаемые потери от ошибки:

$$
P(\theta_B > \theta_A), \qquad
L_B = \mathbb{E}\left[\max(\theta_A - \theta_B,\ 0)\right].
$$

Ожидаемые потери — величина в единицах метрики: «выбрав B, в среднем потеряем
столько-то конверсии на посетителя». Именно она, а не вероятность, должна
быть порогом решения: правило «остановиться при вероятности выше 95 %»
завышает ошибку так же, как и частотное подглядывание.

## Сложность

| Ресурс | Оценка | Комментарий |
|--------|--------|-------------|
| mSPRT | $O(n)$ | Один проход, обновление сумм |
| Байесовский | $O(D)$ | $D$ — выборок из апостериорного распределения |
| Память | $O(n)$ | Траектории p-значения и эффекта |

## API

| Метод | Описание |
|-------|----------|
| `SequentialTest.Run(control, treatment, tau, alpha)` | Всегда допустимое p-значение по шагам |
| `SequentialTestResult.StoppingPoint` | Момент, когда можно было остановиться |
| `SequentialTestResult.ObservationsSaved` | Доля сэкономленного трафика |
| `SequentialTestResult.LowerBound` / `UpperBound` | Доверительная последовательность |
| `SequentialTest.Bayesian(successesA, trialsA, successesB, trialsB, ...)` | Байесовское сравнение |
| `BayesianAbResult.ExpectedLossChoosingB` | Ожидаемая цена ошибки при выборе B |

Исходник: `src/AI.Economics/Experiments/SequentialTest.cs`.

## Код

```csharp
using AI.DataStructs.Algebraic;
using AI.Economics.Experiments;

var random = new Random(77);
const int total = 4000;

var control = new Vector(total);
var treatment = new Vector(total);
int successesControl = 0, successesTreatment = 0;

for (int i = 0; i < total; i++)
{
    bool a = random.NextDouble() < 0.10;
    bool b = random.NextDouble() < 0.13;

    control[i] = a ? 1 : 0;
    treatment[i] = b ? 1 : 0;
    if (a) successesControl++;
    if (b) successesTreatment++;
}

SequentialTestResult sequential = SequentialTest.Run(control, treatment, tau: 0.05, alpha: 0.05);

Console.WriteLine($"Всегда допустимое p: {sequential.FinalPValue:F4}");
Console.WriteLine($"Обычный критерий дал бы: {sequential.FixedHorizonPValue:F4}");
Console.WriteLine(sequential.StoppingPoint > 0
    ? $"Остановка на {sequential.StoppingPoint} наблюдении, сэкономлено {sequential.ObservationsSaved:P0}"
    : "Различие не обнаружено");

BayesianAbResult bayesian = SequentialTest.Bayesian(
    successesControl, total, successesTreatment, total, lossThreshold: 0.001);

Console.WriteLine($"P(B лучше A) = {bayesian.ProbabilityBetter:P1}");
Console.WriteLine($"Ожидаемые потери от B: {bayesian.ExpectedLossChoosingB:F5}");
Console.WriteLine($"Интервал разности: [{bayesian.CredibleLow:P2}; {bayesian.CredibleHigh:P2}]");
Console.WriteLine(bayesian.Interpret().ToLlmText());
```

## Ограничения

- Последовательный критерий консервативнее обычного: он платит мощностью
  за право смотреть на данные в любой момент. На одних и тех же данных
  фиксированный горизонт может дать значимость, а последовательный — нет.
- Порядок наблюдений имеет значение. Данные должны поступать в том порядке,
  в котором собирались, иначе точка остановки не имеет смысла.
- Критерий построен на нормальном приближении: на выборках меньше двух сотен
  наблюдений в группе он работает грубо.
- Байесовский подход не защищает от подглядывания сам по себе. Порогом должны
  быть ожидаемые потери, а не вероятность превосходства.
- На малых выборках байесовский результат заметно зависит от априорного
  распределения; использовано равномерное.
- Правило остановки надо зафиксировать до запуска: критерий защищает
  от подглядывания, но не от смены метрики по ходу дела.
