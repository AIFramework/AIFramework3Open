# Экономика каналов привлечения

Разбор привлечения по каналам: где смешанный показатель CAC прячет убыточный
трафик и как это увидеть до того, как бюджет будет потрачен.

## Постановка задачи

Дано: несколько каналов привлечения, каждый со своими затратами, числом
приведённых клиентов, средним чеком и качеством трафика (оттоком).

Требуется: юнит-экономика каждого канала, смешанный и платный CAC, вклад
каждого канала в общий результат.

Где встречается: ежемесячное распределение маркетингового бюджета, решение об
отключении канала, спор с подрядчиком о качестве трафика.

## Постановка вопроса о смешанном показателе

Смешанный CAC считается как все затраты, делённые на всех клиентов, включая
пришедших бесплатно:

$$
CAC_{blended} \;=\; \frac{\sum_i S_i}{\sum_i N_i},
\qquad
CAC_{paid} \;=\; \frac{\sum_{i:\,S_i>0} S_i}{\sum_{i:\,S_i>0} N_i}.
$$

Разница между ними — вклад органики. Чем её больше, тем сильнее смешанный
показатель занижает реальную стоимость привлечения и тем легче под ним
спрятать канал с $LTV/CAC < 1$.

## Теория

Для каждого канала считается собственная юнит-экономика:

$$
LTV_i \;=\; m_i \sum_{t \ge 0} \frac{(1-c_i)^t}{(1+d)^t},
\qquad
CAC_i \;=\; \frac{S_i}{N_i}.
$$

Итог канала — суммарный маржинальный вклад всех его клиентов за вычетом
затрат:

$$
\Pi_i \;=\; N_i \cdot LTV_i - S_i.
$$

Именно $\Pi_i$, а не отношение $LTV/CAC$, отвечает на вопрос «сколько денег
приносит канал»: канал с отличным отношением, но десятком клиентов в месяц,
не масштабируется.

## Сложность

| Ресурс | Оценка | Комментарий |
|--------|--------|-------------|
| Время  | $O(k \cdot H)$ | $k$ — число каналов, $H$ — горизонт |
| Память | $O(k \cdot H)$ | Кривые по каждому каналу |

## API

| Метод | Описание |
|-------|----------|
| `ChannelEconomics.Analyze(channels)` | Считает экономику каждого канала и сводку микса |
| `ChannelMixResult.BlendedCac` | Все затраты на всех клиентов, включая органику |
| `ChannelMixResult.PaidCac` | Затраты платных каналов на их же клиентов |
| `ChannelMixResult.LtvToPaidCac` | Отношение, пригодное для решений о бюджете |
| `ChannelResult.TotalNetContribution` | Итог канала в деньгах, а не в отношениях |

Исходник: `src/AI.Economics/UnitEconomics/ChannelEconomics.cs`.

## Код

```csharp
using AI.Economics.UnitEconomics;

ChannelInput[] channels =
[
    new() { Name = "Органика", Spend = 0, NewCustomers = 120,
            RevenuePerPeriod = 6_000, GrossMarginRate = 0.8, ChurnRate = 0.03, Horizon = 36 },
    new() { Name = "Контекст", Spend = 1_500_000, NewCustomers = 167,
            RevenuePerPeriod = 6_000, GrossMarginRate = 0.8, ChurnRate = 0.04, Horizon = 36 },
    new() { Name = "Партнёрка", Spend = 600_000, NewCustomers = 83,
            RevenuePerPeriod = 4_800, GrossMarginRate = 0.8, ChurnRate = 0.09, Horizon = 36 },
];

ChannelMixResult mix = ChannelEconomics.Analyze(channels);

Console.WriteLine($"Blended CAC   {mix.BlendedCac:N0}");
Console.WriteLine($"Paid CAC      {mix.PaidCac:N0}");
Console.WriteLine($"LTV/Paid CAC  {mix.LtvToPaidCac:F2}");

foreach (ChannelResult channel in mix.Channels)
{
    Console.WriteLine($"{channel.Name,-12} LTV/CAC={channel.Economics.LtvToCac,6:F2}  " +
                      $"итог={channel.TotalNetContribution,12:N0}");
}
```

## Ограничения

- Каналы считаются независимыми: каннибализация между ними и отложенные
  конверсии не моделируются. Для этого нужен маркетинг-микс, а не разложение
  по последнему клику.
- Атрибуция клиента к каналу берётся как данность. Если она сделана по
  последнему клику, брендовый поиск заберёт заслугу у верхних этапов воронки.
- Отток по каналу должен быть измерен по когортам этого канала: подстановка
  среднего оттока обнуляет весь смысл разбора.
- Канал с нулевыми затратами получает бесконечное отношение `LtvToCac` — при
  сортировке он всегда окажется первым, но масштабировать его нельзя.
