# M-score Бениша: детект манипуляций с отчётностью

Восемь индексов, сравнивающих текущий период с предыдущим, и пробит-балл,
отбирающий компании, чья отчётность статистически похожа на отчётность
известных манипуляторов.

## Постановка задачи

Дано: отчётность компании за два последовательных периода.

Требуется: оценка вероятности того, что отчётность приукрашена, с разбором по
конкретным признакам — какая именно статья ведёт себя нетипично.

Где встречается: скрининг эмитентов перед покупкой акций, проверка контрагента
перед крупной отгрузкой, подготовка к аудиту, работа службы внутреннего
контроля.

## Теория

Модель сравнивает восемь показателей текущего периода с прошлогодними и
объединяет их в пробит-балл:

$$
M = -4{,}84 + 0{,}920\,\mathrm{DSRI} + 0{,}528\,\mathrm{GMI} + 0{,}404\,\mathrm{AQI}
+ 0{,}892\,\mathrm{SGI} + 0{,}115\,\mathrm{DEPI}
$$
$$
\qquad - 0{,}172\,\mathrm{SGAI} + 4{,}679\,\mathrm{TATA} - 0{,}327\,\mathrm{LVGI}.
$$

| Индекс | Что сравнивает | Почему растёт у манипуляторов |
|--------|----------------|-------------------------------|
| DSRI | дебиторская задолженность к выручке | выручка признаётся до оплаты |
| GMI | валовая маржа прошлого года к текущей | падение маржи создаёт мотив |
| AQI | доля «мягких» активов | расходы капитализируются вместо списания |
| SGI | рост выручки | быстрый рост даёт и возможность, и давление |
| DEPI | норма амортизации прошлого года к текущей | замедление амортизации завышает прибыль |
| SGAI | коммерческие расходы к выручке | их опережающий рост, наоборот, снижает подозрения |
| TATA | начисления к активам | прибыль опережает денежный поток |
| LVGI | долговая нагрузка | рост долга усиливает давление ковенант |

Каждый индекс — отношение показателя текущего года к прошлогоднему, поэтому
нейтральное значение равно единице. Исключение — TATA: это не отношение, а
доля начислений в активах, и его нейтральный уровень около 0,02.

Наибольший вес имеет именно индекс начислений — разрыв между прибылью и
операционным денежным потоком. Он же чаще всего и срабатывает: прибыль можно
нарисовать, деньги — нет.

Порог отнесения к манипуляторам равен $-1{,}78$. При нём модель ловит около
76% манипуляторов ценой примерно 17,5% ложных срабатываний на здоровых
компаниях. Это не доказательство манипуляции, а фильтр для отбора компаний на
углублённую проверку.

## Сложность

| Ресурс | Оценка | Комментарий |
|--------|--------|-------------|
| Время  | $O(1)$ | восемь отношений и взвешенная сумма |
| Память | $O(1)$ | девять слагаемых с константой |

## API

| Метод | Описание |
|-------|----------|
| `BeneishModel.Compute(current, previous)` | Балл, вероятность и разбор индексов |
| `BeneishResult.MScore` / `Threshold` | Балл и порог отнесения к манипуляторам |
| `BeneishResult.Probability` | Вероятность по пробит-шкале модели |
| `BeneishIndex.IsFlagged` / `Deviation` | Настораживает ли индекс и насколько |
| `BeneishIndex.Contribution` | Вклад индекса в итоговый балл |

Исходники: `src/AI.Economics/Statements/BeneishModel.cs`.

```csharp
var thisYear = new FinancialStatement

    PropertyPlantEquipment = 550_000_000, IntangibleAssets = 80_000_000,
    TotalLiabilities = 560_000_000, CurrentLiabilities = 280_000_000,
    AccountsPayable = 160_000_000, ShortTermDebt = 120_000_000, LongTermDebt = 280_000_000,
    RetainedEarnings = 350_000_000,
    Revenue = 1_150_000_000, CostOfGoodsSold = 700_000_000,
    OperatingExpenses = 200_000_000, Depreciation = 52_000_000,
    InterestExpense = 52_000_000, IncomeTax = 29_200_000, NetIncome = 116_800_000,
    OperatingCashFlow = 60_000_000, CapitalExpenditures = 70_000_000,
};

FinancialStatement lastYear = thisYear with
{
    Period = "2023",
    TotalAssets = 1_000_000_000, CurrentAssets = 450_000_000,
    AccountsReceivable = 150_000_000, Inventory = 150_000_000,
    PropertyPlantEquipment = 500_000_000, IntangibleAssets = 50_000_000,
    TotalLiabilities = 480_000_000, CurrentLiabilities = 240_000_000,
    Revenue = 1_000_000_000, CostOfGoodsSold = 590_000_000,
    OperatingExpenses = 180_000_000, Depreciation = 50_000_000,
    InterestExpense = 42_900_000, IncomeTax = 27_400_000, NetIncome = 109_700_000,
    OperatingCashFlow = 155_000_000,
};

BeneishResult beneish = BeneishModel.Compute(thisYear, lastYear);

Console.WriteLine($"M-балл {beneish.MScore:F3} при пороге {beneish.Threshold:F2}");
Console.WriteLine($"Вероятность манипуляции {beneish.Probability:P2}");
Console.WriteLine(beneish.IsLikelyManipulator ? "Зона вероятной манипуляции" : "Вне зоны риска");
```

## Ограничения

- Модель откалибрована на публичных компаниях США и даёт заметную долю ложных
  срабатываний. Быстро растущие компании выглядят манипуляторами из-за
  опережающего роста дебиторской задолженности и начислений — это нормальное
  финансирование роста, а не искажение.
- Восемь индексов требуют сопоставимых периодов. Слияние, продажа сегмента или
  смена учётной политики делают отношения бессмысленными.
- Модель работает с агрегатами отчётности и не видит искажений на уровне
  отдельных проводок — для этого нужен [закон Бенфорда](benford.md).
- Балл ниже порога не означает достоверности отчётности: модель ловит один
  конкретный тип манипуляций — завышение выручки и прибыли.
- Результат — основание для проверки, а не вывод. Проверять нужно признание
  выручки, движение дебиторской задолженности и капитализацию расходов.
