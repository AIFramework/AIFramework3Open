# Conjoint-анализ

Разложение выбора покупателя на вклад отдельных свойств товара: что именно
он покупает, сколько готов доплатить за каждое свойство и как изменится доля
рынка при изменении конфигурации.

## Постановка задачи

Дано: задания на выбор, в каждом из которых респонденту предъявлено несколько
карточек товара с разными сочетаниями свойств, и известно, какую он выбрал.

Требуется: частные полезности уровней атрибутов, их относительная важность,
готовность платить в деньгах и симулятор долей.

Где встречается: определение состава тарифных планов, выбор комплектации,
оценка ценности бренда, планирование продуктовой линейки.

## Теория

Полезность карточки складывается из вкладов её уровней, а выбор описывается
логит-моделью:

$$
U_j = \beta^{\mathsf T} x_j + \varepsilon_j, \qquad
P(j) = \frac{e^{\beta^{\mathsf T} x_j}}{\sum_k e^{\beta^{\mathsf T} x_k}}.
$$

Категориальные атрибуты кодируются индикаторами с базовым уровнем: для
атрибута с тремя уровнями создаются два столбца, полезность первого принимается
за ноль. Без базового уровня матрица плана вырождена.

Цену удобно задавать числовым атрибутом — тогда её коэффициент имеет
размерность полезности на рубль, и любая частная полезность пересчитывается
в деньги:

$$
WTP_{\text{уровня}} = -\frac{\beta_{\text{уровня}}}{\beta_{\text{цена}}}.
$$

Важность атрибута — размах его полезностей, нормированный на сумму размахов
по всем атрибутам.

**Агрегатная модель** оценивается методом Ньютона: логарифм правдоподобия
вогнут, градиент и гессиан выписываются явно, сходимость занимает несколько
итераций. Её слабость в том, что она приписывает всем респондентам одинаковые
предпочтения. На неоднородной аудитории это не просто теряет информацию —
оно смещает симуляцию долей: половина, которой важна цена, и половина,
которой важен бренд, в среднем выглядят как аудитория, которой не важно ничего.

**Иерархическая байесовская модель** оценивает индивидуальные полезности:
$\beta_i \sim N(\mu, \mathrm{diag}(\sigma^2))$, выбор внутри респондента
описывается логитом. Оценка — выборка Гиббса с шагом Метрополиса для каждого
$\beta_i$ и сопряжёнными обновлениями $\mu$ и дисперсий. Симулятор долей в
этом случае усредняет доли по респондентам, а не считает их от среднего —
на неоднородной аудитории это разные числа.

## Сложность

| Ресурс | Оценка | Комментарий |
|--------|--------|-------------|
| Агрегатная модель | $O(I \cdot T J k^2)$ | $T$ — заданий, $J$ — альтернатив, $k$ — параметров |
| Иерархическая | $O(D \cdot m \cdot T_i J k)$ | $D$ — выборок, $m$ — респондентов |
| Память | $O(T J k + m k)$ | План и индивидуальные полезности |

## API

| Метод | Описание |
|-------|----------|
| `ConjointDesign(attributes)` | План исследования и правило кодирования |
| `MultinomialLogit.Fit(tasks, design)` | Агрегатная оценка методом Ньютона |
| `MultinomialLogit.SimulateShares(profiles)` | Предсказанные доли выбора |
| `HierarchicalBayesConjoint.Fit(tasks, design, draws, burnIn, seed)` | Индивидуальные полезности |
| `HierarchicalBayesConjoint.AcceptanceRate` | Доля принятых шагов — диагностика сходимости |
| `ConjointResult.AttributeImportance` | Относительная важность атрибутов |
| `PartWorth.WillingnessToPay` | Готовность доплатить за уровень, в деньгах |

Исходники: `src/AI.Economics/Pricing/`.

## Код

```csharp
using AI.DataStructs.Algebraic;
using AI.Economics.Pricing;

var design = new ConjointDesign(
[
    new ConjointAttribute("Бренд", ["Базовый", "Известный"]),
    new ConjointAttribute("Поддержка", ["Почта", "Чат", "Менеджер"]),
    new ConjointAttribute("Цена", ["1000", "2000", "3000"], [1000, 2000, 3000]),
]);

var random = new Random(42);
var tasks = new List<ChoiceTask>();

for (int respondent = 0; respondent < 150; respondent++)
{
    for (int task = 0; task < 10; task++)
    {
        var alternatives = new List<ConjointProfile>
        {
            new([random.Next(2), random.Next(3), random.Next(3)]),
            new([random.Next(2), random.Next(3), random.Next(3)]),
            new([random.Next(2), random.Next(3), random.Next(3)]),
        };

        tasks.Add(new ChoiceTask
        {
            Respondent = respondent,
            Alternatives = alternatives,
            ChosenIndex = random.Next(3),
        });
    }
}

var model = new MultinomialLogit();
ConjointResult result = model.Fit(tasks, design);

foreach (PartWorth worth in result.PartWorths)
{
    Console.WriteLine($"{worth.Name,-28} полезность {worth.Utility,7:F3} " +
                      $"WTP {worth.WillingnessToPay,10:N0}");
}

foreach ((string attribute, double importance) in result.AttributeImportance)
    Console.WriteLine($"Важность «{attribute}»: {importance:P0}");

Vector shares = model.SimulateShares(
[
    new ConjointProfile([1, 2, 0]),
    new ConjointProfile([0, 0, 2]),
]);

Console.WriteLine($"Доли конфигураций: {shares[0]:P0} и {shares[1]:P0}");
Console.WriteLine(result.Interpret().ToLlmText());
```

## Ограничения

- Метод измеряет заявленный выбор в отсутствие бюджетного ограничения.
  Абсолютные доли завышены; относительные сравнения конфигураций надёжнее.
- Число заданий на респондента ограничено вниманием: свыше 12–15 карточек
  качество ответов падает, и оценки ухудшаются вместе с ним.
- Полный факторный план недостижим уже при четырёх атрибутах. Дробный план
  должен быть сбалансирован, иначе часть столбцов почти коллинеарна и
  полезности оцениваются неустойчиво.
- Ковариационная матрица индивидуальных полезностей взята диагональной:
  полная требует обратного Уишарта и на выборках в двести-триста респондентов
  оценивается неустойчиво. Корреляции между предпочтениями не улавливаются.
- Положительный коэффициент при цене — почти всегда признак ошибки
  в кодировании или слишком узкого ценового диапазона, а не открытия
  товара Веблена.
