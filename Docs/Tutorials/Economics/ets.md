# Экспоненциальное сглаживание

Простое сглаживание, метод Хольта и Хольта — Уинтерса с затухающим трендом:
модель без требования стационарности, хорошо работающая на коротких рядах.

## Постановка задачи

Дано: исторический ряд спроса и предполагаемая длина сезонного цикла.

Требуется: прогноз с интервалами и оценка того, какая конфигурация модели
лучше описывает ряд.

Где встречается: планирование спроса по SKU, прогноз выручки по подразделениям,
любые ряды, где подбор порядка ARIMA был бы гаданием.

## Теория

Модель хранит три состояния — уровень, тренд и сезонность — и обновляет их
с весами, убывающими вглубь истории:

$$
\begin{aligned}
\ell_t &= \alpha (y_t - s_{t-m}) + (1-\alpha)(\ell_{t-1} + \varphi b_{t-1}),\\
b_t &= \beta (\ell_t - \ell_{t-1}) + (1-\beta)\varphi b_{t-1},\\
s_t &= \gamma (y_t - \ell_t) + (1-\gamma) s_{t-m}.
\end{aligned}
$$

Прогноз на $h$ шагов:

$$
\hat y_{t+h} = \ell_t + \left(\sum_{i=1}^{h}\varphi^i\right) b_t + s_{t+h-m}.
$$

**Затухание тренда — не косметика.** При $\varphi = 1$ прогноз линейно
продолжает последний наклон, и на горизонте в год уходит в значения, которых
бизнес никогда не видел. Сумма $\sum \varphi^i$ при $\varphi < 1$ сходится,
и долгосрочный прогноз становится конечным. На практике $\varphi$ почти
всегда оказывается в диапазоне 0,85–0,98.

**Выбор между аддитивной и мультипликативной сезонностью** определяется тем,
растёт ли сезонный размах вместе с уровнем ряда. Для выручки почти всегда
верен мультипликативный вариант; аддитивный уместен для физических объёмов
со стабильной амплитудой.

Начальные состояния берутся из первого сезонного цикла: уровень — его среднее,
наклон — разница средних первых двух циклов, сезонные индексы — отклонения
от среднего первого цикла. Параметры сглаживания подбираются минимизацией
суммы квадратов ошибок, ограничения задаются заменой переменных.

Автоподбор перебирает конфигурации — с трендом и без, с затуханием и без,
три вида сезонности — и выбирает лучшую по AIC.

## Сложность

| Ресурс | Оценка | Комментарий |
|--------|--------|-------------|
| Оценка | $O(I \cdot n)$ | $I$ — итераций симплекса |
| Автоподбор | $O(12 \cdot I \cdot n)$ | До двенадцати конфигураций |
| Память | $O(n + m)$ | Ряд и сезонные состояния |

## API

| Метод | Описание |
|-------|----------|
| `ExponentialSmoothing.Fit(series, horizon, season, seasonality, damped, withTrend, level)` | Заданная конфигурация |
| `ExponentialSmoothing.AutoFit(series, horizon, season, level)` | Перебор конфигураций по AIC |
| `SeasonalityType` | Нет, аддитивная, мультипликативная |
| `ForecastResult.Parameters` | Оценённые alpha, beta, gamma, phi |
| `ForecastResult.InSampleMase` | Сравнение с наивным прогнозом |

Исходник: `src/AI.Economics/Forecasting/ExponentialSmoothing.cs`.

## Код

```csharp
using AI.DataStructs.Algebraic;
using AI.Economics.Forecasting;

var random = new Random(3);
const int months = 120;
var sales = new Vector(months);

for (int t = 0; t < months; t++)
{
    sales[t] = 1000 + (4.0 * t)
             + (150 * Math.Sin(2 * Math.PI * t / 12.0))
             + ((random.NextDouble() - 0.5) * 60);
}

ForecastResult best = ExponentialSmoothing.AutoFit(sales, horizon: 24, season: 12);

Console.WriteLine($"Выбрана конфигурация: {best.Model}");
foreach ((string name, double value) in best.Parameters)
    Console.WriteLine($"  {name} = {value:F4}");

Console.WriteLine($"MASE на обучении: {best.InSampleMase:F3}");

// Сравнение затухающего и обычного тренда на длинном горизонте
var smoothing = new ExponentialSmoothing();
ForecastResult damped = smoothing.Fit(
    sales, horizon: 36, season: 12, SeasonalityType.Additive, damped: true, withTrend: true);
ForecastResult undamped = smoothing.Fit(
    sales, horizon: 36, season: 12, SeasonalityType.Additive, damped: false, withTrend: true);

Console.WriteLine($"Через 36 мес.: с затуханием {damped.PointForecast[35]:N0}, " +
                  $"без затухания {undamped.PointForecast[35]:N0}");
Console.WriteLine(best.Interpret().ToLlmText());
```

## Ограничения

- Мультипликативная сезонность требует строго положительного ряда: при нулевых
  значениях деление на сезонный индекс теряет смысл.
- Для сезонной модели нужно минимум два полных цикла. На полутора циклах
  сезонные индексы оцениваются по одному наблюдению на период.
- Начальные состояния берутся из первого цикла и не оптимизируются вместе
  с параметрами. На коротких рядах это заметно влияет на результат.
- Интервалы прогноза приближённые: они строятся по накоплению весов
  сглаживания, а не из точной формулы пространства состояний. Для строгих
  гарантий покрытия используйте [конформное предсказание](conformal.md).
- Модель не принимает внешние регрессоры. Если промо и праздники значимы,
  нужен [SARIMAX](arima.md) либо предварительное очищение ряда.
