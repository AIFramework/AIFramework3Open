# Ожидаемые кредитные убытки по МСФО 9

Резерв на 12 месяцев и на весь срок, стадии обесценения и взвешивание
прогнозных макросценариев — расчёт, который аудитор проверяет построчно.

## Постановка задачи

Дано: портфель договоров с величиной под риском дефолта, вероятностью дефолта
на отчётную дату и на дату выдачи, потерями при дефолте, эффективной ставкой и
сроком до погашения.

Требуется: резерв по каждому договору и по портфелю в целом, стадия
обесценения каждого договора с объяснением, и раскладка резерва по
макросценариям.

Где встречается: обязательная отчётность банков, лизинговых и факторинговых
компаний; оценка достаточности резервов при покупке портфеля; управленческий
прогноз стоимости риска.

## Теория

Стандарт заменил модель понесённых убытков на модель ожидаемых: резерв
создаётся в момент выдачи, а не в момент просрочки. Величина зависит от стадии:

| Стадия | Условие | Горизонт резерва |
|--------|---------|------------------|
| 1 | значимого роста риска нет | 12 месяцев |
| 2 | значимый рост кредитного риска | весь оставшийся срок |
| 3 | кредитное обесценение | весь оставшийся срок |

Значимый рост риска (SICR) фиксируется по двум правилам одновременно —
относительному и абсолютному:

$$
\frac{\mathrm{PD}_t}{\mathrm{PD}_0} \ge \theta_{\text{rel}}
\quad\text{и}\quad
\mathrm{PD}_t - \mathrm{PD}_0 \ge \theta_{\text{abs}} ,
$$

плюс безусловный триггер по просрочке: 30 дней переводят на стадию 2,
90 дней — на стадию 3.

Расчёт идёт по месяцам жизни договора. Годовая вероятность дефолта
раскладывается в помесячную интенсивность, из неё строится кривая выживания и
предельных вероятностей дефолта, каждый месячный убыток дисконтируется по
эффективной ставке:

$$
h = 1 - (1-\mathrm{PD})^{1/12},
\qquad
S(t) = (1-h)^t,
\qquad
m(t) = S(t-1)\,h ,
$$

$$
\mathrm{ECL} \;=\; \sum_{t=1}^{T} \frac{m(t)\cdot \mathrm{LGD}\cdot \mathrm{EAD}}{(1+\mathrm{EIR})^{t/12}} .
$$

Прогнозная информация вводится набором макросценариев с вероятностями: резерв
считается в каждом сценарии и взвешивается. Это принципиальный момент
стандарта — из-за нелинейности убытков по вероятности дефолта взвешенный
резерв не совпадает с резервом, посчитанным по одному «среднему» сценарию.

## Сложность

| Ресурс | Оценка | Комментарий |
|--------|--------|-------------|
| Время  | $O(n\,S\,T)$ | $n$ договоров, $S$ сценариев, $T$ месяцев |
| Память | $O(n\,T)$ | кривые дефолтов по договорам |

## API

| Метод | Описание |
|-------|----------|
| `Ifrs9.Compute(exposures, scenarios, options)` | Резерв по портфелю со стадированием |
| `Ifrs9.AssignStage(exposure, options)` | Стадия договора и причина её присвоения |
| `Ifrs9.DefaultScenarios()` | Базовый, оптимистичный и стрессовый сценарии |
| `EclResult.Stages` / `Scenarios` | Свод по стадиям и по макросценариям |
| `EclResult.StagingEffect` | Прирост резерва сверх 12-месячной базы |
| `ExposureEcl.MarginalDefaultCurve` | Помесячная кривая дефолтов договора |

Исходники: `src/AI.Economics/Credit/Ifrs9.cs`.

## Код

```csharp
using AI.Economics.Credit;

var portfolio = new List<CreditExposure>
{
    new()
    {
        Id = "K-001", Segment = "Розница", ExposureAtDefault = 1_200_000,
        ProbabilityOfDefault = 0.02, ProbabilityOfDefaultAtOrigination = 0.018,
        LossGivenDefault = 0.40, EffectiveInterestRate = 0.14, RemainingMonths = 36,
    },
    new()
    {
        Id = "K-002", Segment = "МСБ", ExposureAtDefault = 5_000_000,
        ProbabilityOfDefault = 0.09, ProbabilityOfDefaultAtOrigination = 0.02,
        LossGivenDefault = 0.50, EffectiveInterestRate = 0.18, RemainingMonths = 48,
    },
    new()
    {
        Id = "K-003", Segment = "МСБ", ExposureAtDefault = 2_500_000,
        ProbabilityOfDefault = 0.70, ProbabilityOfDefaultAtOrigination = 0.05,
        LossGivenDefault = 0.60, EffectiveInterestRate = 0.20, RemainingMonths = 12,
        DaysPastDue = 120, IsCreditImpaired = true,
    },
};

EclResult ecl = Ifrs9.Compute(portfolio);

Console.WriteLine($"Экспозиция {ecl.TotalExposure:N0}, резерв {ecl.TotalEcl:N0} ({ecl.CoverageRatio:P2})");
Console.WriteLine($"Вклад стадирования: {ecl.StagingEffect:N0}");

foreach (StageSummary stage in ecl.Stages)
    Console.WriteLine($"{stage.Stage}: {stage.Count} дог., покрытие {stage.CoverageRatio:P2}");
```

Стадию можно получить отдельно — это удобно для сверки с учётной системой:

```csharp
foreach (CreditExposure exposure in portfolio)
{
    (CreditStage stage, string reason) = Ifrs9.AssignStage(exposure);
    Console.WriteLine($"{exposure.Id}: {stage} — {reason}");
}
```

Собственный набор макросценариев задаётся явно; вероятности нормируются:

```csharp
IReadOnlyList<MacroScenario> scenarios =
[
    new MacroScenario("Базовый", 0.50, 1.0),
    new MacroScenario("Восстановление", 0.20, 0.6, 0.9),
    new MacroScenario("Рецессия", 0.30, 2.2, 1.3),
];

EclResult stressed = Ifrs9.Compute(portfolio, scenarios);

foreach (ScenarioEcl scenario in stressed.Scenarios)
    Console.WriteLine($"{scenario.Name} ({scenario.Probability:P0}): {scenario.Ecl:N0}");

Console.WriteLine(stressed.Interpret().ToLlmText());
```

## Ограничения

- Расчёт предполагает постоянную величину под риском на всём горизонте.
  Для амортизируемых кредитов и кредитных линий график экспозиции надо
  моделировать отдельно и подавать помесячно.
- Вероятность дефолта берётся как годовая и раскладывается на месяцы
  предположением о постоянной интенсивности. Для длинных договоров точнее
  строить кривую по [матрице миграции рейтингов](migration_matrix.md).
- Множители сценариев применяются ко всему портфелю одинаково. Реальная
  чувствительность к макроэкономике различается по сегментам, и для крупных
  портфелей её нужно оценивать регрессией на макропеременные.
- Критерий значимого роста риска — управленческое суждение, а не расчёт.
  Слишком чувствительный порог заставляет договоры «мигать» между стадиями и
  делает резерв волатильным без экономической причины.
- Модель не учитывает обеспечение явно: его влияние закладывается в потери при
  дефолте, которые здесь задаются экзогенно.
