# MRR-мостик

Разложение изменения регулярной выручки на пять компонент и метрики удержания
денег: NDR, GRR и quick ratio.

## Постановка задачи

Дано: два среза «клиент — выручка» — на начало и на конец периода.

Требуется: разложить изменение выручки на новые продажи, расширение,
сокращение, отток и реактивацию; посчитать удержание выручки.

Где встречается: ежемесячная управленческая отчётность, инвесторский апдейт,
due diligence перед раундом.

## Теория

Одно число «выручка выросла на 8 %» не отвечает на главный вопрос: за счёт
чего. Рост на 8 % при оттоке 15 % и продажах 23 % — совсем не то же самое, что
рост на 8 % при оттоке 2 %. Первый вариант требует всё больше денег на
привлечение просто чтобы стоять на месте.

Компоненты считаются по клиентам, а не по агрегатам: иначе расширение и отток
взаимозачитываются и исчезают из отчёта. Для клиента с выручкой $s_i$ на начало
и $e_i$ на конец:

- отток, если $e_i = 0$: вклад $s_i$;
- расширение, если $e_i > s_i$: вклад $e_i - s_i$;
- сокращение, если $0 < e_i < s_i$: вклад $s_i - e_i$.

Клиенты, которых не было в начальном срезе, дают новую выручку — либо
реактивацию, если они уходили ранее.

Тождество мостика:

$$
MRR_{end} = MRR_{start} + New + Expansion + Reactivation - Contraction - Churn.
$$

Метрики удержания считаются **без** новых клиентов — иначе они измеряли бы
работу отдела продаж, а не удержание базы:

$$
NDR = \frac{MRR_{start} + Expansion - Contraction - Churn}{MRR_{start}},
\qquad
GRR = \frac{MRR_{start} - Contraction - Churn}{MRR_{start}}.
$$

$GRR$ не может превышать единицу и потому служит потолком честности: он
показывает удержание без права «закрыть» отток апсейлом крупному клиенту.
$NDR$ выше единицы означает, что база растёт сама даже при полной остановке
продаж.

Quick ratio — отношение прироста выручки к её потерям:

$$
QR = \frac{New + Expansion + Reactivation}{Churn + Contraction}.
$$

Значение ниже единицы означает, что компания теряет быстрее, чем набирает.

## Сложность

| Ресурс | Оценка | Комментарий |
|--------|--------|-------------|
| Время  | $O(n)$ | $n$ — клиентов в срезах |
| Память | $O(n)$ | Множество ранее ушедших для реактивации |

## API

| Метод | Описание |
|-------|----------|
| `MrrBridge.Build(start, end, previouslyChurned)` | Мостик между двумя срезами |
| `MrrBridge.BuildSeries(snapshots)` | Ряд мостиков; реактивация отслеживается автоматически |
| `MrrBridgeResult.NetDollarRetention` | Удержание выручки с расширениями |
| `MrrBridgeResult.GrossRevenueRetention` | Удержание без расширений |
| `MrrBridgeResult.QuickRatio` | Прирост делить на потери |

Исходник: `src/AI.Economics/Saas/MrrBridge.cs`.

## Код

```csharp
using AI.Economics.Saas;

var start = new Dictionary<string, double>
{
    ["Альфа"] = 120_000,
    ["Бета"] = 80_000,
    ["Гамма"] = 45_000,
    ["Дельта"] = 30_000,
};

var end = new Dictionary<string, double>
{
    ["Альфа"] = 165_000,   // расширение
    ["Бета"] = 62_000,     // сокращение
    ["Гамма"] = 0,         // отток
    ["Дельта"] = 30_000,   // без изменений
    ["Эпсилон"] = 95_000,  // новый клиент
};

MrrBridgeResult bridge = MrrBridge.Build(start, end);

Console.WriteLine($"MRR: {bridge.StartingMrr:N0} -> {bridge.EndingMrr:N0}");
Console.WriteLine($"Новые       +{bridge.NewMrr:N0}");
Console.WriteLine($"Расширение  +{bridge.ExpansionMrr:N0}");
Console.WriteLine($"Сокращение  -{bridge.ContractionMrr:N0}");
Console.WriteLine($"Отток       -{bridge.ChurnedMrr:N0}");
Console.WriteLine($"NDR={bridge.NetDollarRetention:P1}  GRR={bridge.GrossRevenueRetention:P1}  QR={bridge.QuickRatio:F2}");
```

## Ограничения

- Срез должен содержать выручку каждого клиента, а не сумму по тарифам:
  агрегированные данные не позволяют отделить расширение от новых продаж.
- Идентификатор клиента обязан быть стабильным между срезами. Переоформление
  договора на новое юридическое лицо выглядит как отток плюс новая продажа.
- Реактивация определяется по истории: в `Build` её надо передать явно,
  `BuildSeries` отслеживает сама.
- Разовые платежи и услуги внедрения в MRR включать нельзя — они дают ложное
  расширение с последующим ложным сокращением.
