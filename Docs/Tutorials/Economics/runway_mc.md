# Runway методом Монте-Карло

Оценка запаса прочности как распределения, а не как одного числа: когда
кончатся деньги при удачном и при неудачном стечении обстоятельств.

## Постановка задачи

Дано: остаток денег, выручка и затраты первого месяца, их средние темпы роста
и волатильность, запланированные поступления инвестиций.

Требуется: распределение месяца исчерпания денег, вероятность дожить до конца
горизонта и коридор остатка на счету по месяцам.

Где встречается: решение о выходе на раунд, планирование найма, разговор с
советом директоров о сокращении затрат.

## Теория

Обычный расчёт «касса делить на средний burn» отвечает на вопрос, которого
никто не задавал: что будет, если всё пойдёт ровно по плану. О риске он не
говорит ничего, а именно риск определяет решение — выходить на раунд сейчас
или через квартал.

Выручка и затраты моделируются геометрическим случайным блужданием:

$$
R_{t} = R_{t-1}\,e^{\varepsilon_t},
\qquad
\varepsilon_t \sim \mathcal N\!\left(\ln(1+\mu),\, \sigma^2\right).
$$

Логарифмически нормальные приращения выбраны не случайно: они удерживают
величины положительными, а медианный темп роста совпадает с заданным $\mu$.
Аддитивная модель с нормальным шумом при достаточной волатильности загоняет
выручку в минус, чего в реальности не бывает.

Денежный поток месяца и остаток на счету:

$$
CF_t = R_t \cdot g - C_t + F_t,
\qquad
K_t = K_{t-1} + CF_t,
$$

где $g$ — доля валовой маржи, $F_t$ — поступления инвестиций (каждое со своей
вероятностью наступления). Траектория обрывается в первый месяц, когда
$K_t < 0$; этот месяц и есть срок жизни в данном сценарии.

По множеству траекторий строится распределение срока жизни. Практический вывод
читается по левому хвосту: важно не то, когда деньги кончатся «в среднем»,
а когда они кончатся в неудачном сценарии. Разрыв между P10 и медианой — цена
неопределённости, и он тем больше, чем выше волатильность выручки.

## Сложность

| Ресурс | Оценка | Комментарий |
|--------|--------|-------------|
| Время  | $O(S \cdot H)$ | $S$ — траекторий, $H$ — горизонт в месяцах |
| Память | $O(S \cdot H)$ | Матрица остатков для расчёта квантилей коридора |

## API

| Метод | Описание |
|-------|----------|
| `RunwaySimulator.Simulate(input)` | Запуск симуляции |
| `RunwayResult.DeterministicRunwayMonths` | Наивная оценка «касса делить на burn» |
| `RunwayResult.CashOutP10` / `CashOutP50` / `CashOutP90` | Квантили месяца исчерпания денег |
| `RunwayResult.SurvivalProbability` | Вероятность дожить до конца горизонта |
| `RunwayResult.CashP10` / `CashP50` / `CashP90` | Коридор остатка по месяцам |
| `FundingEvent(month, amount, probability)` | Поступление денег с вероятностью наступления |

Исходник: `src/AI.Economics/Runway/RunwaySimulator.cs`.

## Код

```csharp
using AI.Economics.Runway;

var input = new RunwayInput
{
    Cash = 60_000_000,
    MonthlyRevenue = 6_000_000,
    RevenueGrowthMean = 0.07,
    RevenueGrowthVolatility = 0.15,
    GrossMarginRate = 0.75,
    MonthlyCosts = 12_000_000,
    CostGrowthMean = 0.03,
    CostGrowthVolatility = 0.03,
    Horizon = 30,
    Simulations = 5_000,
    Seed = 42,
};

RunwayResult result = RunwaySimulator.Simulate(input);

Console.WriteLine($"Наивный runway:  {result.DeterministicRunwayMonths:F1} мес.");
Console.WriteLine($"P10 / медиана:   {result.CashOutP10:F1} / {result.CashOutP50:F1} мес.");
Console.WriteLine($"Дожили до конца: {result.SurvivalProbability:P1}");
Console.WriteLine($"Разрыв за год:   {result.ProbabilityCashOutIn12:P1}");
```

Запланированный транш меняет картину, а вероятность его получения — тоже
параметр модели:

```csharp
RunwayResult withRound = RunwaySimulator.Simulate(input with
{
    Funding = [new FundingEvent(Month: 6, Amount: 150_000_000, Probability: 0.6)],
});

Console.WriteLine($"С учётом раунда медиана: {withRound.CashOutP50:F1} мес.");
```

## Ограничения

- Модель предполагает независимость приращений по месяцам. Реальные шоки
  автокоррелированы: плохой квартал обычно идёт целиком, а не одним месяцем,
  и настоящий левый хвост тяжелее модельного.
- Затраты растут по заданному темпу и не реагируют на падение выручки. Это
  сознательно консервативно: в модели нет «сокращу расходы, если что», хотя
  в жизни такая опция есть.
- Волатильность задаётся руками. Оценивать её стоит по историческим месячным
  приращениям собственной выручки, а не брать «типичное» значение.
- Результат воспроизводим при фиксированном `Seed`; сравнивать сценарии надо
  на одном зерне, иначе разница будет частично шумом симуляции.
