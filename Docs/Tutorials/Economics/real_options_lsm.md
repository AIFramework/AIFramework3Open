# Реальные опционы: метод Лонгстаффа — Шварца

Стоимость управленческой гибкости — права отложить проект, расширить его или
отказаться от него — считается методом наименьших квадратов на траекториях
Монте-Карло.

## Постановка задачи

Дано: текущая оценка проекта, её волатильность, стоимость инвестиции или
ликвидационная стоимость, горизонт принятия решения и безрисковая ставка.

Требуется: полная стоимость проекта с учётом гибкости, отдельно — стоимость
самого опциона, вероятность его исполнения и граница исполнения по времени.

Где встречается: лицензии на разработку месторождений, поэтапные НИОКР,
опцион на расширение мощности, право выйти из проекта с продажей активов,
аренда с правом досрочного расторжения.

## Теория

Классический NPV предполагает, что решение принимается один раз и навсегда.
На деле менеджмент наблюдает за проектом и реагирует: сворачивает при плохих
новостях, расширяет при хороших. Это право несимметрично — оно отсекает
убытки, не ограничивая прибыль, — и потому стоит денег.

**Динамика стоимости проекта** моделируется геометрическим броуновским
движением в риск-нейтральной мере:

$$
V_{t+\Delta} \;=\; V_t\,\exp\!\left[\left(r - \delta - \tfrac{1}{2}\sigma^2\right)\Delta + \sigma\sqrt{\Delta}\,z\right],
\qquad z\sim\mathcal N(0,1),
$$

где $\delta$ — «дивидендная» доходность проекта, то есть теряемый поток за
время ожидания. Именно $\delta$ делает ожидание небесплатным: без неё
откладывать выгодно почти всегда.

**Выплата при исполнении** зависит от типа опциона:

$$
\Pi_t = \begin{cases}
V_t - I, & \text{отсрочка запуска},\\
(k-1)V_t - I_{\text{расш}}, & \text{расширение в } k \text{ раз},\\
S - V_t, & \text{отказ с продажей за } S .
\end{cases}
$$

**Ключевая идея Лонгстаффа — Шварца.** На каждом шаге назад по времени надо
сравнить немедленное исполнение с ожидаемой стоимостью продолжения. Последняя
неизвестна, но её можно оценить регрессией: по траекториям, где опцион «в
деньгах», строится регрессия дисконтированной будущей выплаты на текущее
состояние:

$$
\mathbb E\left[e^{-r\Delta}\Pi_{t+\Delta}\mid V_t\right] \;\approx\; a + b\,V_t + c\,V_t^2 .
$$

Исполнение происходит там, где $\Pi_t$ больше расчётного продолжения.
Регрессия строится **только по траекториям в деньгах** — вне денег решение
тривиально, а их включение испортило бы подгонку в интересующей области.

**Стоимость опциона** — разница между полной стоимостью с гибкостью и
статическим NPV. Она всегда неотрицательна и растёт с волатильностью: чем
неопределённее проект, тем ценнее право передумать.

## Сложность

| Ресурс | Оценка | Комментарий |
|--------|--------|-------------|
| Время  | $O(P\,S)$ | $P$ траекторий, $S$ шагов; регрессия — $O(P)$ на шаг |
| Память | $O(P)$ | текущий срез траекторий и выплат |

## API

| Метод | Описание |
|-------|----------|
| `LongstaffSchwartz.Value(input)` | Стоимость проекта с учётом гибкости |
| `ProjectOptionResult.TotalValue` / `StaticNpv` | С гибкостью и без неё |
| `ProjectOptionResult.OptionValue` | Стоимость самой гибкости |
| `ProjectOptionResult.ExerciseProbability` | Доля траекторий с исполнением |
| `ProjectOptionResult.ExpectedExerciseTime` | Ожидаемый момент решения |
| `ProjectOptionResult.ExerciseBoundary` | Граница исполнения по шагам |

Исходники: `src/AI.Economics/Corporate/LongstaffSchwartz.cs`.

## Код

```csharp
using AI.Economics.Corporate;

var deferral = new ProjectOptionInput
{
    Name = "Лицензия на участок",
    Option = ProjectOption.Defer,
    ProjectValue = 1_000_000_000,
    InvestmentCost = 950_000_000,
    Horizon = 4,
    Volatility = 0.35,
    RiskFreeRate = 0.09,
    ConvenienceYield = 0.03,
    Steps = 48,
    Paths = 20_000,
    Seed = 11,
};

ProjectOptionResult option = LongstaffSchwartz.Value(deferral);

Console.WriteLine($"Статический NPV {option.StaticNpv:N0}");
Console.WriteLine($"С учётом гибкости {option.TotalValue:N0} ± {option.StandardError:N0}");
Console.WriteLine($"Стоимость опциона {option.OptionValue:N0}");
Console.WriteLine($"Исполняется в {option.ExerciseProbability:P1} сценариев, " +
                  $"в среднем через {option.ExpectedExerciseTime:F2} года");
```

Волатильность — главный драйвер стоимости гибкости; для проекта с
отрицательным статическим NPV она может решить исход:

```csharp
foreach (double sigma in new[] { 0.15, 0.25, 0.35, 0.50 })
{
    ProjectOptionResult scenario = LongstaffSchwartz.Value(deferral with { Volatility = sigma });
    Console.WriteLine($"σ = {sigma:P0}: опцион {scenario.OptionValue:N0}, " +
                      $"итого {scenario.TotalValue:N0}");
}
```

Опцион отказа оценивается тем же методом — меняется только тип и параметр
ликвидационной стоимости:

```csharp
ProjectOptionResult abandonment = LongstaffSchwartz.Value(deferral with
{
    Name = "Право выйти из проекта",
    Option = ProjectOption.Abandon,
    SalvageValue = 700_000_000,
});

Console.WriteLine($"Стоимость права выхода {abandonment.OptionValue:N0}");
Console.WriteLine(option.Interpret().ToLlmText());
```

## Ограничения

- Волатильность стоимости проекта не наблюдается напрямую. Её оценивают по
  волатильности цены сырья или по аналогам, и результат крайне чувствителен к
  этой оценке: удвоение $\sigma$ может удвоить стоимость опциона.
- Геометрическое броуновское движение не описывает возврат цены к среднему,
  характерный для сырьевых рынков. Для нефти и металлов оно завышает
  стоимость долгих опционов.
- Метод даёт смещённую вверх оценку при малом числе траекторий: регрессия
  подстраивается под шум. Стандартная ошибка в результате отражает только
  разброс, но не это смещение — увеличивайте `Paths` до десятков тысяч.
- Предполагается, что решение принимается только в узлах сетки. Редкая сетка
  занижает стоимость; для горизонта в несколько лет берите не меньше
  двенадцати шагов в год.
- Модель игнорирует конкурентов: право отложить обесценивается, если
  соперник может занять рынок первым. Такой опцион ближе к игре, чем к
  финансовому инструменту.
