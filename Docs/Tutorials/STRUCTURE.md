# Канон структуры файла теории

Каждый `.md` в `Docs/Tutorials/<Модуль>/` — это левая колонка страницы алгоритма
в WebUI-демо (`/lib/{модуль}/algo/{ключ}`). Он читается рядом с работающим
демо, а не вместо него, поэтому структура ниже обязательна: читатель должен
за один экран понять **что считается**, **по какой формуле** и **как это
вызвать из кода**.

Соблюдение проверяется линтером `Tools/DocsLint` (запускается в CI).

---

## Что проверяет линтер

**Ошибки** — объективно сломанное. Роняют CI всегда, обойти нельзя.

| Код | Правило |
|-----|---------|
| `MD001` | Нет заголовка `# Название` |
| `MD002` | Заголовков `# ` больше одного |
| `MD003` | Первый заголовок файла — не `# ` |
| `MD004` | Документ короче 800 символов (заглушка, а не теория) |
| `MD005` | Неканоническое написание раздела (чинится `--fix`) |
| `MD010` | `AlgoDef.TheoryFile` указывает на несуществующий файл |

**Предупреждения** — незаполненные разделы канона.

| Код | Правило |
|-----|---------|
| `MD006` | Нет раздела канона (`Постановка задачи`, `API`, `Код`, `Сложность`, `Ограничения`) |
| `MD007` | Нет ни одного блока ` ```csharp ` |
| `MD008` | Файл не связан ни с одним `AlgoDef` — в демо недоступен |

### Baseline

Предупреждений в существующих документах сотни, поэтому действует
`Docs/Tutorials/.docslint-baseline`: уже известные записаны там и CI не
роняют, а **любое новое** — роняет. Так канон обязателен для новых
документов и не требует разом переписать двести старых.

Дописав раздел, удалите строку из baseline (или прогоните
`--update-baseline`) — иначе правило перестанет отслеживаться для этого файла.

## Канонический порядок разделов

```markdown
# Название алгоритма

Одно-два предложения: что это и зачем.

## Постановка задачи
Что дано, что требуется найти, где встречается на практике.

## Теория
Формулы в LaTeX: $inline$ и $$display$$.

## Сложность
Время и память, с указанием обозначений (n — число вершин и т.д.).

## API
Таблица методов класса или сигнатуры с пояснениями.

## Код
Рабочий C#-сниппет, который можно скопировать и запустить.

## Ограничения
Когда метод не применим, численные подводные камни.

## См. также
Ссылки на соседние документы: [Название](другой_файл.md)
```

Необязательные разделы, если по теме уместны: `## Свойства`,
`## Применения`, `## Примеры`, `## Числовые замечания`, `## Архитектура`,
`## Быстрый старт`.

## Синонимы: переименования и эквиваленты

Различаются два случая — линтер их не смешивает.

**Переименования** — разные написания одного и того же. Заголовок правится
автоматически (`--fix`), содержимое не трогается:

| Было | Стало |
|------|-------|
| `## API (C#)`, `## API C#`, `## API и использование` | `## API` |
| `## Применение` | `## Применения` |
| `## Пример`, `## Пример использования`, `## Примеры использования` | `## Примеры` |
| `## Идея алгоритма` | `## Теория` |

**Эквиваленты** — заголовок называется иначе, но закрывает ту же роль.
Файл **не правится**: `## Достоинства и ограничения` содержит и достоинства
тоже, переименование в `## Ограничения` сделало бы заголовок ложью.

| Раздел канона | Засчитывается также |
|---------------|---------------------|
| `Постановка задачи` | `Назначение`, `Обзор`, `Определение`, `Задача` |
| `Теория` | `Математическая основа`, `Алгоритм`, `Формулы` |
| `Ограничения` | `Достоинства и ограничения`, `Замечания`, `Числовые замечания` |
| `Код` | `Примеры`, `Быстрый старт`, `Пример кода` |

## Параметры демо

Отдельный раздел про ползунки писать **не нужно**: таблица «Параметры демо»
генерируется автоматически из `AlgoDef.Params` и показывается под теорией.
Чтобы она была полезной, заполняйте в `AlgoParam` поля `Label`, `Unit` и
особенно `Hint` — именно `Hint` попадает в колонку «Что меняет».

Если параметр требует объяснения через формулу (например, связь ползунка
$k_1$ с насыщением TF в BM25), это место — раздел `## Теория`, где параметр
упоминается тем же именем, что и в `AlgoParam.Label`.

## Математика

Markdig настроен на `UseMathematics`, KaTeX рендерит на клиенте.
Поддерживаются `$…$`, `$$…$$`, а также `\(…\)` и `\[…\]` — последние
препроцессор превращает в `$`-форму до Markdig.

## Диаграммы

Блок ```` ```mermaid ```` рендерится как SVG с зумом и панорамированием.
Используйте для схем пайплайнов и конечных автоматов вместо ASCII-графики.

## Проверка перед коммитом

```bash
dotnet run --project Tools/DocsLint -- --strict
```

Это ровно то, что запускает CI (`.github/workflows/docs-lint.yml`).
Без `--strict` проверяются только ошибки.

Полный набор команд:

```bash
dotnet run --project Tools/DocsLint -- --fix
```

```bash
dotnet run --project Tools/DocsLint -- --update-baseline
```

Готовый образец документа, следующего канону, — [Template/algo_a.md](Template/algo_a.md).
