# Оптимизация `AI.Solvers.Optimization` (AI.Solvers.Optimization.dll)

Сборка **`AI.Solvers.Optimization`** (`AI.Solvers.Optimization.dll`, **.NET 9.0**) — линейное
и смешанно-целочисленное программирование. Зависит только от ядра **`AI`**.

До неё в репозитории решались лишь частные случаи: транспортная задача методом потенциалов
и потоки минимальной стоимости в `AI.Algorithms`. Общей постановки не было, и код, которому она
требовалась, обходился приближениями — так, `AI.Economics.Portfolio.CvarOptimization` прямо
пишет, что задача сводится к линейному программированию, но решает её субградиентным спуском
с проекцией на симплекс весов.

---

## Состав

| Тип | Назначение |
|-----|------------|
| **`LinearProgram`** | Модель: переменные с границами и областью значений, ограничения, целевая функция. |
| **`Variable`** | Переменная: непрерывная, целочисленная или булева; границы, в том числе бесконечные. |
| **`Constraint`** | Линейное ограничение со знаком `<=`, `>=` или `=`. |
| **`LpSolver`** | Решение: симплекс для непрерывной задачи, ветви и границы для целочисленной. |
| **`LpSolution`** | Исход, значение функции, значения переменных, число итераций и узлов; реализует `IInterpretable`. |
| **`LpOptions`** | Пределы итераций и узлов, допуск целочисленности. |

```csharp
using AI.Solvers.Optimization;

var lp = new LinearProgram(ObjectiveSense.Maximize, "Производственная программа");
Variable x = lp.AddVariable("x");
Variable y = lp.AddVariable("y");

lp.SetObjective(new Vector(3.0, 5.0));
lp.AddConstraint(new Vector(1.0, 0.0), ConstraintSign.LessOrEqual, 4,  "цех 1");
lp.AddConstraint(new Vector(0.0, 2.0), ConstraintSign.LessOrEqual, 12, "цех 2");
lp.AddConstraint(new Vector(3.0, 2.0), ConstraintSign.LessOrEqual, 18, "сборка");

LpSolution solution = LpSolver.Solve(lp);   // 36 при x = 2, y = 6
Console.WriteLine(solution.Interpret());
```

## Как устроено решение

**Приведение к стандартному виду** делает `LpSolver`, а не симплекс: нижние границы сдвигаются
(`x = l + y`), переменные без нижней границы заменяются отступом от верхней, свободные —
разностью двух неотрицательных, верхние границы переносятся в ограничения, неравенства получают
балансовые переменные. Симплекс видит только задачу `min cᵀy` при `Ay = b`, `y ≥ 0` и о границах
ничего не знает — благодаря этому метод ветвей и границ меняет границы переменных, не трогая
структуру задачи.

**Симплекс** работает в две фазы: сначала минимизируется сумма искусственных переменных, что даёт
допустимый базис либо доказывает несовместность, затем минимизируется исходная функция.

Выбор ведущего столбца — по правилу Данцига, но после двухсот итераций решатель переключается
на правило Бланда. Правило Данцига быстрее, но на вырожденных задачах способно зациклиться;
правило Бланда медленнее и зацикливание исключает. Переключение даёт скорость первого
и гарантию второго.

**Метод ветвей и границ** решает ослабленную задачу, выбирает самую дробную из целочисленных
переменных и делит задачу надвое — `x ≤ ⌊v⌋` и `x ≥ ⌈v⌉`. Ветви с оценкой хуже найденного
целого решения отсекаются. Если дерево пройдено целиком, решение оптимально; если исчерпан
предел узлов, исход — `LimitReached`, а `LpSolution.Gap` показывает, насколько решение ещё
может быть улучшено.

## Границы применимости

Коэффициенты хранятся плотно, симплекс — табличный. Это разумно для задач в сотни переменных
и ограничений: производственные планы, рецептуры, назначения, раскрой, транспортные задачи.
Для тысяч переменных с редкой матрицей нужны разреженное хранение и пересчёт базиса
через разложение, а не полная таблица; это отдельная работа, и делать вид, что её нет,
не стоит.

Двойственные оценки (теневые цены) пока не выдаются: `LpSolution` содержит только прямое
решение. Для анализа чувствительности задачу приходится пересчитывать с изменёнными правыми
частями — на задачах указанного размера это дёшево.

## Проверка

Решатель сверен с задачами, у которых ответ известен независимо: классическая задача о плане
производства, задача о рюкзаке, задача о назначениях, транспортная задача — последняя решается
в `AI.Algorithms` методом потенциалов, и общий решатель обязан давать ту же стоимость.
Отдельно проверены вырожденная задача, несовместная система, неограниченная функция,
отрицательные и бесконечные границы переменных.

```bash
dotnet test Tests/unit/AIFramework.UnitTests/AIFramework.UnitTests.csproj -c Release
```
