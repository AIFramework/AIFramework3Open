# Эконометрика `AI.Econometrics` (AI.Econometrics.dll)

Сборка **`AI.Econometrics`** (`AI.Econometrics.dll`, **.NET 9.0**) — статистический вывод и причинный
анализ, не привязанные к предметной области. Выделена из `AI.Economics`: те же методы нужны
в QSAR, в химической кинетике и в любом месте, где по данным делают вывод, а не прогноз.

Зависимости: только ядро **`AI`** (алгебра, статистика, `AI.Insights`).

---

## Ключевые области

| Область | Содержание |
|---------|------------|
| **Регрессия и диагностика** | МНК и ВНК, робастные ошибки HC0–HC3, Ньюи — Уэста и кластерные; Брёйш — Паган, Уайт, Дарбин — Уотсон, RESET, Чоу, Жарк — Бера, VIF. |
| **Эндогенность** | Инструментальные переменные, двухшаговый МНК, GMM, проверка слабых инструментов. |
| **Панельные данные** | Фиксированные, случайные и двусторонние эффекты, тест Хаусмана, динамические панели Ареллано — Бонда. |
| **Ограниченные зависимые** | Логит, пробит, тобит, Пуассон, отрицательная биномиальная; квантильная регрессия. |
| **Причинный вывод** | Разность разностей с робастной оценкой по когортам, разрывный дизайн, сопоставление по склонности, синтетический контроль, причинный лес. |
| **Временные ряды** | ADF/KPSS, VAR с причинностью по Грейнджеру и откликами, коинтеграция Йохансена и VECM, GARCH/GJR/EGARCH, модели в пространстве состояний. |
| **`Numerics`** (internal) | Вычислительная подложка: МНК на `double[,]`, симплекс Нелдера — Мида, распределения, логистическая регрессия, разложение Холецкого с гребнем. |

Каждый результирующий тип реализует `IInterpretable` из `AI.Insights`: расчёт объясняет себя
метриками, выводами, нарушенными допущениями и рекомендациями.

---

## Почему `Numerics` — internal

Подложка работает с `double[,]` и `double[]`, а публичный API фреймворка по
[CODING_STANDARD](../../CODING_STANDARD.md) допускает только `Vector`, `Matrix` и `NDTensor`.
Публиковать её значило бы нарушить стандарт, а копировать в `AI.Economics` — завести вторую
реализацию МНК. Поэтому типы остаются `internal`, а экономике выдан
`InternalsVisibleTo`: одна реализация, стандарт не нарушен.

## Что сознательно не сведено к общему коду

Ревизия дублирования при выделении сборки дала три случая, где совпадение поверхностное,
а объединение ухудшило бы результат. Они перечислены здесь, чтобы к ним не возвращались
с тем же вопросом.

| Пара | Почему оставлены раздельными |
|------|------------------------------|
| `StateSpace` — `AI.ControlSystems.KalmanFilter` | Общая только рекурсия. В управлении — матричный фильтр общего вида для онлайн-оценивания; здесь — скалярная специализация для локального уровня и линейного тренда с диффузной инициализацией, накоплением правдоподобия для оценки дисперсий и обратным сглаживанием по Дурбину — Купману. Сведение потребует сначала добавить сглаживатель и правдоподобие в общий фильтр. |
| `Numerics.LinearAlgebra.Cholesky` — `AI.ClassicMath.MatrixUtils.Cholesky` | Разные контракты: здесь `double[,]` с гребневой регуляризацией и `null` при вырождении, там `Matrix` с исключением. Делегирование добавило бы преобразование типов в горячий цикл МНК. |
| `Numerics.Ols` — `AI.ML.Regression.MultipleRegression` | Разные задачи: `MultipleRegression` предсказывает (обучение, масштабирование, сериализация), `Ols` делает вывод (стандартные ошибки, `(X'X)⁻¹`, R², веса, гребень). Общего кода почти нет. |

Сведено к общему коду: собственные значения. `Numerics.LinearAlgebra.SymmetricEigen` больше не
реализует метод вращений — он переводит `double[,]` в `Matrix` и обращается к
`AI.ClassicMath.MatrixUtils.Eigen`. Туда же ушла ортогонализация по Лёвдину из теста Йохансена:
та же операция была написана второй раз в квантовой химии.

Что, наоборот, сведено: `EconMath` больше не содержит собственных `Erf`, `NormalCdf`, `NormalPdf`,
`LogGamma` и квантиля нормального распределения — все они делегируют в `AI.Statistics.StatInference`.
При сведении в ядро переехали более точные реализации: квантиль по алгоритму Acklam
(погрешность ~1e-9 вместо ~4.5e-4 у прежней аппроксимации Абрамовица — Стиган) и логарифм
гамма-функции по Ланцошу с g = 7. Локально остались только функции, которых в ядре нет:
дигамма, гипергеометрическая `Hyp2F1`, регуляризованная неполная бета и распределение Фишера.
