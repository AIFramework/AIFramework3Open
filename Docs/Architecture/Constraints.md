# Ограничения `AI.Solvers.Constraints` (AI.Solvers.Constraints.dll)

Сборка **`AI.Solvers.Constraints`** (`AI.Solvers.Constraints.dll`, **.NET 9.0**) — выполнимость
булевых формул и задачи удовлетворения ограничений над конечными областями. Зависит только
от ядра **`AI`**.

Два решателя отвечают на разные вопросы. Первый работает с булевыми переменными и формулой
в конъюнктивной нормальной форме, второй — с целочисленными переменными и ограничениями вроде
«все различны». Задачи переводятся друг в друга, но кодировка целочисленной задачи в КНФ
раздувает её, а перевод булевой задачи в целочисленную теряет структуру, на которой держится
обучение на конфликтах. Поэтому решателя два.

---

## Выполнимость: `Sat`

| Тип | Назначение |
|-----|------------|
| **`CnfFormula`** | Формула в КНФ. Литералы в записи DIMACS: переменные с единицы, отрицание минусом. Готовые сочетания: `Implies`, `AtMostOne`, `AtLeastOne`, `ExactlyOne`. |
| **`SatSolver`** | Решатель CDCL: обучение на конфликтах с обратным прыжком. |
| **`SatSolution`** | Исход, подстановка, статистика; `Verify` проверяет подстановку независимо от решателя. |
| **`SatOptions`** | Предел конфликтов, затухание активности, база перезапусков. |

```csharp
using AI.Solvers.Constraints.Sat;

var formula = new CnfFormula();
int[] colours = formula.AddVariables(3);

formula.ExactlyOne(colours);
formula.AddClause(-colours[0], -colours[1]);

SatSolution solution = SatSolver.Solve(formula);
bool first = solution[colours[0]];
```

Что внутри и почему именно это:

* **два наблюдаемых литерала** — распространение не просматривает дизъюнкт целиком, пока
  два его литерала не ложны; без этого метод не масштабируется дальше игрушечных задач;
* **разбор конфликта до первой точки единственной импликации** — из конфликта выводится
  дизъюнкт, запрещающий не одну подстановку, а целое их семейство;
* **обратный прыжок** вместо отката на уровень: решатель возвращается сразу туда, где
  выученный дизъюнкт становится единичным;
* **активность переменных** с затуханием — ветвление идёт по переменным, которые чаще
  участвовали в недавних конфликтах;
* **сохранение фазы** и **перезапуски по Луби** — частые короткие заходы вытаскивают
  из неудачной ветви, редкие длинные доводят трудный поиск до конца.

Выученные дизъюнкты не удаляются. На задачах в тысячи переменных это допустимо, на больших
промышленных — нет: там нужна периодическая чистка базы по мере полезности. Предел конфликтов
не даёт решателю работать неограниченно и возвращает `Unknown`.

Выбор переменной — линейный просмотр активностей, без кучи. Для задач указанного размера это
не узкое место, для больших — станет.

**Частный случай 2-КНФ** решается за линейное время алгоритмом на графе импликаций —
`AI.Algorithms.GraphStructure.TwoSAT`. Он остаётся отдельно: общий решатель его не заменяет,
а тесты сверяют их ответы на случайных двухлитеральных формулах.

## Ограничения: `Cp`

| Тип | Назначение |
|-----|------------|
| **`CpModel`** | Модель: переменные с конечными областями и ограничения. |
| **`IntVariable`** | Переменная с областью значений `[lower; upper]`. |
| **`AllDifferent`** | Все переменные попарно различны. |
| **`LinearConstraint`** | `Σ aᵢxᵢ ⋛ b` с распространением по границам. |
| **`NotEqual`** | `x + offset ≠ y` — со смещением, чтобы выражать диагонали без вспомогательных переменных. |
| **`DomainStore`** | Области значений с журналом удалений и откатом. |
| **`CpSolver`** | Распространение до неподвижной точки и поиск в глубину. |

```csharp
using AI.Solvers.Constraints.Cp;

var model = new CpModel("Восемь ферзей");
IntVariable[] queens = model.AddVariables("q", 8, 0, 7);

model.Add(new AllDifferent(queens));

for (int i = 0; i < 8; i++)
    for (int j = i + 1; j < 8; j++)
    {
        model.Add(new NotEqual(queens[i], queens[j], j - i));
        model.Add(new NotEqual(queens[i], queens[j], i - j));
    }

CpSolution all = CpSolver.SolveAll(model);   // 92 решения
```

Ветвление идёт по переменной с наименьшей областью — правило первой неудачи. Это не вопрос
вкуса: чем меньше значений осталось, тем раньше вскроется противоречие и тем меньше окажется
бесплодное поддерево. Откат сделан журналом удалений, а не копированием областей на каждом
узле.

`AllDifferent` фильтрует в два шага: вычёркивает значение зафиксированной переменной у
остальных и проверяет условие Холла — если k переменных умещаются в объединение из менее
чем k значений, решения нет. Полная фильтрация по паросочетаниям не делается: она дороже,
а на задачах вроде ферзей и судоку выигрыш от неё невелик.

## Проверка

Ответы сверяются с тем, что известно независимо от реализации:

* число решений задачи о ферзях для досок от 4×4 до 8×8 — 2, 10, 4, 40, 92;
* судоку с известным решением;
* принцип Дирихле: n + 1 голубей в n ящиков невыполнимо при любом n;
* раскраска цикла из пяти вершин: трёх цветов достаточно, двух нет — и в булевой,
  и в целочисленной постановке;
* случайные двухлитеральные формулы: ответ общего решателя совпадает с `TwoSAT`;
* каждая найденная подстановка проверяется методом `SatSolution.Verify`, то есть
  независимо от того, как решатель к ней пришёл.

```bash
dotnet test Tests/unit/AIFramework.UnitTests/AIFramework.UnitTests.csproj -c Release
```
