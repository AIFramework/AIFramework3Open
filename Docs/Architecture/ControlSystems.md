# Системы автоматического управления (САУ) — `AI.ControlSystems`

Сборка **`AI.ControlSystems`** (`AI.ControlSystems.dll`, **.NET 9.0**) — линейный анализ и синтез,
оценивание состояния, оптимальное управление с ограничениями, скользящие режимы, адаптивное
управление, PID и идентификация; плюс учебные сценарии моделирования объекта и обратной модели
на регрессии `AI.ML`. Зависимости: **`AI`**, **`AI.ML`**, **`AI.ClassicMath`** (собственные
значения, LU, Холецкий, SVD), **`AI.Solvers.Optimization`** (квадратичное программирование для MPC).

---

## Состав

Пространства имён:

- **`AI.ControlSystems.Linear`** — дискретная LTI-модель, точный ZOH и шум по Ван Лоану,
  управляемость и наблюдаемость, полюса, уравнения Риккати и Ляпунова, размещение полюсов.
- **`AI.ControlSystems.Observers`** — наблюдатель Люенбергера, фильтр Калмана (в том числе
  установившийся), расширенный фильтр Калмана.
- **`AI.ControlSystems.Optimal`** — LQR, синтез LQG, MPC с ограничениями, MPC конечного горизонта
  без ограничений.
- **`AI.ControlSystems.Nonlinear`** — скользящий режим: скалярный, по состоянию, super-twisting.
- **`AI.ControlSystems.Adaptive`** — MRAC первого порядка и по состоянию.
- **`AI.ControlSystems.Pid`** — PID, векторный PID, IMC-настройка PI, ограничение скорости выхода.
- **`AI.ControlSystems.Identification`** — рекурсивный МНК.
- **`AI.ControlSystems.ComplexObjectControl.Base`** — модели объекта и данных для обучения.

## Как устроено

**Общее вынесено туда, где ему место.** Собственные значения несимметричной матрицы
(балансировка, форма Хессенберга, QR-итерации Фрэнсиса с двойным сдвигом) лежат в
`AI.ClassicMath.MatrixUtils.Eigen.General`: это общая линейная алгебра, а не часть теории
управления. Квадратичное программирование — в `AI.Solvers.Optimization` (`QpSolver`) рядом с
линейным. Разложения LU, Холецкого и SVD уже были в `AI.ClassicMath` и используются как есть.

**Обращение матриц.** Прежний `Matrix.GetInvertMatrix` из ядра считал определитель без перестановки
строк и сравнивал его с абсолютным порогом $10^{-10}$, так что ковариация измерений $10^{-6} I$
размера 2×2 и матрица управляемости с шагом 0.1 для него были «вырождены». Ядро исправлено: LU с
выбором главного элемента и относительный порог $n\varepsilon\|A\|_\infty$. Внутри сборки все
обращения идут через `ControlLinAlg.Inverse`, который теперь просто вызывает его.

**Риккати.** DARE решается методом удвоения, сохраняющим структуру: сходимость квадратичная,
а не линейная, как у прямой итерации. После решения проверяются невязка и спектральный радиус
$A - BK$. Нестабилизируемая пара даёт исключение с причиной, а не усиление, которое не стабилизирует.

**MPC.** Прогноз подставляется в стоимость, и остаётся квадратичная задача от плана управлений.
Её постоянная часть собирается один раз. Ограничения на состояние по умолчанию мягкие: одна
переменная ослабления на ограниченную координату, точный штраф $\rho\varepsilon^2 + \rho\varepsilon$.
Прошлый план, сдвинутый на шаг, служит тёплым стартом, а при неудаче решателя — резервным
управлением. Терминальный вес по умолчанию равен решению Риккати, поэтому без активных
ограничений MPC совпадает с LQR на любом горизонте.

**LQG.** Установившийся фильтр — двойственное DARE. Ожидаемая стоимость
$\mathrm{tr}(PW) + \mathrm{tr}(K^\top(R + B^\top PB)K\Sigma)$ и полюса
$\mathrm{eig}(A - BK) \cup \mathrm{eig}(A - LCA)$ считаются при синтезе.

**Дискретизация.** $\exp\bigl(\begin{smallmatrix} A & B \\ 0 & 0 \end{smallmatrix}\Delta t\bigr)$
даёт $A_d$ и $B_d$ сразу. Экспонента — масштабированием по бесконечной норме и возведением в квадрат.

Умножение «матрица × вектор-столбец» в линейных классах выполняется в соглашении классической
алгебры — в отличие от части операторов `Matrix`/`Vector` в `AI.DataStructs`, где вектор хранится
строкой.

## Что было номинальным и что исправлено

| Было | Стало |
|------|-------|
| MPC без ограничений — по сути конечный LQR | `ModelPredictiveController`: пределы управления, скорости и состояния, мягкие ограничения, тёплый старт, резервный план |
| MRAC: один коэффициент $u = \theta r$, MIT-правило с обратным знаком | Два коэффициента и закон по Ляпунову; MRAC по состоянию |
| Скалярный скользящий режим с обратным знаком | Знак исправлен; добавлены закон по состоянию и super-twisting |
| LQG — склейка готовых $K$ и фильтра | `LqgRegulator.Design`: установившийся фильтр, ожидаемая стоимость, полюса по разделению |
| LQR — итерации без проверки сходимости и стабилизации | Метод удвоения, проверка невязки и устойчивости |
| ZOH рядом для интеграла с масштабом по элементу — теряет точность на жёстких системах | Экспонента расширенной матрицы |
| Аккерман принимал неуправляемую пару, но отвергал управляемую малого масштаба | Ранг по SVD, обращение через LU |
| Ни одного теста | 47 тестовых случаев |

Демо `ControlDemoRunner` (сценарий `nl_smc`) компенсировал обратный знак скользящего режима
обратным знаком объекта; после исправления регулятора он приведён к физическому объекту.

## Границы применимости

- Только дискретное время для синтеза: непрерывные модели сначала дискретизируются.
- Все матрицы плотные. Уравнения Ляпунова решаются через кронекерово произведение, порядок
  до 30 (`LyapunovEquation.MaxOrder`). MPC рассчитан на $N \cdot m$ до нескольких сотен переменных.
- У MPC нет терминального множества, поэтому выполнимость при жёстких ограничениях на состояние
  не гарантирована. Интегрального действия тоже нет.
- Аккерман — только SISO и численно плох для порядков выше 10.
- MRAC по выходу для относительной степени выше единицы и проекция коэффициентов не реализованы.
- Непрерывного уравнения Риккати (CARE), $H_\infty$ и $\mu$-синтеза нет.

## Проверка

47 тестовых случаев в `Tests/unit/AIFramework.UnitTests`. Каждая проверка опирается на
независимый ответ, а не на повторный вызов той же функции:

| Файл | Случаев | Опора |
|------|---------|-------|
| `EigenGeneralTests` | 5 | корни многочлена (сопровождающая матрица), поворот, след, след квадрата и определитель по LU, совпадение с методом Якоби |
| `QuadraticProgrammingTests` | 6 | полный перебор активных множеств на 150 задачах, условия ККТ, замкнутые формулы |
| `ControlSystemsLinearTests` | 14 | аналитический ZOH и Ван Лоан, скалярные формулы Риккати и Ляпунова, 20 000 итераций Риккати, Фаддеев — Леверье, эмпирическая ковариация ошибки Калмана, пакетный МНК |
| `ControlSystemsAdvancedTests` | 16 | MPC = LQR без ограничений, обрезанный оптимум при $N = 1$, соблюдение ограничений, собранная вручную замкнутая система LQG, Монте-Карло по стоимости, условия согласования MRAC |
| `ControlSystemsRegressionTests` | 6 | написаны через прежний API; все шесть падают на предыдущей версии и проходят на текущей |

Регрессии: жёсткий ZOH ($a = -50$, $\Delta t = 1$), LQR на нестабилизируемой паре, размещение
полюсов для управляемой системы малого масштаба, фильтр Калмана с точными датчиками, знак
скалярного скользящего режима, MRAC на неустойчивом объекте (прежняя ошибка слежения
$7.6\cdot10^{86}$).

проверкой `Tools/SnippetCheck`.

## Сборка

```bash
dotnet build src/AI.ControlSystems/AI.ControlSystems.csproj -c Release
```

**Обратная совместимость:** прежние сигнатуры сохранены (`DiscreteLqr.Solve`,
`LqgRegulator(kf, K)`, `PolePlacement.AckermannGain(A, B, coeffs)`, свойства MRAC и скользящего
режима). Изменилось поведение там, где прежнее было ошибкой: знаки скользящего режима и MRAC,
исключения на нестабилизируемых и неуправляемых парах. Типы моделирования объекта ранее
находились в пространстве имён `AI.Controls.ComplexObjectControl.Base` внутри `AICrossPlatform`;
теперь это **`AI.ControlSystems.ComplexObjectControl.Base`** в отдельной сборке.
