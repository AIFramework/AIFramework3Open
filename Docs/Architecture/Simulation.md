# Симуляция `AI.Simulation` (AI.Simulation.dll)

Сборка **`AI.Simulation`** (`AI.Simulation.dll`, **.NET 9.0**) — дискретно-событийное
моделирование, теория массового обслуживания, системная динамика, марковские процессы
принятия решений, обучение с подкреплением, агентное моделирование в пространстве и на сети,
планирование действий и планирование вычислительного эксперимента.

Зависит от ядра **`AI`** (генераторы случайных величин, статистический вывод, контракт
объяснимости), от **`AI.ClassicMath`** (интегрирование систем ОДУ) и от **`AI.Algorithms`**
(граф для сети контактов).

Модуль отвечает на вопрос «что будет, если» (имитация), «как лучше поступать» (марковские
процессы и обучение) и «что сделать, чтобы стало так» (планирование).

## Что взято готовым

| Нужное | Откуда |
|--------|--------|
| Показательные, гауссовы и гамма-величины | `AI.Statistics.RandomEngine` |
| t-интервал по серии прогонов | `AI.Statistics.StatInference.ConfidenceIntervalT` |
| Интегрирование систем ОДУ для системной динамики | `AI.MathUtils.ODE.RungeKutta` |
| Неориентированный граф для сети контактов | `AI.Algorithms.EWG.Graph` |
| Модели популяций и эпидемий на ОДУ | `AI.Biology.Populations` — здесь не повторяются, а служат эталоном для эпидемии на сети |

Календарь событий построен на `PriorityQueue` стандартной библиотеки, а не на очереди
с приоритетом из `AI.Algorithms`: та создаётся с фиксированной ёмкостью, а число событий
в модели заранее неизвестно.

Поиск плана — свой A*, а не `AStarSearch` из `AI.Algorithms`: тот работает на готовом графе
с целочисленными вершинами, а пространство состояний планировщика неявное — соседей
порождает функция переходов по мере раскрытия. Построить граф заранее значило бы перебрать
все достижимые состояния, что и обесценивает A*.

## Состав

| Область | Тип | Назначение |
|---------|-----|------------|
| События | **`SimulationEngine`** | Модельное время, календарь событий, случайные задержки, воспроизводимость по зерну. |
| События | **`Tally`**, **`TimeWeightedAccumulator`** | Среднее по наблюдениям и среднее по времени — величины разной природы. Оба умеют начинать наблюдение заново после разгона. |
| События | **`ServiceStation`** | Многоканальная система с очередью и ограниченным накопителем; классы заявок, дисциплины `QueueDiscipline`: в порядке поступления, приоритет без прерывания, приоритет с прерыванием и дообслуживанием. Статистика общая и по классам, сброс после разгона. |
| Эксперимент | **`Replications`**, **`ReplicationEstimate`** | Серия независимых прогонов, t-интервал по средним прогонов, оценка нужного числа прогонов. Результат реализует `IInterpretable`. |
| Очереди | **`QueueingTheory`** | M/M/1, M/M/c, M/M/1/K, формулы Эрланга B и C, закон Литтла, формулы Кобэма для приоритетов без прерывания и с прерыванием (M/G/1). Результат реализует `IInterpretable`. |
| Динамика | **`StockFlowModel`** | Запасы, потоки, обратные связи; интегрирование методом Рунге — Кутты. |
| Решения | **`MarkovDecisionProcess`** | Итерация по ценностям и по стратегиям, оценка стратегии, розыгрыш шага. Результат реализует `IInterpretable`. |
| Обучение | **`TemporalDifferenceLearner`** | Табличные Q-learning и SARSA по среде `IDiscreteEnvironment`; `MdpEnvironment` делает средой марковский процесс. Результат `LearningResult` реализует `IInterpretable`. |
| Агенты | **`AgentBasedModel<TWorld>`** | Каркас: агенты, среда, порядок обхода, условие остановки, сбор показателей. |
| Пространство | **`GridSpace<TAgent>`** | Решётка, тор или с краями, окрестности фон Неймана и Мура, расстояние, случайная свободная клетка. |
| Пространство | **`ContactNetwork`** | Сеть контактов на `Graph`: полный граф, кольцо, Эрдёш — Реньи, Уоттс — Строгац, Барабаши — Альберт. |
| Планирование | **`StateSpaceSearch`**, **`StripsProblem`** | A* в неявном пространстве состояний; задачи STRIPS — факты, предусловия, добавления и удаления. Результат `Plan<TState>` реализует `IInterpretable`. |

```csharp
using AI.Simulation.DiscreteEvent;
using AI.Simulation.Experiments;

// Двадцать прогонов M/M/1: разгон 500, наблюдение 5000 — и интервал для среднего ожидания
ReplicationEstimate wait = Replications.Run("Ожидание", 20, seed =>
{
    var engine = new SimulationEngine(seed);
    var station = new ServiceStation(engine) { ServiceTime = () => engine.Exponential(1.0) };

    void Arrive()
    {
        station.Arrive();
        engine.Schedule(engine.Exponential(0.5), Arrive);
    }

    engine.Schedule(engine.Exponential(0.5), Arrive);
    engine.Run(500);
    station.ResetStatistics();
    engine.Run(5_500);

    return station.Statistics().AverageWait;
});

Console.WriteLine(wait.Interpret());
```

## Почему имитация и теория проверяют друг друга

Формулы теории массового обслуживания дают точный ответ для простейшего потока
и показательного обслуживания. Имитационная модель тех же условий обязана к ним сойтись —
и это лучшая проверка, какая бывает у имитации: расхождение означает ошибку в модели,
а не в теории.

Тесты сверяют прогон M/M/1 и M/M/c с формулами по загрузке, длине очереди и времени
ожидания, систему с ограниченным накопителем — по доле отказов, а приоритетные дисциплины —
с формулами Кобэма по каждому классу. Старший класс при прерывании обязан вести себя как
отдельная система M/M/1 со своим потоком: младших для него нет.

Тот же принцип распространён на остальные части модуля:

* **Интервалы.** Интервал по серии прогонов M/M/1 накрывает теоретическое ожидание,
  а доля интервалов, накрывших истину, на сотнях серий близка к заявленным 95 %.
* **Обучение.** Стратегия, выученная Q-learning и SARSA только по разыгранным исходам,
  сверяется с точным решением того же марковского процесса итерацией по ценностям.
* **Эпидемия на сети.** Цепная модель Рида — Фроста на полном графе обязана дать ту же
  итоговую долю переболевших, что уравнение итогового размера из `AI.Biology`: полный граф
  и есть допущение «все встречаются со всеми», на котором стоят модели на ОДУ.
* **Планирование.** Аномалия Зюссмана решается планом ровно из трёх действий: задача
  известна тем, что наивное разбиение на подцели даёт план длиннее.

Главный содержательный вывод формул важнее самих чисел: длина очереди растёт как ρ/(1−ρ).
При загрузке 0.5 в системе одна заявка, при 0.9 — девять, при 0.99 — девяносто девять.
Планировать мощность впритык нельзя не из осторожности, а из-за вида этой зависимости.

## Тонкости, которые легко пропустить

**Два разных средних.** Средняя длина очереди — это среднее по времени, а не по заявкам:
очередь из десяти, простоявшая секунду, весит меньше очереди из двух, простоявшей час.
Для этого в модуле два разных накопителя, и путать их нельзя.

**Интервал — по прогонам, а не по заявкам.** Соседние заявки одного прогона зависимы:
очередь, выросшая у одной, достаётся и следующей. Интервал по наблюдениям внутри прогона
вышел бы в разы уже истинного, поэтому `Replications` строит его по средним независимых
прогонов.

**Разгонный участок.** Модель стартует пустой и приходит к установившемуся режиму не сразу.
`ServiceStation.ResetStatistics` забывает накопленное, но оставляет заявки в системе:
очередь, выросшая за разгон, реальна. Где кончается разгон, решает исследователь; тест
показывает, что без отбрасывания средняя очередь при высокой загрузке заметно занижена.

**Прерывание без отмены событий.** Календарь не отменяет запланированное, поэтому
у прерванной заявки растёт номер попытки, и её прежнее событие окончания, сработав, видит
чужой номер и ничего не делает. Остаток работы сохраняется — дисциплина с дообслуживанием.

**Порядок одновременных событий.** События с равным временем выполняются в порядке
постановки в календарь. Без этого правила результат зависел бы от внутреннего устройства
очереди и не воспроизводился.

**Порядок обхода агентов** — часть модели, а не деталь реализации. При последовательном
обходе первые в списке систематически получают преимущество, и результат оказывается
артефактом нумерации; поэтому по умолчанию порядок перемешивается на каждом шаге.

**Край решётки.** Без замыкания в тор у клеток на краю меньше соседей, и в моделях, где важна
плотность контактов, край даёт систематический перекос. На узком торе разные сдвиги приводят
в одну клетку, и соседей там меньше, чем в окрестности, — они не дублируются.

**Шаг обучения.** Шаг для пары «состояние — действие» убывает как `1/(1+n)^ω` при
`0.5 < ω ≤ 1` — это условия Роббинса — Монро, без которых сходимости нет. Исследование
убывает к нулю, но так, что каждая пара испытывается бесконечно часто.

**Допустимость эвристики STRIPS.** Простой счёт невыполненных целей переоценивает остаток
пути, если одно действие закрывает сразу несколько целей. Поэтому он делится на наибольшее
число целей, закрываемых одним действием, и умножается на наименьшую стоимость — тогда план
гарантированно оптимален.

## Границы применимости

Интервалы строятся методом независимых прогонов. Метода пакетных средних по одному длинному
прогону и автоматического определения конца разгона нет: разгон задаёт исследователь.

Формулы для приоритетов — одноканальные (M/G/1). Для нескольких приборов с приоритетами
замкнутых формул нет, и там ответ даёт только имитация. Перехода заявок между очередями
и сетей обслуживания нет.

Марковские процессы и обучение табличные: пространство состояний перечисляется целиком,
поэтому речь идёт о сотнях и тысячах состояний, а не о миллионах. Приближения ценности
нейросетью здесь нет — для больших пространств это отдельная задача.

Пространство агентов — решётка и граф. Непрерывного пространства с поиском ближайших соседей
нет. Эпидемия на сети дана в тестах как пример сборки, а не как готовая модель: готовые
модели эпидемий живут в `AI.Biology`.

Планировщик — классический STRIPS с полной информацией и детерминированными действиями.
Иерархических задач, временных ограничений и неопределённости исхода нет; для недетерминированных
действий подходят марковские процессы этого же модуля.
