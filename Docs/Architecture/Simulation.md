# Симуляция `AI.Simulation` (AI.Simulation.dll)

Сборка **`AI.Simulation`** (`AI.Simulation.dll`, **.NET 9.0**) — дискретно-событийное
моделирование, теория массового обслуживания, системная динамика, марковские процессы
принятия решений и каркас агентного моделирования.

Зависит от ядра **`AI`** (генераторы случайных величин, контракт объяснимости) и от
**`AI.ClassicMath`** (интегрирование систем ОДУ).

Этим модулем закрывается последний пункт дорожной карты: до него репозиторий умел считать,
что есть, но не умел прогонять вперёд — отвечать на вопрос «что будет, если».

---

## Что взято готовым

| Нужное | Откуда |
|--------|--------|
| Показательные, гауссовы и гамма-величины | `AI.Statistics.RandomEngine` |
| Интегрирование систем ОДУ для системной динамики | `AI.MathUtils.ODE.RungeKutta` |
| Модели популяций и эпидемий на ОДУ | `AI.Biology.Populations` — здесь не повторяются |

Календарь событий построен на `PriorityQueue` стандартной библиотеки, а не на очереди
с приоритетом из `AI.Algorithms`: та создаётся с фиксированной ёмкостью, а число событий
в модели заранее неизвестно. Это осознанный выбор, а не недосмотр.

---

## Состав

| Область | Тип | Назначение |
|---------|-----|------------|
| События | **`SimulationEngine`** | Модельное время, календарь событий, случайные задержки, воспроизводимость по зерну. |
| События | **`Tally`**, **`TimeWeightedAccumulator`** | Среднее по наблюдениям и среднее по времени — величины разной природы. |
| События | **`ServiceStation`** | Многоканальная система с очередью и ограниченным накопителем; статистика реализует `IInterpretable`. |
| Очереди | **`QueueingTheory`** | M/M/1, M/M/c, M/M/1/K, формулы Эрланга B и C, закон Литтла. Результат реализует `IInterpretable`. |
| Динамика | **`StockFlowModel`** | Запасы, потоки, обратные связи; интегрирование методом Рунге — Кутты. |
| Решения | **`MarkovDecisionProcess`** | Итерация по ценностям и по стратегиям, оценка стратегии. Результат реализует `IInterpretable`. |
| Агенты | **`AgentBasedModel<TWorld>`** | Каркас: агенты, среда, порядок обхода, условие остановки, сбор показателей. |

```csharp
using AI.Simulation.DiscreteEvent;

var engine = new SimulationEngine(seed: 42);
var station = new ServiceStation(engine, servers: 2)
{
    ServiceTime = () => engine.Exponential(1.0),
};

void Arrive()
{
    station.Arrive();
    engine.Schedule(engine.Exponential(1.6), Arrive);
}

engine.Schedule(engine.Exponential(1.6), Arrive);
engine.Run(100_000);

Console.WriteLine(station.Statistics().Interpret());
```

## Почему имитация и теория проверяют друг друга

Формулы теории массового обслуживания дают точный ответ для простейшего потока
и показательного обслуживания. Имитационная модель тех же условий обязана к ним сойтись —
и это лучшая проверка, какая бывает у имитации: расхождение означает ошибку в модели,
а не в теории.

Тесты сверяют прогон M/M/1 и M/M/c с формулами по загрузке, длине очереди и времени
ожидания, а систему с ограниченным накопителем — по доле отказов. Обратное тоже верно:
если формула применена не к тем условиям, имитация это покажет.

Главный содержательный вывод формул важнее самих чисел: длина очереди растёт как ρ/(1−ρ).
При загрузке 0.5 в системе одна заявка, при 0.9 — девять, при 0.99 — девяносто девять.
Планировать мощность впритык нельзя не из осторожности, а из-за вида этой зависимости.

## Тонкости, которые легко пропустить

**Два разных средних.** Средняя длина очереди — это среднее по времени, а не по заявкам:
очередь из десяти, простоявшая секунду, весит меньше очереди из двух, простоявшей час.
Для этого в модуле два разных накопителя, и путать их нельзя.

**Порядок одновременных событий.** События с равным временем выполняются в порядке
постановки в календарь. Без этого правила результат зависел бы от внутреннего устройства
очереди и не воспроизводился.

**Порядок обхода агентов** — часть модели, а не деталь реализации. При последовательном
обходе первые в списке систематически получают преимущество, и результат оказывается
артефактом нумерации; поэтому по умолчанию порядок перемешивается на каждом шаге.

**Разгонный участок.** Модель стартует пустой и приходит к установившемуся режиму не сразу;
на коротких прогонах начальный участок смещает средние и его отбрасывают. Модуль об этом
предупреждает в разборе результата, но сам не отбрасывает: где кончается разгон, решает
исследователь.

## Границы применимости

Показатели одного прогона содержат случайную погрешность, и доверительных интервалов модуль
не строит: для этого нужно несколько прогонов с разными зёрнами, а планирование
вычислительного эксперимента остаётся за исследователем.

Дисциплина обслуживания только одна — в порядке поступления. Приоритетов, прерываний
и перехода между очередями нет.

Марковские процессы табличные: пространство состояний перечисляется целиком, поэтому
речь идёт о сотнях и тысячах состояний, а не о миллионах. Вероятности переходов и награды
считаются известными; когда они добываются взаимодействием со средой, нужны методы обучения
с подкреплением.

Агентный каркас не содержит ни пространства, ни сети контактов — только обход агентов
и среду, которую задаёт пользователь. Это сделано намеренно: сетка, граф и непрерывное
пространство описываются по-разному, и навязывать одно из них в каркасе неправильно.
