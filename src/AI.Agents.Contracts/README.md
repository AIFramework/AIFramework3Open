# AI.Agents.Contracts

Общие контракты агентного слоя: инструмент, движок, запуск, запись агента, порт модели и подтверждение. Сборка содержит только типы и чистые помощники без поведения хоста. Реализации (циклы, клиенты моделей, наборы инструментов, хранилища запусков) живут в других сборках и ссылаются сюда.

Статус предварительный: версия пакета с суффиксом предварительной версии (сейчас `0.1.0-preview.1`), API может меняться по решению владельца без мажорной версии, пока стабильность не объявлена. `.\build.ps1 -Pack` собирает его в `artifacts/nuget`, а `build/nuget-push.ps1` выкладывает пакеты с суффиксом предварительной версии только с явным флагом `-IncludePreview` (признак — суффикс, а не нулевой старший номер). Обычные пакеты от него не зависят: `AI.LLM` на контракты не ссылается (храповик `RunContractTests.AiLlm_DoesNotReferenceAgentPackages`). Снимок API проверяется наравне с остальными сборками: `Tests/unit/PublicApi.Tests/Snapshots/AI.Agents.Contracts.txt`.

## Правила

1. **Только BCL.** В проекте нет ни одного `PackageReference`, `ProjectReference` и `FrameworkReference`; `System.Text.Json` входит в общий фреймворк. Платформа `net9.0`, `Nullable` включен. Тест читает csproj и ссылки собранной сборки.
2. **Члены `required init`, никаких позиционных записей.** Обязательное поле отмечено `required`: без него запись не компилируется и не читается из JSON. Новые поля добавляются необязательными, поэтому двоичная совместимость не ломается. Открытых конструкторов с несколькими параметрами нет.
3. **Значений по умолчанию, которые молча подменяют выбор, нет.** Необязательный член допускает `null`, и смысл `null` описан в XML-документации. Исключение составляют признаки `bool`, где `false` означает «нет».
4. **Ноль каждого перечисления равен `Unknown`.** Перечисления пишутся в JSON именем значения: конвертер объявлен на самом перечислении, вызывающему ничего настраивать не нужно. Число и неизвестное имя при чтении дают `JsonException` со списком допустимых имен.
5. **`ToolAction.Unknown` означает `Irreversible`.** Трактовку дает одно место, `ToolActions.Effective`. Гейт спрашивает вид до вызова через `ITool.Classify(ToolCall)`: по умолчанию это `Spec.Action`, а инструмент, у которого вид зависит от аргументов, отвечает точнее. `ToolResult.Raised` нужен только журналу.
6. **Имя инструмента проверяется при создании `ToolSpec`.** Шаблон `^[a-zA-Z0-9_-]{1,64}$`, сравнение с учетом регистра (`ToolSpec.NameComparer`). Схема параметров обязана быть объектом JSON.
7. **Итог движка один.** `IEngine.RunAsync` возвращает только поток событий, последним всегда идет `EngineEvent.Finished` с `EngineResult`. Сбой, исчерпание бюджета и вопрос человеку приходят итогом со статусом, а не исключением. `Incomplete` отличается и от `Failed`, и от `Done`.
8. **Одно понятие хранится в одном месте.** Срок живет только в `IRunBudget`, у `EngineInput` поля срока нет. Код причины остановки (`StopCode`) общий для бюджета и итога движка. Плательщика в контракте движка нет, он приходит в реализацию `IModelPort`.
9. **Каждый тип объявлен один раз.** Имена верхнеуровневых типов контрактов не повторяются в других сборках `src` и `Tools`. Исключения записаны долгом в `OwnershipTests.NameDebt` (`ToolResult` и `ToolCall` из `AI.LLM`, `LlmAnswer` из Атласа). Список только сокращается, а в адаптерах для этих имен используются псевдонимы `using`. Совпадение без учета регистра тоже запрещено; похожие имена допустимы: `LLMStreamChunk` из `AI.LLM` и `LlmChunk` контрактов — разные слова.
10. **Каждый публичный неабстрактный тип проходит круг через JSON.** Образец лежит в `Tests/unit/AI.Agents.Contracts.Tests/ContractSamples.cs`, и первый образец заполняет все свойства. Новый тип без образца роняет тест. Если свойства взаимоисключающие (`AgentInstructions.Key` и `Text`), они записаны в `ContractSamples.Exclusive`: первый образец заполняет одно, следующие — остальные. Исключение составляет `EngineInput`: он несет порты хоста, а его данные (`EngineTask`, `EngineContext`, состояние) проходят круг отдельно.
11. **«Повтор безопасен» — ось, отдельная от вида действия.** `ToolSpec.Idempotency` (`ToolIdempotency?`): `null` и `Unknown` значат «не объявлено» и трактуются как `NotIdempotent` одним помощником `ToolIdempotencies.Effective`. Подробности — раздел «Повтор безопасен».
12. **Опасность, видная только по состоянию мира, объявляется итогом.** Если вид действия решают не аргументы, а состояние мира (кнопка на странице браузера оказалась оплатой), инструмент не исполняет действие и сам возвращает `ToolStatus.AwaitsUser` с `Question`: `Kind = Confirm`, `Action` (обычно `Irreversible`), `Target` и сумма в тексте вопроса. `ITool.Classify` не меняется и остается синхронным: он видит только аргументы. Общий гейт такой итог только передает и записывает.

## Место в источнике

`Citation.Location` (`SourceLocation?`) собирает место цитаты в источнике в одну запись:

| Поле | Тип | Смысл |
|---|---|---|
| `Path` | `IReadOnlyList<LocationSegment>?` | путь от документа к вложенному объекту, от внешнего к внутреннему: «слайд 3» → «картинка 2» |
| `Page` | `int?` | номер страницы, с 1 |
| `Lines` | `LineRange?` | строки `Start`…`End` включительно, с 1 |
| `Time` | `TimeInterval?` | отрезок записи `Start`…`End` (`TimeSpan` от начала) |
| `Rect` | `RelativeRect?` | область `X`, `Y`, `Width`, `Height` в долях 0..1, начало в левом верхнем углу |

Все поля необязательны. **Страница, строки, время и прямоугольник относятся к последнему сегменту пути; без пути — к самому документу.**

Сегмент (`LocationSegment`) — это вид (`Kind`, открытый набор строк; известные значения в `LocationSegment.Kinds`: `slide`, `image`, `sheet`, `table`, `page`, `attachment`), номер `Index` (с 1, как видит человек) и непрозрачный `Id`. Нужно хотя бы одно из `Index` и `Id`.

Проверки идут при создании и при чтении JSON: конец строк или времени раньше начала, отрицательное время, доли вне 0..1 и область за краем (`X + Width > 1`, `Y + Height > 1`) отвергаются в любом порядке полей. Сегмент без адреса отвергается при чтении и при записи в `Path`.

Место дополняет цитату, а не заменяет ее: цитата с `Prefix` и `Suffix` находит фрагмент и после правки источника, место быстро открывает нужный слайд или секунду записи. Поля `At`, `Start` и `End` остались в `Citation`: это позиции в тексте ответа, а не в источнике.

## Поток ответа модели

`IModelPort.StreamAsync(ModelAsk, CancellationToken)` отдает `IAsyncEnumerable<LlmChunk>`:

- `LlmChunk.Text` и `LlmChunk.Reasoning` — фрагменты ответа и рассуждения, только для показа;
- `LlmChunk.Final` — итог (`LlmAnswer`) с полным текстом, вызовами инструментов, статусом и расходом.

Правило то же, что у `IEngine`: последний кадр всегда `Final`, и он один. Полный ответ берется только из `Final.Answer`, фрагменты склеивать не нужно. Сбой провайдера приходит итогом со статусом `Failed`, отмена токеном прерывает поток исключением `OperationCanceledException`.

Метод имеет реализацию по умолчанию: вызывает `AskAsync` и отдает один кадр `Final`, без имитации потока фрагментами. Поэтому добавление метода не ломает реализующих. Порт с настоящим потоком переопределяет метод и сообщает об этом обязательным признаком `ModelCapabilities.Streaming`; при реализации по умолчанию он `false`.

## Звук на входе

`MessagePart.Audio` — звук в сообщении модели: `ContentType` обязателен, `Origin` обязателен, как у других частей, а звук приходит байтами (`Data`) или адресом (`Uri`), ровно одно из двух. Байты и адрес вместе отвергаются при создании, через `with` и при чтении JSON. Если не задано ни того, ни другого, часть отвергается при чтении JSON и при записи в `ModelMessage.Parts`. Принимает ли модель звук, порт сообщает обязательным признаком `ModelCapabilities.Audio`.

## Запись агента

Агент — это данные, а не класс: `AgentDefinition` описывает его, исполняет запись хост. Интерфейса `IAgent` нет.

| Поле | Обязательно | Смысл |
|---|---|---|
| `Id`, `Version` | да | постоянный идентификатор и версия записи с 1; `ToRef()` дает `AgentRef` на эту версию |
| `Name`, `Role` | да | имя для показа и кто это, одной фразой |
| `Instructions` | да | `AgentInstructions`: ключ промпта (`Key`) или текст (`Text`), ровно одно из двух |
| `About` | нет | тот же `About`, что у `ToolSpec`; `About.Examples` — примеры задач, по которым выбирают исполнителя |
| `Tools` | нет | имена инструментов и групп; `null` — без инструментов |
| `Engine` | нет | `EngineChoice`: `Key` и `Options` (`JsonObject?`); `null` — движок по умолчанию у хоста |
| `Model` | нет | `ModelRole`, а не имя модели; `null` — роли по шагам выбирает движок |
| `Limits` | нет | `AgentLimits`: `Steps`, `Cost` (валюту задает хост, контракт ее не знает), `Duration`; хост сводит их со своими рамками, побеждает меньший |
| `Inputs` | нет | `InputField[]`, что спросить у человека перед началом |
| `Agents` | нет | `AgentRef[]`, кого агент может позвать |
| `Output` | нет | виды итога строками |
| `Acceptance` | нет | ключ набора проверок приемки |

Неизвестный хосту ключ движка — явный отказ хоста, без подмены другим движком.

Правило «ровно одно» для инструкций проверяется при создании, а не отдельным методом: запись, которую нельзя исполнить, не должна дойти до хоста. Ключ и текст вместе отвергаются сразу, в любом порядке задания. Если не задано ни того, ни другого, запись отвергается при чтении JSON и при присвоении `AgentDefinition.Instructions`. Создавать удобнее через `AgentInstructions.FromKey` и `FromText`.

В запись не входят:

- исполнитель хода, состояние и хранилище запусков: это работа хоста и движка, у одной записи много запусков;
- публикация (цена, видимость, витрина) и примеры готовых работ: это свойства витрины, а не агента;
- рамки хоста (тариф, плательщик, разрешенные движки): одна запись исполняется у разных хостов с разными рамками;
- отдельное поле примеров: примеры задач лежат в `About.Examples`;
- срок: у агента есть только длительность `AgentLimits.Duration`, момент окончания живет в `IRunBudget.Deadline`.

## Повтор безопасен

`ToolSpec.Idempotency` отвечает на вопрос «можно ли повторить вызов с теми же аргументами». Это не вид действия: вид говорит, можно ли действие отменить, а эта ось — сделает ли второй вызов что-то еще раз.

| Значение | Смысл | Пример |
|---|---|---|
| `Unknown` (и `null`) | не объявлено; трактуется как `NotIdempotent` | инструмент чужого сервера без подсказок |
| `Idempotent` | повтор безопасен всегда | удалить запись: идемпотентно, но необратимо (`Irreversible`) |
| `WithKey` | безопасен только с тем же ключом эффекта: инструмент передает `ToolCall.EffectKey` внешнему сервису (например, заголовком `Idempotency-Key`), и сервис второй раз не исполняет | оплата через сервис, который принимает ключ |
| `NotIdempotent` | повтор делает действие еще раз | отправить письмо, создать запись запросом POST, оплатить без ключа |

Ключ эффекта (`ToolCall.EffectKey`) назначает фреймворк перед вызовом, в одном месте (`EffectKeys` в `AI.Agents.Interop`): детерминированно из идентификатора запуска, имени инструмента и канонизированных аргументов. Повтор вызова с ключом, который уже исполнен успешно, инструмент не исполняет: возвращается сохраненный итог. Вызов `Unknown` и `NotIdempotent` после сбоя или обрыва сам не повторяется, `WithKey` повторяется только с тем же ключом. Правила исполняет гейт эффектов `AI.Agents.Interop`.

Граница до шага Ф6: защита от повтора действует внутри одного запуска. Между запусками она заработает, когда движок начнет принимать `EngineInput.State`, а продолжение получит журнал `RunState.Effects`.

## Запуск

Запуск живет дольше прогона движка: стоит в очереди, ждет человека, продолжается, может потеряться. Поэтому у него своя запись и свой набор состояний (`RunStatus`: `Queued`, `Running`, `AwaitsUser`, `Done`, `Incomplete`, `Failed`, `Cancelled`, `Lost`), а `EngineStatus` описывает только один прогон. Пространство отдельное (`Runs`), а не `Engines`: запуск принадлежит хосту, а не движку, и один запуск переживает несколько прогонов и даже смену движка.

| Поле `RunState` | Обязательно | Смысл |
|---|---|---|
| `Id` | да | идентификатор запуска, тот же, что `EngineInput.RunId` |
| `Agent` | да | `AgentRef` с версией: продолжение идет на той же версии записи |
| `Task` | да | `EngineTask`: без задачи продолжать нечего |
| `Status` | да | `RunStatus` |
| `Updated` | да | время последнего изменения; по нему хост находит потерянные запуски |
| `EngineState` | нет | `EngineResult.State` для продолжения; `null` — только начать заново |
| `Question` | нет | вопрос, на котором стоит запуск при `AwaitsUser` |
| `Effects` | нет | журнал эффектов: `EffectRecord` (ключ, инструмент, `ToolResult`) в порядке начала вызовов |

Запись журнала появляется до вызова с итогом `ToolStatus.Unknown` и заменяется итогом после. Поэтому у потерянного запуска запись `Unknown` значит «действие могло состояться». Отдельной базы во фреймворке нет: журнал едет в `RunState` и хранится через `IRunStore` продукта.

`IRunStore` — порт с тремя методами: `SaveAsync` (создать или заменить), `GetAsync` (по идентификатору, `null` — нет такого) и `ListAsync(RunStatus)`. Реализацию (файл, база, память) дает продукт; совместная запись одного запуска двумя исполнителями — забота реализации.

## Канал к человеку

`IHumanChannel.AskAsync(Question, CancellationToken)` возвращает `Answer`. Это временная синхронная реализация `AwaitsUser` для хостов в одном процессе: вопрос задается и ответ ждется внутри вызова инструмента. Его заменит продолжение запуска с места: итог `EngineStatus.AwaitsUser`, сохранение `RunState` через `IRunStore` и новый прогон с ответом в `EngineTask.Answer`. Тогда хосты переходят на паузу по одному.

## Чего в форме пока нет

Решений по этим полям еще нет, поэтому членов не заведено. Место, где они понадобятся, известно:

- подвид необратимого действия (оплата, публикация, регистрация, выгрузка) — рядом с `ToolSpec.Action` и `Question.Action`;
- сумма и валюта — в `Question` (сейчас сумма пишется в текст вопроса) и в `ModelUsage.Cost`, `AgentLimits.Cost`;
- куда уходит результат (Egress) и схема результата — в `ToolSpec`;
- секретный параметр — пометка в схеме параметров `ToolSpec.Parameters`;
- предмет согласия (Preview) — в `Question`; область ответа (Scope: раз, запуск, всегда) — в `Answer`.

## Как добавить член или тип

- Новый член: `init` с `null` по умолчанию и описанием смысла `null`, либо `required`, если без него контракт теряет смысл. Обновить первый образец типа в `ContractSamples.cs`.
- Новый тип: запись с членами `required init`, XML-документация на русском, образец в `ContractSamples.All`. Для наследника полиморфной записи нужна строка `[JsonDerivedType]` на базовом типе.
- Новое перечисление: `Unknown = 0` и атрибут `[JsonConverter(typeof(StrictEnumConverter<T>))]`.
- После изменения обновить снимок API только этой сборки:

```powershell
$env:AI_PUBLIC_API_UPDATE = '1'
dotnet test Tests/unit/PublicApi.Tests -c Release --filter "DisplayName~AI.Agents.Contracts"
Remove-Item Env:AI_PUBLIC_API_UPDATE
```

## Что дальше

Контракты использует только `AI.Agents.Interop` (адаптеры старых типов `AI.LLM`, гейт эффектов, движки `react` и `plan`); `AI.LLM` на них не ссылается, и его поведение не изменилось. Следующие шаги идут отдельными изменениями:

1. Порты в `ReActEngine`: `WithModel(IModelPort)`, `WithTools(IToolSet)`, `WithBudget(IRunBudget)` с проверкой токенов и денег на каждом вызове модели (Ф5). Ссылку `AI.LLM` → контракты владелец вернет к 1.0 контрактов или к Ф5 отдельным решением.
2. Продолжение с места (Ф6): состояние на выходе и входе движка, журнал эффектов прошлого прогона в гейте, пауза вместо `IHumanChannel`.
3. Готовые реализации для внешнего пользователя: набор инструментов из списка, бюджет по числу шагов, хранилище запусков в памяти. Готовый набор не исполняет `Irreversible` без подтверждения.
4. Поля из раздела «Чего в форме пока нет» — по решениям владельца.
