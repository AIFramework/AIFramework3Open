# Память: `AI.Agents.Contracts.Memory`

Контракт памяти агента: один маленький порт `IMemoryPort` и типы, которые через него проходят. Здесь нет хранилища, правил склейки, отбора и экранов. Все это дает реализация, а фреймворк фиксирует только форму, общую для всех реализаций.

## Что это

Память хранит то, что владелец сказал о конкретных вещах (людях, машинах, проектах) и что надо помнить дольше одного ответа. У порта два метода:

- `WriteAsync(MemoryWrite)` записывает эпизод. Если явных изменений нет (`Changes = null`), реализация сама извлекает факты из текста эпизода. Если изменения есть, она применяет их. В той же записи можно снять эпизоды (`Withdraw`).
- `ViewAsync(MemoryAsk)` возвращает память под задачу в пределах бюджета: профиль (всегда), фокус по задаче, имена остальных объектов и след отбора для журнала хода.

К памяти через этот порт ходят все: ход агента, правка человеком, одобрение предложения, дизлайк, импорт и RAG. Отдельного порта `IUserMemory` для RAG нет, он вызывает `ViewAsync` с малым бюджетом.

## Типы

| Тип | Назначение |
|---|---|
| `IMemoryPort` | порт: `WriteAsync`, `ViewAsync` |
| `MemoryScope` | область: владелец, проект, чат; ставит хост, а не модель |
| `MemoryEpisode`, `MemoryActor` | первоисточник записи: кто, когда, текст, что ход прочитал (`Read`, список `Citation`) |
| `MemoryWrite`, `MemoryChange`, `MemoryOp` | запись: эпизод, явные изменения (`Add`, `Revise`, `Confirm`, `Retire`), снятые эпизоды |
| `MemoryObject` | объект: устойчивый `Id` (не из имени), `Name`, один вид `Kind` из графа или `null` |
| `MemoryFact`, `ValueSource` | факт как свойство объекта: значение, происхождение (`Said`, `Document`, `Kind`, `Derived`), время мира `ValidFrom`/`ValidTo`, время записи `Recorded`, опоры, посылки, цитата |
| `MemoryWriteResult`, `MemoryOutcome`, `MemoryVerdict` | итог записи: исход каждого изменения (`Written`, `Revised`, `Confirmed`, `Proposed`, `Archived`, `Rejected`) с причиной |
| `MemoryAsk`, `MemoryView`, `MemoryPick` | запрос среза с бюджетом и сам срез: `Profile`, `Focus`, `Others`, `Trace` |
| `MemoryStatus` | `Ok`, `Partial`, `Failed`: сбой приходит статусом, а не исключением и не пустым ответом |

## Правила формы

1. **Один набор операций записи.** `Add` добавляет факт. Повтор существующего факта не создает новую строку: реализация отвечает `Confirmed` и добавляет эпизод в опоры. `Revise` закрывает старый факт сроком и записывает новый. `Retire` закрывает срок с причиной. Снятие эпизода (`Withdraw`) снимает его опоры, и факт без опор закрывается.
2. **Устаревшее закрывается сроком, а не удаляется.** Живой факт тот, у которого `ValidTo` пуст или в будущем. Время мира (`ValidFrom`, `ValidTo`, даты) отделено от времени записи (`Recorded`).
3. **Происхождение у каждого значения.** У сказанного есть цитата (`Quote`), у факта есть эпизоды-опоры (`Episodes`), у вывода есть посылки (`Premises`). Происхождение определяет код по структуре хода, модель только предлагает факт.
4. **Каждая запись возвращает исход с причиной.** Отклоненный секрет, содержимое документа, полный слой и неполное изменение видны в журнале хода исходом `Rejected` с `Reason`, а не строкой отладки.
5. **Бюджет постоянный.** `MemoryAsk.Budget` задает токены на всю память хода и не растет вместе с числом фактов. Остальное приходит в `Others` только именами.
6. **Область ставит хост.** `MemoryScope` лежит только в запросах порта (`MemoryWrite`, `MemoryAsk`), а не в факте или эпизоде, которые предлагает модель. Это проверяет тест `MemoryContractTests.Scope_LivesOnlyInRequests`.
7. **Ссылка на память в ответе** оформляется обычной `Citation` с видом `CitationKind.Memory`: `Title` указывает объект и свойство, `Quote` содержит значение. Своего типа сноски у памяти нет.

## Как ложатся две реализации

Реализация №1 будет в MASAgents (`src/Memory` поверх KnowledgeGraph), №2 позже даст FAIMemory. Контракт обязан подойти обоим.

| Метод | Реализация №1 (граф, MASAgents) | Реализация №2 (FAIMemory) |
| --- | --- | --- |
| `WriteAsync` с эпизодом | `FactExtractor` → происхождение по структуре → сверка → `FactWriter` | `Conversation.SendAsync` без пересказа или `Session.Apply` |
| `WriteAsync` с изменениями | правка, одобрение, дизлайк через одни проверки | наблюдения `correct`, `remove` |
| `Withdraw` | снятие опор, факты без опор закрываются | `Session.Undo` и исправления журнала |
| `ViewAsync` | профиль, гибридный отбор фокуса, имена объектов | `Session.Focus` и строка «Вне внимания» |

Экраны («Что помнят», очередь «Ждут решения», карта) остаются фасадом реализации и в контракт не входят. Ответ на вопрос с интервалами нужен только FAIMemory и тоже не входит.

## Границы

**Содержимое документов это RAG, а не память.** На вопрос «что в файле» отвечает RAG. Значение с происхождением `Document` в память не пишется: реализация возвращает исход `Rejected` с причиной «содержимое источника». В памяти остается только отношение человека к документу («работает с», «решил по»), и сам документ в нем выступает объектом со стабильным идентификатором. Чтобы реализация могла это различить, эпизод несет `Read`: список того, что ход прочитал.

**Граф хранит верное дольше разговора, FAIMemory считает версии мира в разговоре.** Граф знаний держит виды, умолчания, объекты владельца со сказанными свойствами, их историю и происхождение. FAIMemory разыгрывает распределения, положение и процессы во времени, отвечает с интервалом и держит фокус текущего разговора. Обратно в память из разговора уходит только сказанное и устойчиво выведенное.

## Чего в контракте нет

- Хранилища, склейки, отбора фокуса и укрупнения: это реализации.
- Адаптеров к KnowledgeGraph и к старым типам памяти `AI.LLM`. `AI.LLM` на контракты не ссылается.
- Уверенности факта, распределений и ответов с интервалами. Если они понадобятся обеим реализациям, поле добавится необязательным по решению владельца.
