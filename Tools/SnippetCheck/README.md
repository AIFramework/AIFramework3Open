# SnippetCheck — компиляция примеров из документации

Проверяет, что C#-примеры в `Docs/Tutorials/**/*.md` вообще собираются
против настоящих библиотек `src/AI.*`.

## Зачем

Линтер канона (`Tools/DocsLint`) проверяет структуру документа, но не может
заметить, что раздел «API» описывает несуществующий класс. Такие ошибки были
массовыми: документация ссылалась на пространства имён `AI.Graphs`,
`AI.Routing`, `AI.MAPF`, `AI.Optimization`, `AI.DCOP` — **ни одного из них в
репозитории нет**. Читатель, копировавший такой пример, получал не рабочий
код, а ошибки компиляции.

Компилятор ловит это за секунды.

## Как запустить

Сгенерировать `.cs` из документации:

```bash
dotnet run --project Tools/DocsLint -- --emit-snippets Tools/SnippetCheck
```

Скомпилировать:

```bash
dotnet build Tools/SnippetCheck
```

Ненулевой код возврата = документ, который обязан был собраться, не собрался.

## Как это устроено

Генератор живёт в `Tools/DocsLint/SnippetEmitter.cs` и подчиняется правилам,
вытекающим из того, как написана документация:

| Правило | Причина |
|---------|---------|
| Все блоки одного документа склеиваются в один метод | Второй блок в статье продолжает первый и опирается на его переменные |
| Каждый документ получает свой `namespace` | Типы из разных статей могут называться одинаково |
| `using` поднимается наверх, но только настоящая директива | `using var idx = …` — это оператор, а не директива |
| Объявления типов выносятся из метода | Локальный тип не может быть `public` |
| `async` добавляется только при наличии `await` | `Span<T>` запрещён внутри асинхронного метода |
| Документы с многоточием (`// ...`, `/* ... */`, `…`) пропускаются | Это иллюстрации, а не самодостаточный код |

Файлы `*.g.cs` генерируются и в git не хранятся.

## skip.txt

Список документов, которые **не** компилируются. Всё остальное собирается,
поэтому любая ошибка сборки означает регрессию.

На момент внедрения проверки список содержит 88 записей: 3 принципиальные
(шаблон нового модуля с несуществующим `AI.Template`) и 85 документов с
примерами-иллюстрациями — необъявленные переменные, отсутствующие `using`,
обрывки циклов. Под защитой сейчас **69 документов**, включая весь
`Algorithms/` и `Geometry/`.

Записи в `skip.txt` и автоматический пропуск фрагментов могут пересекаться:
документ с многоточием отсеялся бы и без записи. Явная запись при этом не
лишняя — она фиксирует причину, которая переживёт правку примера.

Список нужно сокращать: починили пример — удалите строку, документ попадёт
под защиту. Новый документ в список добавлять не надо.
